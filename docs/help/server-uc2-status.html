UC2 status

What it shows

Every UC2 flow (the partner collects from us), one row per flow, in one of five statuses; the info boxes count them. Siblings: UC1 (we push out), UC3 (we poll and pull), UC4 (the partner delivers to us).

Columns

  • Subscription — the “collect from us” subscription (the account’s primary movement-out flow, else its configured subscription), linked to its detail page. Keyed internally by the account owning the pickup folder — the token the server-log lines carry; the account is one click away.
  • Expired — files File Maintenance deleted from the account’s folder (“File Maintenance … finished. Deleted files [ … ]”).
  • First / Last arrived — when the app first and last staged a file (transfer log): the timeline of a file waiting uncollected.
  • Pickups / Last pickup — successful partner logons (“Allowed user … from address …”); zero = never connected over SSH to collect.
  • Status — one of five, a complete partition (below).

Statuses

  • Never collected (red) — files expired and nothing was ever collected; logon visits alone do not count.
  • No files (amber) — the partner logs in (pickups > 0) but the app never staged a file: a dormant or broken source side.
  • Both (green) — the partner provably collects (Files in the transfer log) and the odd file still expired.
  • OK (green) — files staged and collected, none expired.
  • Nothing (plain) — no collection, no expiry: a quiet flow, a partner collecting over CFT (no SSH pickup logged), or visits that came up empty.

Rules

  • Expiry and SSH pickups come from the server log, keyed on the NAME@FEnnn account token; subscription and arrival dates from _files.tsv (files the subscription staged, movement out).
  • Uncollected detection is on the retention delete, not on arrival: “staged and no SSH pickup” would flag almost every pickup flow, since CFT/PESIT collectors never log an SSH pickup. A file the sweep deleted was collected by nobody — an SFTP pickup logs its connection, a CFT pickup removes the file before it can expire.
  • No files and OK need the positive SSH signal, so they only distinguish SFTP collectors; a CFT partner with no expiry lands in Nothing.
  • A logon whose session only delivered files (the account’s UC4 twin flow) is not a pickup.
  • An account serving several UC2 flows (the hybrid production accounts) lists each with its own staged, collected and expired Files; the Pickups figures are the account’s — the partner logs on to the account. On an account with several FE logins they are the flow’s own login’s: each login is a different partner credential.
  • A current-state audit — the date filter does not narrow it.

Tips

  • Click a row for the account’s 10 most recent maintenance-delete messages; No files and OK rows drill to the partner’s recent pickup logons.
  • An uncollected flow fails silently — nothing errors, the file expires. Usually the partner side: another channel, changed credentials or schedule, or refused at the door (the Disallowed column of the Logon report).
  • High Expired, recent Last arrived, no pickups = a live flow to chase; a one-off expiry on a collecting account is normal.
