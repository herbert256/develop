Pickups

What this shows

Every UC2 flow (the partner connects in and collects files from us) on one row — the detail pages’ Pickup information tables collated, so the whole pickup landscape can be scanned and sorted at once.

The columns

A pickup is a successful SSH logon by the flow’s pickup account in the server log. The logons group into visits (a gap of more than 30 minutes starts a new one); a visit that only delivered files — the account’s UC4 twin flow — is not a pickup: its logons land in the Delivered-only logons column instead. First / Last pickup and Pickups cover the remaining pickup logons; With files counts the pickup visits that collected at least one file of the subscription; Files picked up counts the subscription’s collected Files (its OK figure); Waiting / Expired are its staged files by outcome; Pattern is the pickup cadence (“Daily”, “Every 15 minutes”, …); UC4 drop = proven two-way traffic in one and the same technical SSH connection: at least one session (by the transfer log’s Session ID) both delivered and collected a file — deliveries over a separate connection, even in the same visit, do not raise it (the UC2 pickup visits analysis has the visit breakdown and the Same connection figure).

The logon columns are the account’s and repeat on each of its UC2 subscriptions; the file columns are each subscription’s own. A partner collecting over CFT/PESIT logs no SSH pickup, so its logon columns stay empty while its files still move.

How it's computed

All figures come from the same per-visit classification that feeds the UC2 status report, the UC2 pickup visits analysis and the detail pages (the uc2-pickups sidecar), so the four views can never disagree.
