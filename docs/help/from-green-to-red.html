From green to red

What it shows

The regression list: one row per subscription that is red right now (its latest File failed) but was green on an earlier day — flows that used to work and broke, so something changed. Newest flip first.

Columns

  • Last green day — the most recent day that ended on an OK File.
  • Went red on — the first failure of the run the subscription is still in.
  • Days red — counted to the dataset’s last day, not today.
  • Consecutive failures — failed Files since the flip.
  • OK Files / Files — lifetime counts of the subscription.

Rules

  • Files are walked chronologically per subscription.
  • Site-wide colour rule: red when the latest File is Failed or Expired, green otherwise. Waiting (a UC2 file staged, not collected yet) is OK; Expired (the staged copy deleted before pickup) is Error.
  • A day ends green when its last File is OK. An OK and a failure on one day leave it red, so Last green day and Went red on can sit days apart.
  • Subscriptions that never delivered an OK File are excluded (never green, nothing flipped): see Only red; Failure Episodes lists them with Last OK “never”.
  • Always the full period, no date filter (like Went quiet and Failure Episodes): a narrowed range would fabricate flips (hiding the newest failures) or hide them (cutting the green history).

Tips

  • Click the Error count for the 10 most recent failed Files, the OK count for the last successful ones.
  • Failure Episodes shows every failure run (its Open incidents table needs 3+ consecutive failures and includes never-green flows); this page needs only green before, red now and shows the flip even for a single failure.
  • Failure rate answers what share fails; Not in Flow Manager covers configuration drift.
  • The red tint on the Entities and detail pages follows the same latest-File rule.
