No remote files

What it shows

UC3 subscriptions that poll the partner faultlessly and never find a thing: every poll logs Applying the search pattern '*' for transfer site '<site>': 0 file(s) were found of which 0 matched the pattern.

Columns

  • First / Last — bound the polling; Polls — the empty listings; Days — how many separate days it ran.

Rules

  • Nothing is broken: connection, credentials and remote directory are fine and the listing succeeds — there is simply never a file. Each row is a schedule spending connections and listings around the clock for no data; the top rows poll thousands of times a month.
  • UC3 only — the pull use case, where polling is the whole point.
  • No transfer data — the subscription is in the server log with no transfer rows at all; its result is green when its latest poll succeeded (the clean-poll rule: verifiably working, nothing to fetch) or blue otherwise. A subscription that has moved files is left out — a quiet stretch there is a lull.
  • Every poll empty — zero files found on every poll. Found > 0 with matched = 0 is a search-pattern problem, not an empty directory, and is left out; the note under the table says how many.
  • Both poll shapes count — N file(s) were found of which M matched the pattern. and N file(s), matching the pattern, were found and will be downloaded. — only the leading count is common to them.
  • Poll counts are additive and re-total under the date filter; click a row for its 10 most recent poll lines.
  • An empty poll leaves no trace in the transfer logs, so the flow is invisible in every file-based report and can run for years at a connection every few minutes: a candidate for retirement, a slower schedule, or a question to the partner.
  • Compare Remote Polls (the empty-poll rate of every subscription, working ones included) and No remote dir (the listing fails outright: the directory is not there).
