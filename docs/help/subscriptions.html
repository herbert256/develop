Subscriptions (analyses)

What this shows

Every configured subscription on one row, keyed by its FlowID (the customAttribute_FlowIdentifier value — the cell links the subscription’s own detail page, and since a flow’s UC subscriptions share one FlowID, a FlowID can carry several rows) — the whole configuration mapping at a glance: its use case (the UC<n> token from the name prefix, or the one the configuration derives when the name carries none), the account it belongs to, its endpoint (the login the partner connects in with — inbound — or the remote host we dial out to — outbound), the BL tag, and the four derived groups: Logical (the FlowID condensed into its logical flow group), Partner, Domain and Application.

Every other name links its own detail page too, and each row is tinted by the subscription’s result — light green = last transfer OK, light orange = configured but never seen, light red = last transfer Error, light blue = surfaced only by the server log. Click a column header to sort.

The BL column

The subscription export (subscriptions.json) carries free-form tags; the BL column shows the entry (or entries) starting with BL — the business-line marker. A subscription without such a tag shows a blank cell.

How it's computed

The roster is the pristine configured snapshot (the base cache before the build appends discovered names), so the list is exactly what FlowManager defines. Everything else is joined from the flow-manager caches: the FlowID from the subscription’s profile pair, the account/login/host from their pair caches, the Logical / Partner / Domain / Application from the derived group caches, and the BL tag straight from the export via jq. No log data is read — only the row tint reflects activity.
