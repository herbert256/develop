Subscriptions (analyses)

What it shows

Every configured FlowID (customAttribute_FlowIdentifier) on one row, ordered by use case. UC subscriptions sharing a FlowID fold into one row, each cell the union of their values; a subscription without FlowID keeps its own row.

Columns

  • Subscription — the FlowID; links the detail page for a single subscription, plain text when the row folds several.
  • UCx (column two, where the subscriptions live) — every use case the FlowID appears under, by number, each linking that use case’s subscription page (UC1, UC4 = two links).
  • The UC token is the name-prefix UC<n>, or the one the configuration derives when the name has none.
  • Logical — the FlowID condensed into its logical flow group.
  • Account, Partner, Domain, Application — the owning account and the derived groups.
  • Endpoint — inbound: the login the partner connects with; outbound: the remote host we dial.
  • BL — the tags entries in subscriptions.json starting with BL (business-line marker); blank without one. An entity of the Logical, Partners, Domains, Applications & BL group.

Rules

  • Every name links its detail page; click a header to sort.
  • Row tint: light green last transfer OK, light orange configured but never seen (or a mix), light red a last transfer in Error, light blue surfaced only by the server log.
  • Fold rule, as for the derived entities: any red wins; one shared value carries; anything mixed is orange.
  • Roster = the pristine configured snapshot (base cache before the build appends discovered names): exactly what FlowManager defines.
  • Joined from the flow-manager caches: FlowID from the profile pair, account/login/host from the pair caches, Logical / Partner / Domain / Application / BL from the derived group caches.
  • No log data is read; only the tint reflects activity.
