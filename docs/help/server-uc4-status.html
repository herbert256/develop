UC4 status

What it shows

Every configured UC4 subscription (inbound delivery: we are the server, the partner connects in and hands us a file), one row each, in exactly one of seven statuses; the info boxes count them. Siblings: UC1 (we push out), UC2 (the partner collects from us), UC3 (we poll and pull).

Columns

  • Status — one of seven, a complete partition (below).
  • Subscription — the configured name, linked to its detail page.
  • Files / OK / Error / Last file — Files received, by outcome, and the newest one’s date (_files.tsv); blank on a never-seen subscription.
  • Logons — the “successfully authenticated” line, one per successful SSH logon; an “Allowed user” whitelist admission that then fails authentication does not count.
  • Arrivals — files actually handed over (“will be submitted for processing”).
  • Problems — logon attempts the account whitelist refused.
  • Last log — the newest line of those kinds: “is this partner still knocking at all”.

Statuses

  • ok (green) — its latest File arrived.
  • error (red) — its latest File failed and no OK File in the window: nothing ever worked.
  • ok -> error (red, was green) — OK Files before, the latest failed: a regression, a change to find.
  • server - no files (blue) — the partner does log in and never sends: credentials work, the partner reaches us, no file ever came. The question is for the partner.
  • server - error (blue) — the partner never got in: its only attempts were refused by the whitelist. Fix the whitelist.
  • server - no result (blue) — the server log says nothing about the subscription either way.
  • not seen (orange) — configured, in neither log: set up and never used, or a partner side never finished. Estate to review, not an incident.

Rules

  • Roster: every UC4 name in the FlowManager subscription export, run or not. Colour = the site-wide result: green/red are real transfer data (the LAST File OK / Failed-or-Expired), blue server log only, orange neither log.
  • The server signals are account-keyed: the partner connects to an account, and the subscription name barely reaches the log (only the PeSIT confirmation of the onward internal leg carries it). The account↔subscription cross-reference is 1:1 both ways for UC4, so every line attributes to exactly one subscription.
  • error vs ok -> error is per File — right after any OK File the subscription WAS green — finer than From green to red, which buckets by whole days.
  • We are the server: no unreachable-partner failure exists, so a refusal at the door is the only way a UC4 flow breaks before a file exists — server - error is narrower than on UC1 and UC3.
  • server - no files means what it means on UC2 (the partner never sends), not on UC3 (we poll an empty directory). not seen is first-class as on UC1; UC3 has none, so its box stays hidden there.
  • Inbound fails silently — never sent, never connected and turned away look alike and write no transfer record; the blue split separates them.

Tips

  • Click a row for its most recent server-log lines; on a server - error row those are the refusals.
