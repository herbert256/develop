Not in Flow Manager

What this shows

Every entity value that appears in the transfer logs but is not in the current FlowManager configuration — the traffic running outside the configuration. All nine configured lists are checked: accounts, subscriptions, logins, hosts, whitelist, logical flows, partners, applications and domains. Typical hits are ad-hoc test uploads (an account created directly on the server), configuration objects that were renamed or deleted after the logs were written, and partner source addresses missing from the AllowIP whitelist.

How it's computed

The report walks the logical-transfer cache (one row per File) and compares each attributed value against the FlowManager caches extracted from partners.json / subscriptions.json, case-insensitively. A logged subscription value counts as configured when a configured subscription name prefixes it — the same rule the rest of the site uses (logged site values carry protocol suffixes). Host rows are outbound endpoints we dialed that partners.json does not list; Whitelist rows are the source addresses of incoming connections that no AllowIP entry covers.

Counts are Files (one logical transfer per CoreId), with the Error/OK split by each File's delivered outcome and the volume counting each file once. Names link to their detail pages where one exists (whitelist addresses have none). These are exactly the values that render untinted (no status color) on the Entities pages — FlowManager has no result to color them by.

Note that the configuration is compared as it is now: the report cannot tell whether a value was configured at the time it was logged — a since-deleted account and a never-configured one look the same.
