Not in Flow Manager

What it shows

Every entity value seen in the transfer logs that the current FlowManager configuration does not know — the traffic running outside the configuration. All ten configured lists are checked: accounts, subscriptions, logins, hosts, whitelist, logical flows, partners, applications, domains, BL tags.

Rules

  • Walks the logical-transfer cache (one row per File) and compares each attributed value, case-insensitively, against the FlowManager caches extracted from partners.json / subscriptions.json.
  • A logged subscription value counts as configured when a configured subscription name prefixes it — the site-wide rule (logged values carry protocol suffixes).
  • Host rows: outbound endpoints we dialed that partners.json does not list. Whitelist rows: source addresses of incoming connections that no AllowIP entry covers.
  • Counts are Files; the Error/OK split follows each File’s delivered outcome; the volume counts each file once.
  • A missing FlowManager export makes every logged value of that type appear here.
  • The configuration is compared as it is now: the report cannot tell whether a value was configured when it was logged — a since-deleted account and a never-configured one look the same.

Tips

  • Typical hits: ad-hoc test uploads (an account created directly on the server), objects renamed or deleted after the logs were written, partner source addresses missing from the AllowIP whitelist.
  • Names link to their detail pages where one exists (whitelist addresses have none).
  • These are exactly the values that render untinted (no status colour) on the Entities pages — FlowManager has no result to colour them by.
