No remote dir

What it shows

Subscriptions whose configured remote directory does not exist: we reach the partner, authenticate, ask for a listing, and get No such file.

Error occurred while listing files from partner <site> defined in account <account>. No such file: '<dir>': No such file.

Columns

  • One row per subscription, newest failure first. Subscription = the logged site truncated at its _SCP_ suffix; Account from the “defined in account” clause; both link to a detail page when the name resolves.
  • Last — the most recent failed listing, with its time.
  • Remote directory — every path the partner rejected, exactly as logged (odd separators included — often the cause), stacked newest first; several spellings mean someone was guessing. Click a long cell to expand it.
  • Last OK File (transfer cache) and Last good poll (newest successful listing, UC3) — the two recovery stamps the row did not pass: both older than the error, or absent (—). A same-day OK File that preceded the error is the usual reason a row looks recovered but is not.
  • Per day — affected subscriptions per day: a short burst is someone reconfiguring, a flat line a flow dead for the whole window.

Rules

  • The connection is healthy; this is a configuration fault on one side: the path was renamed or never created, the partner moved it, or the account is chrooted so the absolute path resolves elsewhere.
  • Source: the TM error above, with or without its Error during transfer operation: prefix. Only No such file counts; other listing failures (Permission denied, …) are counted per subscription by Remote Polls, which also covers polls that list a directory and find it empty.
  • Only open problems are listed. A row is dropped when the flow recovered after its last error on either proof: an OK File in the transfer cache (OK = any outcome not Failed or Expired; on these pull flows exactly Processed), or — on a UC3 (pull) subscription — a later Applying the search pattern '*' for transfer site '<SITE>': 0 file(s) were found of which 0 matched the pattern. line for the same site, since an empty poll downloads nothing and leaves no transfer record.
  • Every figure — totals, per-day table, subscription and directory counts — is over the surviving rows; the intro says how many directories were suppressed. Error counts are additive and re-total under the date filter.
  • Click a row for its 10 most recent log lines.
  • A failed listing starts no transfer, so none of this reaches the transfer logs: the flow looks silent there, like a partner with nothing to send. Compare Remote Polls (the folder is right but always empty) and Connection failures (we never reach the partner).
