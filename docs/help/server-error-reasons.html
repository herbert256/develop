Error Reasons

What this shows

The transfer log only ever records a transfer as Processed or Failed — its "why" fields are always blank. This report reads the server log instead (data/server/cache/_parse.tsv) and classifies every ERROR-level message into a failure-reason bucket, so it is the one place on the site that shows why transfers actually failed. The count column is a plain count of ERROR log records, not Files.

How it's computed

Each ERROR message is matched, in order, against a fixed set of patterns:

  • Connection failure (partner unreachable) — "Connection failure while …" messages.
  • PESIT: <code> — a PESIT protocol refusal carrying a reason= code; each distinct code becomes its own bucket.
  • PESIT: negative response — "Received negative …" messages.
  • TLS/SSL error — SSL exceptions or TLS fatal alerts.
  • Network error: connection reset and Network error: other.
  • Listing files from partner failed, Advanced-routing step failure, CONFIG_PASSWD state variable error, Transfer operation error (other).
  • Other — anything not matching the above, kept visible with an example so a new failure family surfaces instead of silently disappearing into a catch-all.

Each bucket's row shows its count, share of all ERROR records, and a first-seen example message (truncated). Per-day buckets let the table re-aggregate under the date filter.
