Publish to account failed

What this shows

Every Publish to account failed line the server log holds, one row per line, newest first: the route could not publish a received file into its account and stopped — the file never reached the account it was routed to. The line looks like this:

ARPA0001: [SECURETRANSPORT] [UC2_ODV_MAIA_SCHUBERGPHILIS] An error occurred while publishing the file {AIMAPF_NL81ABNA0438073703_11-09-2026.XML} to an account. Step configuration suggests to stop further route execution

The table

  • Date & time — when it happened, to the second.
  • Subscription — the route, the second bracket of the line; it opens the subscription's detail page, and the row carries the subscription's result colour.
  • File — the file in the braces.

How it's computed

The tokenized server log is scanned for Advanced Routing lines (an AR<code>: prefix with its two bracket groups) whose text carries the message above; the subscription is read from the bracket named in the table and folded to its current name when it was renamed. The report shows at most 1000 rows and at most 10 rows per subscription — the newest ones on both counts; the intro and the total row say how many lines the log really holds. The date filter, search and sort work over the shown rows. The Could not send file report is its twin for the AR0074 delivery failures.

Why it matters

Each row is a file whose routing did not complete as configured; a subscription that keeps appearing has a problem on this step that the Errors reasons and its own detail page put in context.
