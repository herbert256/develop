Whitelist audit

What it shows

  • Every whitelisted partner IP (the AllowIP lists, CIDR ranges expanded) against what actually connects in. Boxes: Whitelisted IPs · Used (Files) · Connect only · Never seen.
  • Active whitelisted addresses — IP · Allowing accounts · Files · Server contacts (in) · Last File · Verdict: Used (carried Files, green), Connects only — no Files or Server-log mention only — no Files (orange).
  • Unused whitelist entries per account — Account · Whitelisted IPs · Active · Never seen; red = none of the account’s entries is active.
  • Sources without a whitelist entry — Address · Files · Server contacts (in) · Last File: sources that carried Files or connected in without any entry.

Rules

  • Files = the transfer log’s inbound source addresses.
  • Server contacts (in) = the address’s inbound connection lines (the In side of Connections, every address, not its top 50) plus its SSH logon lines. SecureTransport’s own outbound connections never count.
  • Never seen = no File, no inbound contact and no server-log mention — the Cleanup backlog’s unused-whitelist rule.
  • A named (non-IP) source is an address already resolved to its hostname.

Tips

  • Internal cluster addresses appear among the unlisted sources legitimately (PeSIT needs no whitelist entry); an unexpected external address is the one to chase.
  • Every unused entry is attack surface that buys nothing.
