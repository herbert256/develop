Account Details

What it shows

The per-account page, one per account name, linked from every Account cell (the list is Accounts): KPI line, Activity per day / weekday / hour, breakdowns of every other dimension (subscription, login, remote host, protocol, AV scan, security parameters, direction, action-by, mode), Latest 100, the 10 largest transfers.

Sections

  • KPI line — rank and share among all accounts, failure rate, volume, cadence (days active, median gap between active days, days idle since last seen); with recorded durations also avg/p50/p95/max, throughput, distinct sessions.
  • Last error(s) — above Features when a subscription it moves files with has an error: per subscription its newest error (date, time, subscription, file), newest first; red = failed, orange = expired uncollected; absent when none. A click anywhere on the row opens the file’s error page (all legs plus server log), guaranteed by Failed Subscriptions.
  • Features — a Login, Host, Partner, Application, Domain, Logical or BL breakdown with exactly one value folds in here as a linked, tinted row.
  • Logins, Hosts, Domains / Applications / Logical / Partners / BL — one table each, side by side, every configured and logged value: green = logged, red = configured, never seen (no counts; links its never-seen page); unconfigured-but-logged partners green; group rows tint by the entity’s own result. A narrowed date filter re-tints (no activity = red), never hides.
  • Incoming / Outgoing connections — after Latest 100; address · In · Out · Name; full-period, unchanged by the date filter.
    • Incoming = the configured AllowIP whitelist (partners.json, patterns expanded) plus observed source addresses, coloured against the site-wide expanded whitelist; rows link details/incoming_connections/ (none for a never-sighted whitelist address).
    • Outgoing = configured endpoints plus observed hosts; IP = forward-resolved address(es), Name = configured hostname; rows link the host page.
    • In / Out = Files that entered / left us; Name = the endpoint input/ip/ip-hosts.tsv maps, blank if none (no reverse DNS).
    • Light green configured and used; light red traffic on an unconfigured address; light orange configured, never seen (folded behind one summary row); light blue whitelisted, server-log sighting only (not folded).
  • Files not picked up — files File Maintenance purged uncollected from the account’s folder (the log’s “Deleted files [ … ]” sweeps, keyed on NAME@FEnnn); newest expiry first, up to 100, paged 10 — a real pickup removes a file before it expires.
  • Last server log messages — at the bottom: the account’s 25 newest lines merged with its configured login(s) and host(s) lines (a host by name and each resolved IP — address-keyed caches), plus each one’s 10 newest Error/Warning lines; deduplicated, newest first, full-period.

Rules

  • Red banner “ERRORS IN SERVER LOG AFTER LAST TRANSFER – SEE LOG AT BOTTOM OF THIS PAGE”: an Error/Warning after the account’s last transfer ended (a retry delivering after it clears it), for the account or any 1-to-1 connected entity (its one login, one host); those lines join the table.
  • Every count is in Files, split by the delivered (final-row) outcome; volume once per file.
  • Page background: light brown seen & in, light blue seen & out, light gray seen & both/unknown, light yellow never seen & in, light orange never seen & out, light purple never seen & both/unknown. A never-seen page says so and shows its configured cross-references (all red) and whitelisted IPs.
  • Configured both ways: outcomes split into In - Error / In - OK / Out - Error / Out - OK by the file’s direction; a file without one counts in Files and Volume only.
  • Activity per day leads with Files; the Subscription breakdown comes first below it; the Account breakdown sits under the connection tables.
