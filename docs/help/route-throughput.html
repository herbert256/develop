Route throughput

What it shows

  • Wire speed per route (subscription × protocol × direction), slowest first, then the same figures per protocol; the summary line gives the route count, measured Transfers, volume and the overall MB/s.

Columns

  • Subscription / Protocol / Direction — the route.
  • Transfers / Volume / Wire time — the counted legs, their bytes and summed durations.
  • MB/s — counted bytes ÷ summed leg durations: volume-weighted, so one big slow file outweighs ten quick ones.
  • Trend (MB/s) — first-half against second-half MB/s of the window; shown when both halves have 3+ Transfers.
  • Per protocol — Protocol / Transfers / Volume / Wire time / MB/s.

Rules

  • Only legs that measure a real rate count: duration over 500 ms and size over 1 MB; smaller legs are mostly session setup and rounding. Failed legs count too: a leg that moved its bytes before failing still measured the route’s wire speed.
  • A leg’s duration is the record’s own wire time; the store-and-forward dwell between legs is never in it (Distribution & Store-and-forward measures that).
  • routing is the internal store-and-forward leg between the inbound and outbound sides.

Tips

  • Compare a route with its protocol row, not across protocols: PeSIT throttles far below SFTP by design, so 0.2 MB/s PeSIT and 40 MB/s SFTP are both normal.
