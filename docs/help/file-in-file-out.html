File in - File out

What it shows

Partner-to-partner handovers carried by TWO subscriptions: a file arrives from one partner on an inbound subscription, OpsWise copies it across, and the same filename leaves to another partner on an outbound one. Headline: routes, files, and how many routes cross partners the grouping does not merge.

Sections

  • Handover routes — one row per (inbound → outbound subscription) pair, busiest first: the partner on each side, Files (handovers detected), Filenames (distinct names), Same size / Size changed, and the gap from inbound to outbound file (fastest / median / slowest).
  • Latest handovers — the 100 most recent files, newest first: In (arrived from the first partner), Out (left to the second), the gap, the size on each side; subscription cells link their detail pages.

Rules

  • Nothing links the two halves — separate CoreIds, accounts, partners — except the filename; without this report each counts as an unrelated one-partner flow.
  • One pass over the logical-transfer cache _files.tsv: every named file with a known movement direction (col 17 in / out) is indexed by filename; each inbound file pairs with the next outbound file of a different subscription within 48 hours, at most once.
  • Matching is on the filename only: the largest route re-encrypts in transit (.afp.pgp, growing 4–19 KB), so a size match would miss it. Size is reported instead: all-same = a byte-for-byte copy, all-changed = re-encrypted or re-wrapped.
  • 48 hours because the copy is a scheduled OpsWise batch: observed gaps run from 4 minutes to 47 hours; a one-hour window finds about a sixth.
  • Trust: Files = Filenames means every match carried a distinct (timestamped) name — thousands of collisions with one subscription cannot be coincidence. Far fewer filenames than files = a repeated fixed name (a daily export.zip) that can pair by accident: a lead, not a fact.
  • The same partner group on both sides is usually not a handover but a pull-then-stage flow (we fetch a file and stage it back for the same partner); kept so the pattern stays visible.
  • The platform’s documented single-subscription relays (UC5, UC8; one each today) are not this: this report finds the undocumented two-subscription form, which carries far more traffic.
  • The partner derivation merges partner codes sharing a whitelisted IP or endpoint domain (see Entity coverage); a handover inside OpsWise leaves neither trace, so routes across unmerged partners are invisible to it.
