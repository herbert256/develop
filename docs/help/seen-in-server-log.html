Seen in server log

What it shows

The audit of the blue marking: entities alive on the server (connecting, authenticating, or a connection’s target) with no transfer-log record, and the server-log line that proved each alive.

Sections

  • Result-status rollups — the Flow manager Entities and the Logical, Partners, Domains, Applications & BL tables: Seen = a transfer or a blue sighting; Error/Warning/Ok = red/orange/green by last transaction. (+n)/(−n) = what blue moved: Seen gains the blue count, Warning loses it.
  • Why blue — each entity once: Direct when its own name is in its type’s seed list (raw sightings) or only its successful SSH logons found it (evidence = the logon line); else under the seed type of the first surviving tuple that reached it through the cross-reference enrichment. Logical, Partners, Domains, Applications, BL are derived, never a TM seed — a Direct there is an SSH-logon rollup. Total = the type’s blue entities; nonzero cells link the entities with their claiming lines.
  • Message shapes — the seeds’ latest messages, quoted values, IPs, UUIDs and numbers normalized away; click a shape for its table.
  • Evidence tuples — one table per shape, most frequent first; two rows per entry: the newest qualifying line (the blue date; 300 characters; click to expand) and the attribution. Seed = the “Missing …” list: account, login, subscription, host or whitelisted IP. Account / Login / Subscription / Remote Host = the seed plus what the FlowManager cross-references fill unambiguously (a truncated subscription canonicalized when it uniquely prefixes one configured name); cells link detail pages.

Rules

  • bin/build/seen-in-server-log.sh runs after both parses, before the result fill: reads the data/unknown/ sidecars, enriches each seed, writes the evidence sidecars, marks blue in data/flow-manager/base/ only when no real File carries the entity; never changes _files.tsv or _transfers.tsv.
  • Only Transfer Manager runtime messages qualify, not deployment or housekeeping mentions.
  • Dropped: a host seed with no configured attribution; a whitelisted-IP seed whose partner has transfer data (an unused alternate address); duplicate enriched tuples collapse.
  • Blue = a fourth result state, no real transfer: no File or transfer row is created (File totals, day pages, per-transfer dimension reports stay transfer-log only), and real red/green health never changes. Entity, detail and coverage views count it in the Server bucket.
  • The tuple tables count surviving seeds, not blue names: one tuple can attribute several entity types and the rollup adds related names — different units.
  • The result step keeps valid blues, derives related partner/application/domain and SSH-logon blues, and turns a would-be-blue UC3 subscription green when a clean poll found no file.
