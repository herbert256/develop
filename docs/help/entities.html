Entities

What it shows

The nine entity reports — Subscriptions, Logical, Partners, Accounts, Logins, Hosts, Domains, Applications, BL — share one layout: one row per name, its traffic in seven column groups, the Top view way. This page explains the columns, rules, views and scope; each entity’s own help page says how a File is attributed to it.

Columns

  • Files — one per CoreId (Waiting = OK, Expired = Error), split In / Out by the movement direction, with the Error count and rate. A File with no known movement counts in the total and the rate only.
  • Retry / Resubmit — Auto = an OK File with a failed leg and no resubmitted leg (the platform’s own retry delivered it); Ok / Error = every File an operator resubmitted (the log’s Resubmitted flag), by its final outcome — the Top view rule, so a resubmitted re-delivery that never failed counts under Ok.
  • Duration — p90 / p95 / p99 / p100 (the longest) wall-clock span of the OK Files, first record start to last record end, Error attempts left out; whole seconds / minutes / hours / days (s m h d): seconds green, minutes amber, hours and days red.
  • Volume — the total; Avg = volume / Files. Whole units.
  • Transfers — the physical log rows, every leg of the Files: Ok / Error with the error rate.
  • State — the UC2 Waiting Files (staged, not collected yet) and the Expired ones (deleted unclaimed).
  • Dates — First and Last day; Days = days with at least one File.

Rules

  • Source: the per-CoreId cache _files.tsv — one logical transfer per File, Error/OK by its delivered (final-row) outcome, volume counted once per File.
  • Every figure follows the From/To range (Duration is re-picked from per-day histograms); First and Last stay full-period.
  • An empty cell is a zero: In / Out and the tinted counts never show a 0, an empty Error keeps an empty rate. Red = an Error / Expired count, amber = a Retry / Resubmit / Waiting count.
  • Retry / Resubmit and State show only while a visible row carries a value: a view without any drops them; a date range or search that empties them hides them until a value returns.
  • The total row is the last row; its cols hotspot opens the column picker.
  • Rows tint by the name’s result: light green = last transfer OK, light orange = never seen or a mixed rollup, light red = last transfer Error (or server-log Errors after the last OK transfer), light blue = seen in the server log only. An untinted row is logged but not configured. Rolled-up types (accounts, logins, hosts, partners, …) take the result of their connected subscriptions.

Views and scope

  • Entity tabs: switching one tab group keeps the other two (entity, view, scope).
  • Views: All = every configured plus every logged name; Seen = the names with activity; Not seen = configured in FlowManager, never seen (name column only); OK / Warning / Error = the names whose result is green / orange / red.
  • Scope +Server (default) counts a server-log sighting as seen: a server-log-only name sits under Seen, light blue. Transfer ignores the server log: that name turns orange and moves to Not seen / Warning.
  • The scope changes only Seen, Not seen and Warning; All, OK and Error are the same list either way (only a real transfer makes a name green or red), so their scope tabs are greyed out.
  • Under +Server a seventh view, Server = the names seen in the server log and nowhere else; not offered in the Transfer scope. It is the same choice as the front page’s including server log switch, whose figures link into the matching view and scope.

Tips

  • Every count opens its 10 most recent Files (newest first, by start time); a Transfers cell the Files that carried a leg of that outcome; a Duration cell the 10 most recent OK Files at or above that percentile, each with its span. A blank cell is not clickable.
  • Every name links its detail page. Tabs, search, date range, sorting, cols, csv: Generic help.
