Skipped

What it shows

The audit of what the skip list removed: the ignored accounts, subscriptions and logins, the transfer-log and server-log records set aside with them, and the raw transfer records dropped for other reasons. Skipped names appear in no report, coverage table, detail page or search result. The buttons give a per-value report; this page lists all.

Sections

  • Info boxes: skipped accounts, subscriptions, transfer log lines, server log lines, dropped raw records.
  • Tables of every skipped account, subscription and comm-profile login by name; a last table of the dropped raw records with their reason (http, empty ssh probe, otherwise no subscription).

Rules

  • The rules live in input/skip.txt, this checkout’s own, one token per line (e.g. CRG, SWIFT). Edit and rebuild — a changed list re-derives the FlowManager config and re-parses both logs.
  • Config-side matching is a case-insensitive substring of the account, subscription or comm-profile login name (CRG matches IPO_CRG-OK01_RABOBANK); log records follow the rule kind (contains, exact or regex).
  • A login rule drops the matching comm-profile login from the configuration (its detail page and login pairs with it); the partner stays. A server-log mention of that login is scrubbed only by a message or any rule — to hide a login completely, use any.
  • Applied at parse time: bin/flow-manager.sh writes a filtered copy of the exports to data/flow-manager/filtered/ (every base list, pair, Partner/Domain/Application group and config-derived analyses page excludes the names); bin/transfer/parse.sh drops a record whose attributed account or subscription matches into data/transfer/_skipped.tsv; bin/server/parse.sh drops a record whose message contains a token into data/server/_skipped.tsv.
  • Raw records dropped for another reason (kept verbatim in data/transfer/_skipped.csv, counted nowhere): a CoreId with neither subscription nor account after every attribution pass (platform-internal traffic the blacklist blanked); an http leg (web-UI hand traffic); an empty ssh probe — one lone Outbound ssh record of size 0 whose Application reads none, no file moved.
  • A record with an account but no subscription is never dropped. The parser first asks the server log which flow the connection executed (the session id joins the logs, the route lines name the subscription), then lets a partner-delivered Inbound leg pick the account’s single receiving flow when only a response leg contradicts it.
  • Failing both, it counts under the synthetic UCx_account (UCx = the use case nothing could determine): in the transfer counts, the Entities views and Not in Flow Manager, never in First seen or the coverage figures. A UCx_ row is a routing gap to investigate, not a configured flow.
  • An estate where nothing matches shows zeros and empty lists — expected. Static audit, no From/To.
