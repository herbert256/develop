Could not send file

What it shows

Every “Could not send file” error in the server log, one row per line, newest first: an Advanced Routing route that gave up delivering a file to its transfer site after its retries (AR0074 — the “Duplicate file” reason of the failure pages).

AR0074: [SECURETRANSPORT] [<subscription>] Could not send file: {<path>} using transfer site: {<site>} after attempting {<n>} times.

Columns

  • Date & time — when the route gave up, to the second.
  • Subscription — the route, the line’s second bracket; opens the detail page, and the row carries the subscription’s result colour.
  • File — the last path element inside the first braces.

Rules

  • Source: TM lines whose message starts with an AR<n>: code and carries “Could not send file:”.
  • The subscription is read from the second bracket (the same reading as UC1 status and the failure pages’ “Duplicate file” reason), folded to its current name when renamed.
  • At most 1000 rows and 10 per subscription, the newest on both counts; the total row says how many lines the log really holds. Date filter, search and sort work over the shown rows.
  • The error is the delivery leg failing for good after the configured number of tries: each row is a file a partner did not get. A recurring subscription has a delivery-side problem — the transfer site, its credentials or the far end — that the Errors reasons and its detail page put in context.
