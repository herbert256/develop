Search

What this shows

A single searchable table listing every account, subscription, login and remote host the site knows about by name, all at once — one flat list across all four entity types instead of four separate pages. Its count column is the Files count, split Error/OK like the entity list pages. The rows carry no drill-downs — for an entity's 10 most recent transfers open its detail page or the Seen reports.

The Partners, Domains & Applications page's partner / application / domain groupings are searchable too, as types Partner, Application and Domain. Their counts come from each File's own attribution (the partner organisation, and the application/domain segments of the account name), so a grouping is seen when at least one File carries it. They link to their detail pages and leave the Server log column blank.

Each subscription's From and To paths (the source and target directory + file mask shown in its detail-page Features table) are searchable as types Source and Target, so you can find a flow by the folder it reads from or writes to. A Source or Target row links to its subscription and carries that subscription's Error / OK counts. When the path is on a remote partner (an endpoint we dial), the partner host is appended after an @ — e.g. /some/dir @ sftp-test.lifetime.nl — so you can also find a location by its partner host. When the same path is used by more than one subscription it collapses to a single row marked ▸ <path> (N) whose counts are the sum across all N subscriptions; click it to expand one indented row per subscription, each linked to its detail page and showing that subscription's own counts.

Unlike every other searched table on the site, the table starts completely empty — with five entity types and potentially thousands of names combined, showing everything at once wouldn't be useful. Rows appear only once you type a search term into the Search box (wildcards and and/or keywords work as usual).

Searching

Type in the Search box to filter every entity by name. Wildcards: ? matches any single character, * any run (AB* for a prefix, *QUION* anywhere); combine terms with and / or / not (RABO or SAP, ABC and XYZ) — and a plain space means AND, so ABC XYZ equals ABC and XYZ (type an operator word to search it literally: abc and and). The searchable set covers configured and logged accounts, logins, hosts and subscriptions; partner/application/domain groupings; source and target paths; configured endpoint address aliases from input/<env>/ip/ip-hosts.tsv; and every whitelisted IP. A Whitelist row links to the account that allows the IP, one row per allowing account. The Error / OK columns split each entity's Files by delivered outcome (Files itself is Error + OK, so that redundant column is omitted). There is no From/To date filter here — "seen" always means seen anywhere in the loaded logs.

The view and type filters

The controls at the top of the page hold one client-side filter, applied on the one page — there are no separate view pages. The entity type checkboxes select which types a search may match: Partner, Subscription, Host, Login, Application, Domain, IP, Account, Source and Target. All start unchecked, which means every kind is searched; ticking one or more boxes narrows the search to just those kinds. The IP box covers both the resolved-host IP aliases and the whitelisted IPs. Every entity is listed whether or not it was ever seen — the row colour carries each one's status, so there is no seen/not-seen filter.

Names with no logged activity

Beyond entities that appear in the transfer logs, the list includes every configured account, login, host and subscription from partners.json and subscriptions.json. An ordinary configured-never-seen row is orange, links to its never-seen detail page and carries zero counts; a name seen only in qualifying server-log messages is blue. There is one searchable raw-IP alias for each configured endpoint address in input/<env>/ip/ip-hosts.tsv, except when that address is already represented as a host entity or a Whitelist row. The alias links to the configured endpoint's host detail page when that association is available.

Whitelisted IPs are searchable too, as type Whitelist — one entry per (allowing account, IP) from the partners.json AllowIP whitelists. A whitelisted IP never gets a page of its own: clicking the row opens the detail page of the account that allows it. An IP allowed by several accounts appears once per allowing account.

The "Last seen" column

The timestamp (ccyy-mm-dd hh:mm:ss) of the newest File attributed to that entity in the loaded transfer logs — blank for a name that never moved a file (including the blue server-log-only entities). Partners and applications use the same union attribution as everywhere else on the site; a Whitelist or IP row shows the last transfer involving that address; a Source or Target row shows its subscription's stamp, and a multi-subscription path row the newest across its subscriptions (expand it to see each one's own).
