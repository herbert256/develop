Missing Entities

What it shows

Entity names that appear in server-log messages but never in the transfer log — one tab per type, one row per name with its mention count. Something alive on the platform (usually in a failed-connection message) that never produced a transfer; these are the seeds of the site-wide blue result.

Tabs

  • Subscriptions — UC… names in server messages. The server truncates long names, so a name counts as known when it is a prefix of a real one.
  • Accounts — names from associated with account "…", checked against every transfer row’s account (not only first-row accounts, so a destination-side-only account is not falsely flagged).
  • Hosts — the outgoing side: configured endpoint addresses (the FlowManager partner host fields, the servers we connect to) named in messages such as “tried to connect to remote host …”. A hit = a configured endpoint the server tried to reach that never produced a transfer.
  • Whitelist — the incoming side: whitelisted partner addresses (the FlowManager AllowIP fields) named in messages. A hit = an allowed address that connected, or tried to, without ever producing a transfer.
  • Logins — names from login name "…", checked against every transfer row’s login.

Rules

  • Only Transfer Manager (runtime) lines count; the admin/audit deploy trail names entities too, but that is configuration activity, not traffic.
  • The known list of every tab is the transfer parse cache itself (every technical row’s attribution), so the comparison covers everything the transfer log ever recorded.
  • Hosts and Whitelist look only for configured endpoints and whitelisted addresses, so every hit is directly actionable.

Tips

  • Click a row for its 10 most recent server-log lines.
