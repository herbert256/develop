Missing entities

What it shows

  • Names the server log mentions but the transfer log never recorded: something alive on the platform (usually in a failed-connection message) that never produced a transfer. One row per name with its Server-log mentions.

Tabs

  • Subscriptions — UC… names in Transfer Manager messages; the server truncates long names, so a prefix of a logged subscription counts as known. Rows carry the subscription’s result colour.
  • Accounts — account "…" mentions (@login stripped), checked against every transfer row’s account.
  • Hosts — configured outbound endpoints (the servers we connect to) named in messages, never a transfer’s remote host.
  • Whitelist — whitelisted partner addresses (AllowIP) named in any component’s messages: an allowed address that connected, or tried to, without a transfer.
  • Logins — login name "…" mentions, checked against every transfer row’s login.

Rules

  • The known set is the whole transfer log, every leg’s attribution included.
  • Hosts and Whitelist look only for configured endpoints and whitelisted addresses, so every hit is actionable.
  • Mentions re-total under the date filter.

Tips

  • Click a row for its 10 most recent server-log lines.
  • The ↗ beside a subscription, account, login or host opens its detail page; a name without one (not configured, or truncated) and a whitelist address have none.
