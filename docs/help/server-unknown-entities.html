Missing Entities

What this shows

Five tabs — Subscriptions, Accounts, Hosts, Whitelist, Logins — each list entity names that appear in server-log messages (Transfer Manager lines only) but never appear in the transfer logs at all. These are entities the server actually saw (usually in a failed-connection message) that never went on to produce a single transfer. It's a cross-check between the two logs: something the server knows about that the transfer side has no record of.

  • Subscriptions — UC… names pulled from server messages. Server messages truncate long subscription names, so a name counts as "known" when it's a prefix of a real one.
  • Accounts — names from associated with account "…", checked against every transfer row's account (not just first-row accounts, so a destination-side-only account isn't falsely flagged).
  • Hosts — the outgoing side: configured endpoint addresses (the FlowManager partner host fields — the servers we connect to) mentioned in server messages, e.g. "tried to connect to remote host …". A hit means the server tried to reach a configured endpoint that never produced a transfer.
  • Whitelist — the incoming side: whitelisted partner IPs (the FlowManager AllowIP fields — the addresses partners connect from) mentioned in server messages. A hit means an allowed partner address connected, or tried to, without ever producing a transfer.
  • Logins — names from login name "…", checked against every transfer row's login.

How it's computed

Each tab counts server-log mentions of the unmatched name and can be clicked to expand its 10 most recent log lines. Only Transfer Manager (runtime) log lines are considered — the admin/audit deploy trail also names entities, but that's configuration activity, not traffic. The "known" list for every tab is the transfer parse cache itself (every technical row's attribution), so the comparison covers everything the transfer log ever recorded. The Hosts and Whitelist tabs additionally scope their search to the FlowManager configuration: only configured endpoints and whitelisted addresses are looked for, so every hit is directly actionable.
