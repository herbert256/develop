Entity coverage

What it shows

One row per configured entity (account, logical flow, partner, domain, application or BL), answering per direction: is the connection working? Two colours only — green = covered (listed first), red = not covered; this verdict overrules the usual status colours.

Columns

  • Subs — configured subscriptions per side; a both-ways subscription counts on both.
  • Files — real logical transfers on that side.
  • Logons (In) / Polls (Out) — the server-log proofs; shown on every view, counted towards the verdict only under Current and Once.

Rules

  • A side is covered when at least one real File moved that way or the server log proves the connection. 0 Subs = nothing to prove, covered; a Both entity needs In AND Out. One File on one of ten configured outgoing connections covers Out.
  • In proof: an account of the entity authenticated over SSH — User with login name "FE…", associated with account "…", successfully authenticated… — so the connection works even when no file was submitted.
  • Logons are counted per account on Logon and rolled up to the account’s entity; on the Accounts view that rollup is the identity.
  • Out proof: a UC3 remote poll succeeded — Applying the search pattern '…' for transfer site '…': N file(s) were found…, logged only when ST could connect and list the remote folder; 0 files found still proves it.
  • Polls are counted per subscription on UC3 status (Polls by subscription) and rolled up to the subscription’s entity.
  • Left buttons pick the entity, right ones the rule. Current (default): works now — the most recent File that way was OK, or a logon / poll proves the link. Once: has ever worked — any File, logon or poll.
  • OK transfers: the transfer, not the link — the most recent File must be OK; logons and polls do not count.
  • Difference between Current & Once: only the regressions — covered under Once, not under Current; every row red, row count = Once’s covered minus Current’s.
  • Full-period; no date filter.
