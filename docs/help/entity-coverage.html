Entity coverage

What this shows

One row per configured partner, answering one question per direction: is the connection to this partner actually working? Rows carry TWO colors only — green = covered (listed first), red = not covered; this verdict overrules the usual partner status colors on this page. A partner configured for Both directions is covered only when In AND Out both work; a side with no configured connections has nothing to prove and counts as covered.

What counts as proof

A side is covered when at least one of these holds:

Files — at least one real logical transfer moved on that side (the partner's Files split by its connection direction). If even one of ten configured outgoing connections moves files, Out is covered.

Out · Polls — a UC3 remote poll succeeded: the server logged Applying the search pattern '…' for transfer site '…': N file(s) were found… That message only appears when ST could connect and list the partner's remote folder — 0 files found still proves the connection works. Counted per subscription by the Remote Polls report and rolled up to the subscription's partner.

In · Logons — the partner's system successfully authenticated: the server logged User with login name "FE…", associated with account "…", successfully authenticated over SSH… Counted per account by the Auth activity report and rolled up to the account's partner — the connection works even when no file was submitted.

The rule buttons

The buttons on the left pick the entity (Accounts, Logical, Partners, Domains, Applications); the ones to their right pick the rule — what a side must show to count as covered:

Current (the default) — the connection works now: the most recent File that way was delivered OK, or a successful logon / poll proves the link.

Once — the connection has ever worked: a File moved that way at all, or a logon / poll succeeded.

OK transfers — the strictest view, about the transfer rather than the link: the most recent File itself must have been delivered OK; the logon and poll proofs do not count here.

Difference between Current & Once — only the regressions: entities covered under Once but not under Current. The connection worked at some point and the most recent attempt did not, so every row is red by construction; the row count is exactly Once's covered count minus Current's.

Columns

Subs = the partner's configured subscriptions per side (a both-ways subscription counts on both sides). Files = real logical transfers on that side. Logons / Polls = the server-log proof counts described above. This is a full-period status report — it carries no date filter.
