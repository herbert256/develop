Partners - Incoming

What it shows

One row per FE login (the credential a partner connects with): every configured login with its use cases, logons, Files and pickup figures. Full-period; no date filter.

Columns

  • Login — links its detail page.
  • Use cases — of its subscriptions: UC2 (the partner picks up from us), UC4 (the partner delivers to us), UC2/UC4 (both: the mailbox pair).
  • Cloud — the newest successful authentication on this platform, any protocol (the detail pages’ Logons figure); empty when the log window holds none.
  • Gateway — the last logon on the old gateway, from input/logons_old.txt.
  • Files in / Files out — Files delivered to us / staged for pickup, by movement direction, whole transfer window.
  • Error — Files that failed, delivered or picked up (Expired has its own column).
  • Retrieved / Waiting / Expired — collected / staged, not collected yet / deleted by the retention sweep before pickup. Retrieved + Waiting + Expired + the failed pickups = Files out.
  • Oldest waiting — age of the oldest staged file, one truncated unit (“5 days”, “12 hours”), against the newest transfer in the log; sorts by exact age; the Total row shows the oldest of all.
  • Pickups — pickup logons (the detail page’s Total pickups); an SFTP client opens several connections per visit, a gap over 30 minutes starts a new visit.
  • Pickup pattern — typical visit spacing (“Hourly”, “Every 6 hours”); Once = a single visit, two visits show their spacing (under three short visits: no cadence); Irregular = fewer than six in ten gaps within half and double the typical spacing.
  • Logon problems — the login’s count on the Incoming logon funnel (Server → Logons & Connections → Incoming, Logon); empty when none. Click it for the Incoming page with the row marked and the count split into six columns:
    • Disallowed (address failed the whitelist) + Bad key (no matching certificate) + Key failures (repeated-key-failure counter) + Locked (lockout) + Auth failed (anonymous failure line, attributed by timing) + Session errors (its sessions’ Error / Warning SSH lines).

Rules

  • Tints: green delivering, red failing, orange configured, never seen; a login only the old-gateway file names (not configured here) is untinted — a partner not yet moved over. A 0 renders empty.
  • Roster = the FlowManager export’s login list; a subscription’s use case = its UC<n> name prefix, else the use case derived from its configuration.
  • Cloud: the server log’s logon summary. Files in / out, Retrieved, Waiting, Expired, Oldest waiting: the transfer files cache (one File per CoreId).
  • Pickups and Pickup pattern: the UC2 pickup data behind UC2 status and UC2 pickup visits, joined through the subscriptions and taken once per login and account; several FE logins on one account each show their own.
  • The visits page repeats an account’s figures per UC2 subscription, so its totals run higher; the visit breakdown (collected, two-way, delivery-only, same-connection) stays there.
  • A login without a UC2 flow, or whose partner collects over CFT/PESIT and logs no SSH visit, has empty pickup cells while its Files still move.
  • The boxes above: logins per use-case mix, logged on here or not, known gateway logons, old-gateway-only logins, the pickup total.
  • input/logons_old.txt: hand-maintained, one login per line — the login, then its stamp (FE000123  2026-09-02 14:35). First token (up to spaces, TAB, comma or semicolon) = the login, case-insensitive; the rest shown as written; blank and # lines ignored. Missing file = empty Gateway column.
