Partners - Incoming

What this shows

One row per FE login — the credential a partner connects with — the login roster with its pickup figures (the former FE status information page folded in). Use cases are those of the login’s subscriptions: UC2 (the partner picks up files from us), UC4 (the partner delivers files to us) or UC2/UC4 (both — the mailbox pair). Cloud is the newest successful authentication on this platform over any protocol (the detail pages’ Logons figure; empty when the log window holds none). Gateway is the login’s last logon on the old gateway, from the hand-maintained file input/logons_old.txt. Files in counts the login’s Files delivered to us and Files out those staged for it to pick up, over the whole transfer window; Error the Files that failed, delivered or picked up (Expired keeps its own column); Retrieved those the partner actually collected — Retrieved + Waiting + Expired + the failed pickups = Files out; Waiting are the staged Files not yet collected, Expired those the retention sweep deleted before any pickup, and Oldest waiting is how long the oldest staged file has waited, in one unit (“5 days”, “12 hours”, …), aged against the newest transfer in the log. Pickups counts the pickup logons (the detail page’s Total pickups; an SFTP client opens several connections per visit, a gap of more than 30 minutes starting a new one) and Pickup pattern the typical spacing of those visits (“Hourly”, “Every 6 hours”, …; “Once” for a single visit, and the spacing between two, when there are too few for a median; “Irregular” when the gaps have no rhythm, fewer than six in ten falling within half and double the typical spacing). Logon problems — one number: the login’s problem count from the Incoming logon funnel (Server → Logons & Connections), Disallowed + Bad key + Key failures + Locked + Auth failed + Session errors, full-period, empty when there are none. Click it for the Incoming page with that login’s row marked, where the count is split into its six columns.

Reading the table

Every configured login is listed, tinted by its result colour: green delivering, red failing, orange configured but never seen. A login that the old-gateway file names but that is not configured on this platform gets an untinted row — a partner not yet moved over stands out that way. The login links to its detail page. A 0 renders empty, so a login without a UC2 flow — or whose partner collects over CFT/PESIT and logs no SSH visit — simply shows empty pickup cells while its Files still move. Oldest waiting sorts by the exact age. The boxes above the table count the logins per use-case mix, those that have and have not logged on here, the known gateway logons, the old-gateway-only logins, and the pickup total. Every figure is full-period; there is no date filter on this page.

How it's computed

The roster is the FlowManager export’s login list; the use cases come from the login → subscription pairs (a subscription is classified by its UC<n> name prefix or, for a flow without one, by the use case derived from its configuration). Cloud comes from the server log’s logon summary; Files in / out, Waiting, Expired and Oldest waiting from the transfer files cache (one File per CoreId, attributed to the login, split by the file’s movement direction). Pickups and Pickup pattern come from the UC2 pickup data behind the UC2 status and UC2 pickup visits pages, joined to the login through its subscriptions and taken once per login and account: on the UC2 pickup visits page the account’s figures repeat on each of its UC2 subscriptions, which is why that page’s totals run higher. On an account carrying several FE logins each login shows its own logon figures. Pickups counts logons; the visit breakdown (collected, two-way exchanges, delivery-only visits, same-connection proof) stays on the UC2 pickup visits page. Retrieved counts the out-side Files whose pickup completed, from the transfer files cache; Files out holds every File staged for the login — retrieved, waiting, expired or (rarely) failed at pickup — so Retrieved + Waiting + Expired = Files out up to those failed pickups.

The input file. input/logons_old.txt holds one login per line: the login, then its stamp — for example FE000123  2026-09-02 14:35. The first token (up to the first spaces, TAB, comma or semicolon) is the login, matched case-insensitively; the rest of the line is shown as written. Blank lines and lines starting with # are ignored. When the file is missing the Gateway column simply stays empty.
