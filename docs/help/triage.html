Triage

What it shows

  • One ranked worklist of every subscription that needs eyes now: red, carrying staged Files at expiry risk, or just went quiet. The boxes count each; links below the table lead to the deep-dive reports.

Columns

  • Status — red (the red result), expiry-risk (Waiting Files staged 9+ days; the retention sweep deletes at ~11) or just-went-quiet (last File 8–13 days before the window end).
  • Since — red: the server-log evidence stamp, else the first failure of the current failing run; expiry risk: the oldest staged File; quiet: the last File.
  • Days in state — days from Since to the last data day, never the wall clock.
  • Files / OK / Error — the flow’s Files over the whole window, by outcome.
  • Volume in window — historical throughput, not an undelivered backlog; At expiry risk — the staged bytes the sweep is about to delete.
  • Score — the rank (Rules); the table opens highest first.
  • Symptoms — the state in words, plus any second condition; Evidence — the proof and the report to read on.

Rules

  • Score = Files / (days in state + 1): state recency times historical weight — yesterday’s flip on a busy flow outranks a month-old red, which outranks a one-file flow.
  • One row per subscription; priority red > expiry risk > just went quiet.
  • A triage desk, not a diagnosis: Failed Subscriptions, Went quiet, Waiting and Subscriptions in boxes are the deep-dives.
  • Full period; a date range does not narrow it.
