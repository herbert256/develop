Added BL

What it shows

What input/BL.txt adds on top of the configuration export: one row per subscription, listing only the BL numbers that come from the file and are not among that subscription’s tags.

Columns

  • Subscription — the configured flow, in its configured spelling, linking its detail page.
  • BLs — the added numbers, comma-separated, each linking its BL detail page (a BL is a full entity, alongside Logical, Partners, Domains and Applications).

Rules

  • A subscription carries its business-line marker in two places: the tags of subscriptions.json (any entry starting with BL) and the hand-maintained input/BL.txt, rows <subscription> <BL>[,<BL>...].
  • The pipeline unions both, so the BL entity always shows every number a flow has; this page is the difference.
  • A subscription whose numbers all come from its tags is not listed; a file that adds nothing gives a one-line page.
  • Names in BL.txt match the environment’s configured subscriptions case-insensitively; a row naming an unconfigured subscription is skipped by the config step, which reports it on the build.
  • Row tint = the subscription’s result: light green last transfer OK, light orange configured but never seen, light red last transfer Error, light blue surfaced only by the server log.
  • Source: the config step (bin/flow-manager.sh) keeps the two sources apart while building the union and writes the file-only rows to xref/_subscriptions-bl-added.tsv; the page renders that sidecar, so it cannot disagree with the pipeline.
