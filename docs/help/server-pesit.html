PeSIT

What it shows

PeSIT activity per day from the PESITD component (the PeSIT protocol layer), its problem lines and diagnostic codes, and the file retention / cleanup sweeps.

Sections

  • Per day — one row per calendar day, gaps as zero rows. Logins/Logouts = “Client logged in/out”; Transfers = “Inbound transfer completed with diagCode”; Conn resets (red) = PESITD “Network error: Connection reset” (also counted in Transfer Error Reasons); Max-conn hits (amber) = “PeSIT server has exceeded the maximum number of allowed connections 100”, the CFT link saturating the 100-connection limit. Click a day for its 10 most recent Warning/Error lines.
  • Problems per day — the problem lines by leg: ST → CFT (the TM component, ST as PeSIT client) and CFT → ST (PESITD, ST as server). One failed transfer commonly logs several lines (the client-side wrapper plus FPDU_AWRITE/FPDU_ABORT pairs): log lines, not failed transfers.
  • Problem types — by message shape, most frequent first. Transfer rejected/refused = the CFT saying no (negative FPDU_ACREATE / SEND_CONF: file-side or configuration issues there); Checkpoint mismatch = a restart disagreement after an interrupted transfer; Connection reset / network incident = the link dropping; the two connection-limit classes = the capacity ceiling on either side (ST refuses above 100 inbound; the CFT refuses with RCONNECT 309 outbound). First/Last seen stay full-period.
  • PeSIT diagnostic codes — the protocol’s own diagCode taxonomy (lines without a code — resets, ceilings — are not in it): 2xx transfer-level (213 refused/file error, 214 checkpoint), 3xx connection-level (309 too many connections, 399 generic/SSL). Share is of all problem lines at the full range, so codes need not sum to 100%; a narrowed range re-shares over this table only.
  • Outbound FPDU ledger — the TM client’s (ST → CFT) Info-level confirmations per FPDU kind and diagCode: connectionConfirmation (session setup), sendFileConfirmation (per file), abortIndication (torn down). Info lines are invisible to the error reports: 309 = the CFT refusing the session (“Too many connections”), 310 a network-incident abort, 214 a checkpoint mismatch on restart, 0 success. Problem types counts the E-level wrappers of the same failures, so the two never double-count.
  • Cleanup — AR0089 “Deleting local file” (the staged copy removed after a leg, per account, endpoint stripped, linked when known); “Deleting remote file … under <dir>” (partner-folder files removed after pickup, per remote directory); “Start File Maintenance” vs “File Maintenance … finished” — a finish is logged only when the sweep deleted files, so far fewer finishes than starts is normal; a big gap for one account, or none finishing, is worth a look.

Rules

  • All PeSIT traffic is the internal cluster CFT (caller P14303_CFT01, remote hosts 145.219.156.20/.21): a capacity and stability view of one internal link; the protocol lines carry no flow names, so there is no partner dimension.
  • Counts are log lines, additive, re-totalled under the date filter. Click a row for its 10 most recent lines, newest first.
