Ranking

What it shows

  • The five rankings of the detail pages’ Ranking section, for every entity of one type at once; the tabs pick one of the nine types (Subscriptions … BL).
  • Each metric is two columns: the position # and the value it stands on.

Columns

  • Files — most Files first.
  • Volume — most bytes first.
  • Errors — Error %, highest first: #1 is the worst; a flawless entity sorts last.
  • Duration per leg — Average OK transfer leg, shortest first; a leg, not a File (File spans are on Duration).
  • Throughput per leg — Bytes/s over the OK legs, highest first.

Rules

  • Ranks never cross types, and only entities seen with real transfers are ranked. Nothing timed: - for Duration and Throughput, still ranked on the other three.
  • The positions are the detail pages’ own, so the two never disagree; a tie shares a position and skips the next ones.
  • From/To re-ranks: every value and position is recomputed over the selected days; an entity with nothing in range drops out.
  • The total row sums Files and Volume on the Subscriptions, Accounts and Logins tabs, where a File belongs to one row; elsewhere a File counts for several names, so it stays blank.

Tips

  • A row of a detail page’s Ranking section opens this page at its type, sorted on that metric, scrolled to the entity’s outlined row, at the full period.
  • Look for mismatches: #1 by volume but #40 by throughput.
