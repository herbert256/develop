Since yesterday

What it shows

  • What changed on the newest data day D (the latest date in either log, the first box). Every table judges against D or D−1: exports arrive in batches, so a late change may surface only in the next one.
  • The boxes count the rows of the five tables. Changes to the reports themselves are on What’s new.

Columns

  • New red flips — red subscriptions whose red run (the failing Files since the last OK) started on D/D−1, or whose server-log evidence after an OK last File is on D/D−1; a chronic failer is not listed.
  • Its columns: When (the run start, else the evidence) · Failing since · Consecutive failures · Files · Evidence.
  • Newly quiet — flows whose last File is exactly 8 days before the window end, so they just crossed the Went quiet threshold: Last File · Days ago · Files carried · Evidence.
  • Recovered — green flows whose first OK File after their last failure is on D/D−1: Recovered · Failed until · OK since recovery · Evidence.
  • First seen — configured logical flows, partners, subscriptions, accounts, logins and hosts whose first-ever File is on D/D−1 (the cells of First seen): Type · Name · Date · Evidence.
  • Server-only names still mentioned — names the server log mentions without a transfer of their own, newest mention on D/D−1: Type · Name · Mentioned · Evidence. Missing entities has the full lists.

Rules

  • Waiting counts as OK; Failed and Expired break a recovery.
  • A first sighting appears here once, then lives only on First seen.
  • Every table covers D/D−1 only; a date range does not narrow them.
