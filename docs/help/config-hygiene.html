Config hygiene

What it shows

  • The first table (Category · Item · Detail, counted by the Findings box) — the orphans: Account without subscriptions, Host referenced by no subscription, Login tied to no account, Whitelist entry no account allows.
  • Then the Subscription, Account, Login and Host twins: names identical once case and -/_ are folded, configured separately.
  • Server-log config defects — recurring single-cause families, each fixable with one configuration change: Profiles that cannot receive (Transfer profile · Errors), DNS-dead configured hosts (Host · Failed lookups), Server tuning warnings (Setting · Warnings); each with First and Last.
  • Double — one name, two roles — Application and partner sharing one name (the Partner accounts and Application accounts behind each role) and Subscriptions connected to two partners; two boxes count them.

Rules

  • Rows tint by the entity’s result colour: a green twin pair is two entities that both work — deliberate, not legacy.
  • A profile that cannot receive misses its Receive File As field, so every incoming transfer using it errors.
  • A DNS-dead host with a Last date near the window end is still failing; a single-day range was a transient.
  • Both roles are legitimate products of the naming convention: a relay’s middle token is system and party at once, or one organisation is the middle segment of one name and the trailing segment of another.

Tips

  • Not in Flow Manager is the reverse: logged values missing from the configuration.
