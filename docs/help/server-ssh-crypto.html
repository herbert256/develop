SSH security

What it shows

  • The cryptography in live use, from the “Connection security parameters” line every authenticated connection logs, with weak algorithms flagged — plus the server’s own security warnings. None of it is in the transfer log. Stacked tables:
  • Negotiations by protocol (first, unheaded) — Protocol, Negotiations, Share.
  • Cipher suites, Key exchange, MAC algorithms, Public-key algorithms — the algorithm (Cipher suite, Key exchange, MAC, Public key), Negotiations, Share (within the table), Assessment (OK or red Weak), First, Last.
  • Deprecated-parameter warnings — Parameter, Account, Subscription, Remote host (as logged; a known name links its detail page), Warnings, First, Last.
  • Hygiene signals and Certificate chain errors by subject — only when the log holds any: ASCII fallback, FTPS setup failed, CONFIG_PASSWD read error, certificate-chain error, disconnect error.
  • Algorithm negotiation failures — outbound SSH connections that died before authentication for lack of a common algorithm: Signal, Log lines, First, Last.
  • PeSIT TLS adoption — the internal ST–CFT link over TLS: Cipher suite, TLS version, Connections, First, Last, Per week (the ramp).
  • Session-lifecycle problems — sessions used after teardown, streams aborted mid-transfer: Signal, Occurrences, Component, First, Last.

Rules

  • Weak: CBC / 3DES / RC4 ciphers, SHA-1 key exchange or MAC, ssh-rsa / ssh-dss keys (they sign with SHA-1).
  • A TLS connection logs only a cipher suite, so Cipher suites counts every negotiation; the other three only the SSH connections that itemise them.
  • Counts re-total under the date filter; click a row for its 10 most recent lines.
