Connection Failures

What it shows

Connection failures per subscription, counted from the server log’s “Connection failure while <site> tried to connect …” ERROR messages — a data source separate from the transfer log. Every failing subscription is counted, well-known ones included (the Missing entities report lists only names absent from the transfer logs entirely).

Sections

  • Known subscriptions — a logged name that is the unique prefix of exactly one known subscription: shown in full, linked to its detail page.
  • Unresolved subscription names — a logged name matching several subscriptions, or none: listed as logged, unlinked.

Rules

  • The server truncates long subscription names in its messages; each token is resolved against the transfer area’s subscription list, data/transfer/reports/subscription.rpt.
  • Share is of all connection failures across both tables at the full range; a narrowed date range re-shares over each table separately.
  • Repeated failures toward one subscription are usually a retry storm against an unreachable partner.
  • The report needs the transfer reports first: without subscription.rpt it fails with an error asking you to run them.

Tips

  • Click a row for its 10 most recent connection-failure lines, newest first.
