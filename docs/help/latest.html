Latest files

What it shows

One page per subscription: its most recent Files, newest first, at most 1000. Opened from the Files row of the subscription page’s Features table; it carried this table itself until 2026-09-16.

Columns

  • Start / End — the first leg’s start and the latest leg’s end.
  • Pickup — UC2 pages only: how long after Start the partner collected the file.
  • State — Delivered, Errored, Waiting (staged, not collected) or Expired (staged, deleted unclaimed).
  • Recovered — yes when the File finished OK after a failed leg; the column shows only when a row carries it.
  • Direction — the connection / file-movement pair (out/in); ? = unknown side, - = neither known.
  • Size, Throughput, Duration — the file once, its rate and its wall-clock span.
  • File, CoreId — the name as logged and the transfer key; the CoreId opens File Tracking.

Rules

  • A row is tinted by that File’s own state: red Errored or Expired, orange Waiting, green Delivered.
  • Files, not transfer records: one row per CoreId, all its legs folded into one.
  • The search box and the From/To selectors apply here (the subscription page has neither); From/To is the shared transfer-area range, so it follows you from other transfer pages.
  • 25 rows per page; csv in the last header cell exports what is shown.
  • Only the newest 1000 Files are kept. A subscription that never carried one has no page, and its Features table has no Files row.
  • The rows load from the page’s own <slug>.js; the Latest files search loads all of them to find a File across every subscription.
