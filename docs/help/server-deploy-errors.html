Deploy errors

What it shows

Accounts and subscriptions a configuration defect stops dead, with no successful transfer since. Two server-log lines qualify, both deployment mistakes rather than runtime faults; Cause says which.

  • Route stopped — ARSP0001 [<account>] [<subscription>] An error occurred while sending the file {…} to a partner site. Step configuration suggests to stop further route execution.: the step’s configuration told SecureTransport to abandon the rest of the route, nothing downstream ran for that file, and the flow can sit so indefinitely, looking quiet rather than broken.
  • Receive File As not set — PeSIT Transfer profile '<P>' of account 'SECURETRANSPORT' is used for incoming transfer, but 'Receive File As' field not set.: one profile field never filled in, so every incoming transfer of that flow errors.

Columns

  • Account or subscription — the subscription when a bracket names a configured flow (ARSP0001’s second bracket; a name fronted by the platform’s own SECURETRANSPORT account, blacklisted everywhere else, is taken as the flow); the account only when no bracket names one (the ARPA0001 “publishing to an account” variant names a destination account). The @FE… endpoint suffix is stripped, so the name links to its detail page.
  • Type — account or subscription. Cause — Route stopped, Receive File As not set, or both.
  • Messages — how many such lines; a high count is a flow retrying into the same wall. Last message — the most recent; rows newest first.

Rules

  • A Receive File As row names the subscription its profile belongs to, resolved through the configuration: a transfer profile is internal plumbing with no page and never an entity; a profile matching no single configured flow is left out, not guessed. Config hygiene lists the defect per profile, recovered ones included.
  • Only unresolved entities appear: an OK File after the last message drops the row (history, not a live problem); a UC3 subscription is also cleared by a successful poll after its last message, even one that found no files. Exact to the millisecond, so a same-day recovery clears it. The same rule as the Connection failures box.
  • Connection failures covers connections never established at all; the entity’s detail page carries its recent server-log lines in full.
