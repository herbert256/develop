BL Details

What it shows

The detail page of one BL: a tags entry of a configured subscription starting with BL, kept verbatim, or a BL number listed for it in input/BL.txt.

Sections

  • KPI line — rank and share of traffic among all BL tags, failure rate, total volume, cadence, and processed-transfer performance where durations are recorded.
  • Last error(s) — directly above Features, only when a subscription it moves files with has an error: one row per such subscription, its most recent error, newest first, with date and time, subscription and file.
  • Features — a Partner, Application, Domain or Logical breakdown holding exactly one row is folded away into a Features row, keeping its link and colour.
  • Activity per day.
  • Breakdowns — every dimension the tag’s transfers touch: subscription, account, login, remote host, domain, application, logical, partner.
  • Latest Files and the load tables.

Rules

  • The Subscriptions table’s nonzero Error count opens Failed files for that subscription at the full date range: every failed File of the subscription, so a page that sees only part of its traffic can list more.
  • A file belongs to a BL through its subscription: every BL tag of the File’s subscription counts it.
  • Every count is in Files: one per logical transfer, split by its delivered (final-row) outcome, volume counted once per file.
  • The subscription / account / login / remote host tables are cross-referenced with the FlowManager configuration: every name configured for this tag is listed, seen or not — green rows have logged data, red rows are configured but never seen; each links its own detail page.
  • Every configured BL has a page, seen or not. Background: light brown = seen & in, light blue = seen & out, light gray = seen & both/unknown, light yellow = never seen & in, light orange = never seen & out, light purple = never seen & both/unknown.

Tips

  • Click anywhere on a Last error(s) row for that file’s error page: every transfer leg and the server log of the failure.
