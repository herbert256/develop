Use cases

What it shows

One row per use case — what it means and how many configured subscriptions it has, by status — then the FlowManager templates behind them. Every use case with a published template (templates.json) is listed, one no subscription uses yet with blank counts.

Columns

  • Direction — connection side / file movement: out/in = we connect out, the file comes towards us.
  • Trigger — OpsWise = our automation initiates (UC1, UC8); Partner = the partner connects in (UC2, UC4, UC7); Cronjob = a Quartz receive scheduler polls the partner (UC3, and the pull side of UC5/UC6).
  • We are — SecureTransport as client or server. We — send, receive or relay.
  • Total / Seen / Error / Warning / Ok — configured subscriptions; the most recent transfer ended Error / OK; never seen = Warning. Seen = Error + Ok. A count opens the Subscriptions page filtered to that use case and colour.
  • Templates — the published flow templates (🔗 opens one in FlowManager); Route = the flow pattern a subscription instantiates; Subscriptions = those created from it. UC1 and UC3 each have two variants (via SecureTransport ST or the CFT hub directly CFT).

Rules

  • Subscriptions: subscriptions.json via data/flow-manager/base/_subscriptions.tsv. Status buckets read that cache’s result column, filled by the build’s Server → Transfer and result steps.
  • Use case of a subscription: its UC<n> name prefix, else the use case derived from its configured pattern — the one derivation every page uses.
  • UC1–UC4 bridge one partner to our internal application; UC5–UC8 are direct relays with no CFT leg. Definitions: one shared table (bin/uc-cases.sh), also behind the Subscription detail pages.
  • A warning appears under the table when a subscription’s configured direction disagrees with its use case.
  • Templates: templates.json via data/flow-manager/xref/_templates.tsv; a template’s flow pattern equals the pattern on its subscriptions (the join). Without that export the pages fall back to the subscription-derived UC list and omit the Templates table.
