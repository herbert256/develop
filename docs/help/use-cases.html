Use cases

What it shows

  • One row per use case — its meaning and its configured subscriptions by colour — then, with the FlowManager template export loaded, the templates behind them.

Columns

  • Use Case — UC1…UC8; (none) collects the subscriptions with no use case.
  • Direction — connection side / file movement: out/in = we connect out, the file comes to us.
  • Trigger — OpsWise (our automation starts it), Partner (the partner connects in) or Cronjob (a receive schedule polls the partner).
  • We are — client, server or both; We — send, receive or relay.
  • Total · Seen (a File in the transfer log) · Error (red) · Warning (orange) · Ok (green) — Total and the colour counts open Configured subscriptions filtered that way; Total leaves out the skipped (white) ones.
  • Seen is not always Error + Ok: a UC3 that polls and cannot connect is red without ever transferring a File.
  • Description — the use case in one sentence.
  • Templates — Template (🔗 opens it in FlowManager) · Use Case · Route (the flow pattern) · Subscriptions created from it · Status (its own status code) · Last modified.

Rules

  • A subscription’s use case is its UC<n> name prefix, else the one derived from its configured pattern — the same everywhere on the site.
  • UC1–UC4 bridge one partner to our internal application; UC5–UC8 relay between two partners with no internal CFT leg.
  • ⚠ under the table: subscriptions whose configured direction disagrees with their use case — a naming or configuration error.
  • Colours per Generic help.
