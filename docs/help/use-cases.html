Use cases

What it shows

The configured subscriptions grouped by UC<n> name prefix, on two tabs; a third tab, Use Case patterns, groups accounts by subscription mix.

Both tabs list every use case with a published FlowManager template (templates.json), including one no subscription uses yet (blank counts on the traffic tab).

Use Case traffic tab

  • Status columns as on the Flow manager Entities table: Total configured subscriptions, Seen (= Transfer + Server), Transfer (in the transfer logs), Server (surfaced only by the Server → Transfer step: in the server logs, never in the transfer logs).
  • Error / Warning / Ok — the most recent transfer ended Error / OK; never seen = Warning. Total = Server + Error + Warning + Ok.
  • Every nonzero count links a page listing exactly the subscriptions it counts, each linked onward. Description = the UC’s one-line meaning.

Use Case definitions tab

  • Trigger — OpsWise = our automation initiates (UC1, UC8); Partner = the partner connects in (UC2, UC4, UC7); Cronjob = a Quartz receive scheduler polls the partner (UC3, and the pull side of UC5/UC6).
  • From / To — Internal (our systems, over the internal CFT hub) or External (a partner). We are — SecureTransport as client or server. We — send, receive or relay.
  • UC1–UC4 bridge one partner to our internal application; UC5–UC8 are direct relays with no CFT leg, one per push-pull combination.
  • UC5 we pull → we push (two external partners); UC6 we pull → the target collects; UC7 the source delivers → the target collects; UC8 the source delivers → we push (in practice two internal systems).
  • UC6 and UC7 have a template but no subscriptions yet: template-derived rows.
  • Consistency check below the table: each subscription’s configured direction must match its prefix (UC1/UC3/UC5 outbound, UC2/UC4/UC7 inbound; mixed relays UC6/UC8 exempt); exceptions are flagged.
  • Templates table — the published FlowManager flow templates; the 🔗 icon opens one in FlowManager. Route = the flow pattern a subscription instantiates (source leg → SecureTransport/CFT → target leg).
  • Subscriptions = configured subscriptions created from the template, matched on the subscription’s pattern; the total reconciles with the traffic tab. UC1 and UC3 each have two variants — relayed through SecureTransport (ST) or handled by the CFT hub directly (CFT) — splitting one traffic row.

Rules

  • Subscriptions: subscriptions.json via data/flow-manager/base/_subscriptions.tsv. Status buckets read that cache’s result column, filled by the build’s Server → Transfer and result steps.
  • Definition rows: one shared table (bin/uc-cases.sh) that also feeds the Subscription detail pages’ Summary.
  • Templates: templates.json via data/flow-manager/xref/_templates.tsv; a template’s flow pattern equals the pattern on its subscriptions (the join). Without that export the pages fall back to the subscription-derived UC list and omit the Templates table.
