Transfer top view

What it shows

  • One row per calendar day of the transfer log, newest first, total on top; opens at the full period. Days without data get a zero row.

Columns

  • Date — opens the day page.
  • Files — Count / Ok / Error / Error %: logical transfers (one per CoreId), each credited to its start day.
  • Recovered — Files with a failed leg that still ended OK: Automatic = the platform’s retry delivered, Manual = a leg was resubmitted.
  • Resubmit — every File with a resubmitted leg, Ok or Error by outcome; one without a failed leg counts here, not under Recovered.
  • Transfers — Count / Ok / Error / Error %: the physical log rows (legs).
  • State — the Files by final state: Processed, Failed, Waiting (staged, not collected yet), Expired (deleted uncollected, never delivered).
  • Volume — the bytes of every File started that day.

Rules

  • Elsewhere Processed + Waiting count as OK, Failed + Expired as Error.
  • The home page’s Cured = Automatic + Manual.

Tips

  • A Files Ok cell drills to the day’s 10 newest OK Files. Other day cells open that day: Error → Failed files; Automatic → its recovered Files; Manual, Resubmit Ok / Error → its resubmitted Files; Waiting / Expired → Waiting & Expired, day marked; Volume → Sizes & types.
  • On those two lists a row opens its File page: every resubmitted File, the five newest recovered per subscription.
  • Recovered files splits Recovered per subscription, protocol and day.
