Transfer top view

What it shows

  • One row per calendar day of the transfer log, newest on top, with a total row above; always opens at the full period. Days without data get a zero row.

Columns

  • Date — opens the day page; (partial start) / (partial end) / (partial) marks an edge day the export did not cover fully (first time after 02:00, last before 22:00).
  • First / Last — the day’s first and last transfer time.
  • Files — Count / Ok / Error / Error %: logical transfers (one per CoreId), each credited to its start day.
  • Recovered — Files with a failed leg that still ended OK: Automatic = the platform’s retry delivered, Manual = a leg carries the Resubmitted flag.
  • Resubmit — every File with a resubmitted leg, Ok or Error by final outcome (Waiting = Ok, Expired = Error); a re-delivery without a failed leg counts here, not under Recovered.
  • Transfers — Count / Ok / Error / Error %: the physical log rows (legs).
  • State — the Files by final state: Processed, Failed, Waiting (staged, not collected yet), Expired (deleted unclaimed by the retention sweep, never delivered).
  • Volume — the bytes of every File started that day.

Rules

  • Only here are the four states apart; elsewhere Processed + Waiting count as OK and Failed + Expired as Error.
  • The home page’s Cured = Automatic + Manual.

Tips

  • A Files Ok / Error cell drills to that day’s 10 newest Files; a nonzero Waiting / Expired cell opens Waiting / Expired.
  • Recovered files splits Recovered per subscription, protocol and day.
