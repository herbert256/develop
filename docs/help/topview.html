Top View

What this shows

Top View is the transfer log's landing dashboard: one row per calendar day, with the day's first/last time and three column groups. Files — logical transfers (one per CoreId, the site-wide counting unit) with their Count / Ok / Error / Error % split. Transfers — the same day counted as physical log rows (one per transfer leg), with the same split. State — the day's Files by their final state: Processed (delivered), Failed, Waiting (UC2 staged for pickup, not collected yet — a live state, amber) and Expired (deleted by the retention sweep before any pickup — never delivered). On the other reports Processed + Waiting count as OK and Failed + Expired as Error; this page is where the four states appear separately per day. The page always loads at the full date range regardless of any range remembered from another page — it's meant to show the whole dataset at a glance. The Date cell opens that day's page; a Files Ok or Error cell clicks open to that day's 10 most recent Files of that outcome.

Sessions are not counted here — the site counts Files (records grouped per CoreId).

How it's computed

The Files columns come from the same normalized activity stream that feeds Activity per Day (one record per File); the Transfers columns are counted from the tokenized row cache; the State columns split the logical-transfer cache by its outcome column, per the file's start day. Calendar gaps are filled with zero rows, and an edge day is flagged (partial start) or (partial end) when the log collection window began or ended partway through it.
