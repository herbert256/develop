Top View

What it shows

The transfer log’s landing dashboard: one row per calendar day, newest on top, with first/last time. Always loads the full date range, whatever another page remembered.

Columns

  • Date — opens the day’s page; (partial start) / (partial end) when the collection window began or ended partway through it.
  • Files — logical transfers (one per CoreId, the site-wide unit; Ok when the final row processed): Count / Ok / Error / Error %.
  • Recovered — Files with a failed leg that still finished OK (under Files/Ok, their failed legs under Transfers/Error): Automatic = the platform’s own retry delivered, Manual = a leg carries the log’s Resubmitted flag (operator resubmit).
  • Resubmit — every File with a resubmitted leg, Ok or Failed by final outcome (Waiting = Ok, Expired = Failed); a resubmit without failed leg (re-delivery) counts here, not under Recovered.
  • Transfers — the day as physical log rows (one per leg), same Ok/Error split.
  • State — the Files by final state: Processed (delivered), Failed, Waiting (UC2 staged, not collected yet: live, amber), Expired (retention sweep deleted it unclaimed ~11 days after staging: never delivered).

Rules

  • Elsewhere Processed + Waiting = OK and Failed + Expired = Error; only here are the four states separate.
  • Files: the normalized activity stream behind Activity per Day; Transfers: the tokenized row cache; State: the logical-transfer cache’s outcome column.
  • Recovered / Resubmit join both caches per CoreId: recovered = outcome OK with a row not Processed; Manual and Resubmit read the Resubmitted flag.
  • Every per-File figure credits the File’s start day; the home page’s Cured = Automatic + Manual.
  • Calendar gaps get zero rows. Sessions are not counted (the site counts Files); Session Topview has them.

Tips

  • A Files Ok / Error cell opens the day’s 10 most recent Files of that outcome; a nonzero Waiting / Expired cell opens that report.
  • Recovered files splits Recovered per subscription and protocol.
