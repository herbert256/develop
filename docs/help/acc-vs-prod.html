Acceptance vs production

What this shows

The two environments’ entities compared by name, one page per entity type (Accounts, Subscriptions, Logins, Hosts, Partners, Domains, Applications, Whitelist). An entity counts here when the environment knows it at all — configured in FlowManager or seen in the logs.

The three views

The second button row splits the names into three disjoint sets:

Only acceptance — names known to Acceptance but not to Production.
Both — names known to both environments, shown as two columns: the Acceptance column links that environment’s detail page, the Production column the other’s — so both sides are one click away. Each column is tinted by its own environment’s result, so a flow that is healthy in Acceptance but failing in Production shows green next to red.
Only production — names known to Production but not to Acceptance.

Names are matched case-insensitively; each column shows its environment’s own spelling. The button labels carry the three counts.

Activity columns

Next to each name, Files and Volume show that environment’s own logged activity over its data window (lifted from the environment’s entity reports, so the figures always agree with them). A blank pair means the name is configured but never logged there — so in the Both view, a flow that is busy on one side and blank on the other is dormant in that environment, which the name comparison alone cannot show. Whitelist has no entity report, so that type keeps the name-only layout. The total row sums the Files column per environment.

The Summary view

The fourth button, Summary, is the verdict layer: per type the three set sizes plus the Both set’s activity split (busy in both, or dormant in exactly one environment), followed by the two promotion gaps — the top flows active in production that acceptance does not know at all (untestable: production traffic with no acceptance twin to test against) and the top flows active in acceptance never promoted to production.

Subscriptions vs partners

The last button of the type row opens a cross-view: the subscriptions present in both environments whose partners differ between Acceptance and Production, with each environment’s own partner(s) and account(s) beside them, every name linking its own environment’s detail page. Read a difference with care: it can be a real configuration gap, but it can also be the per-environment partner grouping — the same organisations merged into one group on one side and kept as separate partners on the other.

Colors

The standard entity results: green = last transfer OK, red = last transfer Error (or server-log errors after it), orange = configured but never seen, blue = seen in the server log only. An untinted name was logged but is not configured.

Freshness

Each environment’s copy of these pages is generated during that environment’s build pass and reads the other environment’s data as it is on disk at that moment — after a full build the Production copy is fully fresh and the Acceptance copy may lag the other side by one build.
