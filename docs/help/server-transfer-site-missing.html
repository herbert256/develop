Transfer site missing

What this shows

Endpoints where SecureTransport ran a transfer with no transfer site in its environment and fell back to the communication profile’s raw host, port and user. The server log says so literally:

Transfer site ID is not present in environment. Using host, port and user: host:port:user

The transfer still moves — the fallback works — so this is a configuration gap rather than a runtime failure: a route or profile that lost its transfer-site reference. What it costs is everything the subscription would have governed: with no site there is no site-level routing and no site-level limit, and the connection is made on profile values alone.

Why the rows are hosts

Because that is all the message names. This is the one server-log line that identifies no flow at all — it reports the absence of the very thing that would tie the connection to a subscription, and neither the message nor its session mentions one. Listing it per endpoint is the most precise thing the log supports; a host appears once however many subscriptions use it.

That property is why the line is here rather than anywhere else. It sits in the endpoint’s server-log ring, where it once counted as evidence against every subscription configured for that host. The colour rules now redden a host only on unattributable Errors, and these are Warnings, so they had no home until this page.

Recovered endpoints are not listed

A host that has moved a file OK since its newest warning is dropped: a later OK transfer through the same endpoint says the gap is closed. It is the same “recovered since” test Deploy errors applies to a configuration defect, and the intro says how many hosts were cleared that way — in acceptance it is usually most of them, which is what makes the remainder worth reading.

The columns

  • Host — the endpoint the fallback connected to, linked to its detail page.
  • Warnings — how many times it happened.
  • Users and Ports — the other fallback values, read from the message itself. Several users on one host usually means several profiles share the endpoint and more than one has lost its site reference.
  • First / Last — the window the warnings span. A tight burst is a change that went wrong; a long tail is a gap nobody has noticed.
