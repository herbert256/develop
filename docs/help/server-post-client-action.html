Post client action error

What this shows

Every Post client action error line the server log holds, one row per line, newest first: the action that runs after a file was received — typically the delete of the source — failed; the file arrived, its cleanup did not. The line looks like this:

ARRC0009: [CD_ARIVA_HAANSADVOCATEN@FE000225] [] Error deleting the file after a post client action.

The table

  • Date & time — when it happened, to the second.
  • Account — the first bracket of the line, before the @; it opens the account's detail page.

How it's computed

The tokenized server log is scanned for Advanced Routing lines (an AR<code>: prefix with its two bracket groups) whose text carries the message above; the account is read from the bracket named in the table and folded to its current name when it was renamed. The report shows at most 1000 rows and at most 10 rows per account — the newest ones on both counts; the intro and the total row say how many lines the log really holds. The date filter, search and sort work over the shown rows. The Could not send file report is its twin for the AR0074 delivery failures.

Why it matters

Each row is a file whose routing did not complete as configured; a account that keeps appearing has a problem on this step that the Errors reasons and its own detail page put in context.
