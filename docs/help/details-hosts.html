Remote Host Details

What it shows

One page per remote host — a raw IP or a configured endpoint hostname — linked from every Remote Host cell across the site.

Sections

  • KPI line — rank and share among all remote hosts, failure rate, volume, cadence, processed-transfer performance where a duration is recorded; for an endpoint hostname also its forward-resolved address(es) — one hostname can have several over time.
  • Features, Activity per day, Logons — side by side at the top; then Activity per week / hour / weekday. A single-row Partner, Application, Domain or Logical breakdown is folded into a Features row, keeping its link and colour.
  • Last error(s) — above Features, only when a subscription it moves files with has an error: one row per such subscription, its most recent error, newest first — date and time, subscription, file. Red = failed, orange = expired before the partner collected it.
  • Breakdowns — account, subscription, login, protocol, AV scan, security parameters, direction, action-by, mode. The day table leads with Files; Subscription comes first below it, Account right under the connection tables.
  • 10 largest transfers, Latest 100, then the two connection tables.
  • Incoming connections — the AllowIP whitelist (patterns expanded) of the partner this host is configured under, unioned with the addresses observed on incoming connections attributed to this host.
  • Outgoing connections — the host itself as configured endpoint plus the hosts observed on its outgoing connections; IP = the endpoint’s forward-resolved address(es), Name = its configured hostname.
  • Last server log messages — at the bottom: its 25 most recent lines merged with its 10 most recent Error/Warning lines, plus the Error/Warning lines of its 1-to-1 connected entities (its one account, subscription, login) after the host’s last transfer. Deduplicated, newest first, full-period.
  • Any such after-the-last-transfer line raises the red top banner ERRORS IN SERVER LOG AFTER LAST TRANSFER – SEE LOG AT BOTTOM OF THIS PAGE.

Connection tables

  • One layout: address · In · Out · Name; In / Out = the Files the address moved (In = entered us, Out = left us).
  • Name = the configured endpoint mapped to the address by input/ip/ip-hosts.tsv, blank when none; no reverse-DNS lookup.
  • Light green = configured and used; light red = traffic with an address NOT in the configuration; light orange = configured, never seen (collapsed behind one summary row); light blue = whitelisted address sighted only in the server log, never a transfer (stays visible).
  • Full-period figures: the date filter leaves both tables unchanged.

Logons table

  • Inbound (its addresses connect to us) — first successful authentication, pattern, count (newest in Last), plus the Allowed and Disallowed whitelist-screening counts, the only funnel families whose lines carry the client address.
  • Outbound (we connect to it) — Connections (out) = every connection SecureTransport opened toward its addresses, with its own first stamp and pattern.
  • Red rows classify our failed attempts: Timeouts (socket timeouts, PeSIT “317 Time out” aborts), SSH errors (SSH layer failing without detail), Network errors (incidents, refusals, drops), TLS handshake (bad/unknown certificate, handshake failure), Too many connections, SSH negotiation (algorithm mismatch, rejected host key), Proxy errors (SOCKS).
  • Auth failures (red) = our authentication failures there, the Logon report’s Outgoing-tab evidence, split into Password, Key, Certificate, Other, each with its last occurrence.
  • An endpoint sums over its resolved addresses; no connection evidence in either direction = no table.

Rules

  • The Subscriptions table’s nonzero Error count opens Failed files for that subscription at the full date range: every failed File of the subscription, so a page that sees only part of its traffic can list more.
  • Every count is in Files, as distinct (host, CoreId) pairs: a File touching several hosts counts once on each host’s page.
  • The account / subscription / login tables are cross-referenced with the FlowManager configuration: every partner configured for this host is listed — green = logged data; red = configured, never seen with it (no counts, a link to its never-seen page). Partners logged but not configured are listed too (green).
  • Narrowing the date filter re-tints: a partner without activity in the range turns red instead of being hidden.
  • Every configured name from the FlowManager exports has a page. Background: light brown = seen & in, light blue = seen & out, light gray = seen & both/unknown, light yellow = never seen & in, light orange = never seen & out, light purple = never seen & both/unknown.
  • A never-seen page opens with a “configured, never seen” line, its configured cross-references (all red) and any whitelisted IPs.
  • Configured both ways: every outcome splits into In - Error / In - OK / Out - Error / Out - OK by each file’s own direction; a file without a direction counts in Files and Volume only.

Tips

  • Click anywhere on a Last error(s) row (name included) for the file’s error page: every leg plus the server log of the failure — the files of the Failed Subscriptions list, which guarantees every subscription’s last error has a page.
