File search

What it shows

Search the transfer logs’ Files by file name or CoreId, split into up to seven pages so each loads and answers fast. A match shows date and time, subscription, size and CoreId; the row colour is its outcome.

Rules

  • The first button row switches implementation: Implementation 1, period — these window pages; Implementation 2, all files — the All files search.
  • Windows: 24 hours (the newest full day, plus the partial newest day when one exists), 48 hours (the second full day), Week (the rest of the last seven days), 2 weeks and 3 weeks (a week each further back), Month (through data day 30), > 1 month (every file older than that — always shown, empty when the data spans a month or less; the other windows appear only when they hold files).
  • Windows never overlap — a file is on exactly one page. A window with no files gets no page and no button.
  • Each page ships every file of its window — no cap.
  • The results follow as you type a file name or CoreId (or part of either); Enter searches at once. ? = one character, * = any run; several space-separated words must all match. Matches newest first, the first 500 shown.
  • Switching window re-runs the current search there — the buttons carry the query, and it survives a reload.
  • Green = OK (Delivered, or Waiting — staged for a UC2 pickup that has not happened yet); red = Error (Failed, or Expired — a staged file deleted by File Maintenance before pickup).

Tips

  • A red row with its own error page (the facts, every transfer leg and the server log behind it; kept for a subscription’s newest 10 failures of each day) opens it from anywhere on the row; every other row opens its subscription’s detail page.
