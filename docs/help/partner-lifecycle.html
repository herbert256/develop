Partner lifecycle

What it shows

The three quiet failure modes of a partner relation, one table each.

Sections

  • Configured, never live — the onboarding that never happened: the name and its subscriptions exist, no File ever flowed. Its Subscriptions column counts the configured subscriptions waiting behind the name.
  • Gone quiet — partners with real history followed by 14+ days of silence, measured against the newest log day.
  • Shrinking — the partner still transfers, but the number of its subscriptions actually carrying Files dropped by 2 or more between the previous 14 log days and the last 14: flows dying one by one while the relation as a whole looks alive.

Rules

  • Partner attribution is the site-wide UNION rule (the subscription’s configured partners unioned with the parse attribution), so the figures match the Entities and coverage views.
  • In the never-live table the row colour is the partner’s standard result colour: orange never seen anywhere, blue seen in the server log only (a connection, still zero Files).
  • “Active subscription” in the shrinking table = a distinct subscription with at least one File in the window; the drop threshold of 2 filters ordinary week-to-week noise.
