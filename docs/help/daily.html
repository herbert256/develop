Day pages

What it shows

One calendar day for one log — a transfer page (file movements) or a server page (the platform’s own log) — opened from a date on either Top view. Top links: previous/next day, the other log’s page for the same day, back to the Top view.

Sections

  • KPIs — Transfer files, Transfer error rate, Volume, Server lines, Server error rate; cards add the activity window, average File size, active subscriptions, resubmissions, busiest-hour share.
  • Hero chart — the only graph: the dashboard’s activity views at 15 min / 30 min (default, 48 slots) / 1 hour by start time. Line / Bar / Solid switch, hover tooltip, collapsible Data table.
    • Duration (default) — P50/P90/P98 of the slot’s OK Files, stacked dark-green/orange/dark-red bands, the dashboard’s fixed scale.
    • Files processed — OK Files. Volume — bytes.
    • Error % Files — small slots mislead: 1 of 2 = 50%; empty = a gap.
    • Transfer errors — raw Status Failed / Failed Subtransmission records: legs, not Files; none = a real zero.
    • PeSIT — CFT-link problem lines, ST→CFT red vs CFT→ST purple; only with server-log coverage.
  • Server log problems this day — errors, warnings, any non-zero signal: logon screening failures both ways (partners failing ours, us refused at theirs), connection failures, route-abandon deploy errors, PeSIT ceiling hits, configured remote directories that do not exist, UC3 polls of an always-empty directory, UC3 failing polls (the scheduled poll itself errors).
  • Transfer log problems this day — failures, one-legged transfers, subscriptions gone from green to red or only red, files staged that day still waiting or expired before it, the Anomaly scan when the day has findings.
  • Remarkable facts — only what stands out.
    • Transfer: busiest/quietest day of the window, heaviest volume, error rate well above the period average, a fully clean day, a flow with every File failed, a zero-byte spike, a heavily-retried transfer, one account or hour dominating, overwhelmingly inbound or outbound, one protocol carrying most legs, an unusually long transfer, the largest file, accounts first seen that day or quiet after it, heavy resubmission, weekend activity.
    • Server: busiest/quietest server day, most errors, an error-spike hour, a warning surge, PeSIT 100-connection ceiling hits, one dominating message, an authentication-failure surge, an unusually busy component.
  • Busiest this day — six tables: the five biggest partners (left) and subscriptions (right) by Files, Volume, Errors; none = not listed (a clean day has no Errors tables). See more → opens the Entities view narrowed to the day, sorted descending on that column.

Rules

  • Transfer figures count Files (Shared Concepts), server figures raw log records; both reconcile with the day’s Top view rows. Rebuilt every build.
  • No From/To filter — the page is the filter; every KPI and chart title links its report pre-narrowed to the day (?axway_date= sets the target’s From/To).
  • The two lists carry every Subscriptions in boxes signal with dated evidence, on its day; only Missing cron, Went quiet, Not seen have none. Entries open pre-narrowed, except the full-period reports (from green to red, only red, waiting, trouble after success, deploy errors, failing polls). Nothing to report = no list.
  • Partner figures use the union rule (a File counts for every partner of its subscription as well as its own), matching the entity reports.
  • “First seen” / “went quiet” are relative to the loaded window: first seen on its first day is not called new, quiet on its last day not called gone.
  • View and style are remembered across previous/next day and to/from the dashboard, whose slot columns link into these pages.
  • Server KPI cards (records, error rate) and facts join the transfer ones; full-period message clusters are on Top messages.
