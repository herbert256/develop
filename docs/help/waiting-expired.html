Waiting & Expired

What it shows

  • Staged UC2 Files: Waiting = staged, the partner has not collected it yet; Expired = the nightly File Maintenance sweep (03:00, ~11 days after staging) deleted it before any pickup — never delivered.

Columns

  • Summary — per start day: Waiting and Expired Files (every File, the Unknown subscription’s too). From/To narrows it; a count opens that day’s list of those Files; the date opens the day page.
  • Subscriptions (beside it) — Waiting and Expired (each opens that subscription’s list of those Files), Collected (delivered Files the partner picked up), Oldest Waiting (how long its oldest still-waiting File has waited) and Last Expired (how long ago its newest deletion was), both up to the data’s last record in one unit — 5d, 16h, 14m. Sorted by Oldest Waiting; an Expired count is red.

Rules

  • Subscriptions rows: the subscription’s current colour. The state at the data’s end: no date filter.
  • Subscription lists: Waiting Files orange, longest waiting first (Waiting for runs to the data’s last record, in one unit: 5d, 16h, 14m); Expired Files red, last expired first.
  • Day lists: every Waiting (orange) or Expired (red) File that started that day — Date/time, Subscription (Unknown included, not linked), File name, CoreId — newest first; as many rows as the Summary cell counts.
  • Every list: the first 10 rows open their File page; a Total row; a button back to Waiting & Expired.
  • The deletion leaves no transfer-log record: it comes from the server log’s File Maintenance “Deleted files” lines, matched on account and file name.

Tips

  • A subscription detail page’s Waiting / Expired count opens this page with its row marked.
