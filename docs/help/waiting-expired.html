Waiting & Expired

What it shows

  • Staged UC2 Files: Waiting = staged, the partner has not collected it yet; Expired = the nightly File Maintenance sweep (03:00, ~11 days after staging) deleted it before any pickup — never delivered.

Columns

  • Summary — per start day: Waiting and Expired Files (every File, the Unknown subscription’s too). From/To narrows it; a count opens that day’s 10 newest such Files; the date opens the day page.
  • Subscriptions (beside it) — Waiting and Expired (each opens that subscription’s list of those Files), Collected (delivered Files the partner picked up), Oldest Waiting (how long its oldest still-waiting File has waited) and Last Expired (how long ago its newest deletion was), both up to the data’s last record in one unit Oldest Waiting (when its oldest still-waiting File was staged), Last Expired (its newest deletion).
    • mdash; 5d, 16h, 14m. Sorted by Oldest Waiting; an Expired count is red.

Rules

  • Subscriptions rows: the subscription’s current colour. The state at the data’s end: no date filter.
  • The list pages: Waiting Files orange, longest waiting first (Waiting for runs to the data’s last record); Expired Files red, last expired first.
  • The deletion leaves no transfer-log record: it comes from the server log’s File Maintenance “Deleted files” lines, matched on account and file name.

Tips

  • A subscription’s Entities Waiting / Expired cell opens this page with its row marked.
