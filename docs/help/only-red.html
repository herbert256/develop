Only red

What it shows

The never-worked list: one row per subscription whose every File is an Error (Failed or Expired) — not one OK delivery in the whole log window. Dead configurations, wrong endpoints, credentials that never matched, or flows abandoned right after setup. Most recent failure first.

Columns

  • Files — all of them errors, with the Failed / Expired split.
  • First / Last failure — the newest on top are still actively trying and failing; a long-past last failure suggests an abandoned flow.
  • Days failing — first failure to the dataset’s last day.
  • Volume — the bytes of the failed attempts.

Rules

  • One pass over the Files per subscription, with the site-wide outcome rule: Error = Failed or Expired (a staged UC2 file the retention sweep deleted before any pickup), OK = Processed or Waiting (staged and still collectable).
  • A single OK File disqualifies a subscription — a Waiting one included, so a UC2 flow whose file simply has not been collected yet is not “only red”.
  • Always the full period, no date filter (like From green to red and Failure Episodes): “never delivered” is a whole-window property; a narrowed range would fabricate entries by cutting away the successful days.

Tips

  • Click an Error count for that subscription’s 10 most recent failed Files.
  • From green to red is the exact complement: red now, green before. Counts can differ slightly from its “never green” — a subscription with one mid-day OK File never ended a day green, yet delivered once, so it is excluded here.
  • Failure Episodes shows every failure run; its Last OK column reads “never” for these flows. Failure rate answers what share fails for flows that partially work.
  • These subscriptions are red on the Entities pages and their detail pages by the same outcome rule.
