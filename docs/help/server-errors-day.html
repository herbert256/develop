Errors

What it shows

The server log’s own info/warning/error records (data/server/cache/_parse.tsv, not the transfer log) from every angle, one tab per table. Every number is a count of log records, not Files.

Sections

  • Reasons — one row per failure-reason bucket (connection, PESIT refusal codes, network, routing); each PESIT reason= code gets its own bucket; Example message = the first occurrence, truncated; unrecognized families land in “Other” so new problems surface rather than vanish. Below it, Reasons over time: the same buckets per ISO week, newest first, full period.
  • Heatmap — hour × weekday, each cell the Error + Warning total, tinted by quartile (darker = busier); Errors / Warnings / Total = the hour over all days, the Total row = the weekday over all hours.
  • Top messages — the most-repeated messages with numbers, IDs and quoted values normalized away; truncated to 160 characters before clustering so stack-trace variants group; Info records excluded.
  • Per component — records by level (Info/Warning/Error) for TM (transaction manager), PESITD and SSHD.

Rules

  • Every number is re-aggregated from per-day buckets under the date filter (the heatmap re-sums and re-tints; Reasons over time always shows the full period).
  • The levels per day with the error rate are the Top view.
  • Levels other than Info/Warning/Error (none expected) are counted in Records only.
  • Click a reason, week, hour, shape or component row for its 10 most recent lines (Warning/Error, newest first; the shapes table shows raw lines).
  • The same reasons per subscription: Failure reasons per flow.
