Errors per Day

What it shows

The server log’s own info/warning/error records (data/server/cache/_parse.tsv, not the transfer log) from every angle, one tab per table. Every number is a count of log records, not Files.

Sections

  • Errors per day — records per day by level (Info/Warning/Error) with the error rate.
  • Per component — the same split for TM (transaction manager), PESITD and SSHD.
  • Per hour — Error (red) and Warning (amber) by hour of day, all days combined; Load = the hour’s total relative to the busiest hour.
  • Per weekday — the same counts by day of week, Monday first.
  • Heatmap — hour × weekday, each cell the Error + Warning total, tinted by quartile (darker = busier). Cells are not clickable.
  • Reasons — one row per failure-reason bucket (connection, PESIT refusal codes, network, routing); each PESIT reason= code gets its own bucket; Example message = the first occurrence, truncated; unrecognized families land in “Other” so new problems surface rather than vanish.
  • Message shapes — the most-repeated messages with numbers, IDs and quoted values normalized away; truncated to 160 characters before clustering so stack-trace variants group; Info records excluded.

Rules

  • One pass over the parse cache counts each record by date and level, and by component and level; per-day buckets make every table re-aggregate under the date filter (the heatmap re-sums and re-tints).
  • Levels other than Info/Warning/Error (none expected) are counted in Records only.
  • Click a day, component, hour, weekday, reason or shape row for its 10 most recent lines (Warning/Error, newest first; the shapes table shows raw lines).
  • The same reasons per subscription: Failure reasons per flow.
