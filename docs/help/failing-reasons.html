Error reasons

What it shows

One row per Reason the Failed Subscriptions pages can show: how many currently red subscriptions carry it (Count) and the newest occurrence among them (Last) — the estate’s failure profile at a glance.

Rules

  • The row set is fixed: the shared classifier vocabulary (Connection failures, PeSIT transfer aborted, Wrong server fingerprint, …) parsed from bin/flip-reason.awk in classifier order (a new verdict appears on its own), plus One-legged, the raw last-leg status, and whatever a server-log row carries (a Subscriptions-in-boxes label).
  • A reason with nothing counted stays listed with blank Count and Last: a fault class disappearing is an emptied row, one appearing a new nonzero.
  • Red subscriptions only, one each: the source is the default Failed Subscriptions view (one row per failing subscription — its newest failed File or its server-log verdict), so Count sums to the red total the home page’s two red tables split.
  • Green (recovered) flows never count, whatever their history; volumes over time: Failure rate.
  • Unit buttons (each combination its own page): Subscriptions (default) counts each flow once, by its newest failure’s reason; Errors counts every failed File, so a busy flow counts as often as it failed.
  • Period buttons: Current (default) = the still-failing estate; History includes the recovered — on the Subscriptions unit its drill rows tint red (still failing) or green (recovered since).

Tips

  • A nonzero row opens the red subscriptions carrying that reason, each row as on the Failed Subscriptions pages (Subscription, Date/time) and opening the same error page: the file’s legs and server log, or the server-failing flow’s reddening session.
  • Errors drills show at most the newest 500 rows per reason and say so; the searchable All views of Failed Subscriptions hold every one.
