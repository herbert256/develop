Application dependencies

What it shows

  • Which external partners each internal application exchanges Files with, and how well each pair runs. Boxes: applications seen, dependency pairs, pairs at 100% Error.
  • Applications by external exposure — per application, most partners first: Partners, Files, Worst pair Error %, Pairs at 100% Error.
  • The dependency pairs — one row per application and partner, 50 per page: Files, Error %, Last seen.

Rules

  • Application and partner are parts 2 and 3 of the logical name domain_application_partner of the File’s subscription — a naming heuristic, good for exposure and failing pairs, not a configuration export.
  • A File counts for every application and every partner of its subscription; an application’s Files sum its pairs, so a File shared by two partners counts twice there.
  • Error % = Failed or Expired Files. Red = a pair at 100% Error (first table: an application with one) — usually a decommissioned counterparty still being tried.
