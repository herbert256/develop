Application dependencies

What it shows

Which external partner organisations each internal application exchanges Files with, and how well each pair runs. The intro names the most exposed application, its partner count and how many of its pairs run at 100% Error.

Sections

  • Per application — one row per application: partner count, Files, worst-pair Error % and the number of pairs at 100% Error.
  • Dependency matrix — one row per (application, partner) pair: Files, Error %, last seen.

Rules

  • Application and partner are parts 2 and 3 of the logical flow name (domain_application_partner) a File’s subscription resolves to through its FlowID — heuristic by design: good enough for exposure and failing pairs, not a configuration export.
  • Both sides use the site-wide union rules: a File counts for every application and every partner of its subscription.
  • Pair Error % = the Failed-or-Expired share of its Files (Waiting counts as OK, Expired as Error).
  • The per-application Files column sums its pairs, so a File shared by two partners counts twice there — exposure, not throughput.
  • Red row = 100% Error: the dependency exists in the logs but never works, usually a decommissioned counterparty still being retried.
