Application dependencies

What this shows

Which external partner organisations each internal application exchanges Files with, and how well each pair runs. The first table ranks applications by how many partners they depend on, with the worst pair Error % and the count of pairs running at 100% Error beside it; the second is the full (application, partner) dependency matrix with Files, Error % and last seen.

Applications derive from the logical flow names (the middle part of the domain_application_partner shape), so the attribution is heuristic by design — good enough to see exposure and dead dependencies, not a configuration export. A red pair exists in the logs but never works, usually a decommissioned counterparty still being retried.
