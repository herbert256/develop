Incoming Connection Details

What it shows

One page per sighted whitelisted IP address: an address from the partners’ AllowIP whitelists (patterns expanded) that was actually seen — as the source of real transfers, or in the server log. The ~3,000 whitelisted addresses never seen anywhere (whole ranges whitelisted “just in case”) get no page.

Sections

  • Summary — the raw incoming address, the configured endpoint name when that same address is in input/ip/ip-hosts.tsv (otherwise blank; no reverse-DNS lookup), its result, how many accounts whitelist it, and its totals: Files, Volume, first/last seen.
  • Activity per day and Latest 10 Files — addresses with real traffic only; the account and subscription cells link their detail pages.
  • Whitelisted by — every account whose whitelist allows this address, each linked to its account page.
  • Last 10 server log lines mentioning the address — closes the page of an address sighted only in the server log.

Rules

  • Traffic = every File whose remote host equals this address; the side-aware parse keeps an incoming connection’s raw source IP, so the address a partner connects from stays visible.
  • The whitelisting accounts come from the FlowManager configuration (the expanded AllowIP whitelist); the server-log lines are the ones the Missing whitelisted IPs server report collected.
  • Page background = the address’s result: light green = its last transfer was OK, light red = its last transfer failed, light blue = sighted in the server log only, never a transfer.
  • Coloured by its own transfers exclusively, never by the health of its partner’s flows: a healthy flow says nothing about which of its whitelisted addresses actually connect.

Tips

  • The index page lists every sighted address; the “Why blue” matrix on the Seen in server log page links its whitelisted-IP entries here.
