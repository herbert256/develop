Transfer Duration

What this shows

One selector, switched with the button row at the top — the scope: OK transfers (the default) counts only delivered (Processed) Files, so the statistics aren't skewed by failures; All transfers counts every File including failed ones — a failed transfer's duration is how long it ran before failing (a 2-hour timeout, say), so long-hanging failures show up there. Both per-day tables sit side by side on the page (until 2026-09-13 the min/avg/max table was a separate page behind a Percentage / Min/Avg/Max button pair). Within each scope, how long transfers take:

  • Duration per day — percentiles — p10, p25, p50 (median), p75, p90, p95, p98, p99 and p100 per day (the left table). A percentile says “this share of transfers finished at or below this duration”, so p95 = 95% of that day's transfers were at least this fast. Percentiles resist the single huge outlier that dominates the Max column — p100 is that outlier, the day's longest File (the same value as Max in the table beside it), shown beside p99 so the gap between the two says how far the worst case sits from the rest.
  • Duration per day — Min / Avg / Median / Max — the shortest, mean, middle and longest transfer duration for each calendar day (the right table).
  • The Top 50 longest Files and the Duration distribution moved to their own Performance pages, Longest Files and Duration distribution (2026-09-03).

Three tables that used to sit here have their own pages in this group: the Longest Files (the 50 slowest individual transfers), the Distribution & Store-and-forward histograms, and the Slowest subscriptions (the 25 flows with the highest p95).

How it's computed

The report counts Files (logical transfers — all records sharing one CoreId). On the OK transfers view it counts only those that were delivered (outcome Processed); Error transfers are excluded deliberately — most are instant 0-byte attempts that would flatten every statistic toward zero. The All transfers view drops that filter and counts every File with a measured duration, so failed/timed-out transfers are included (this is why a day's Max there can far exceed the OK view's — e.g. a transfer that hung for ~2h before failing).

A File's duration is the summed duration of its records, in milliseconds. Duration in the raw logs is compound and mixed-unit (e.g. 574 ms, 1.314 s, 1 min 0.550 s); it is normalised to milliseconds when the caches are built. The first two tables show these values in raw milliseconds, as requested; elsewhere durations are shown in readable units (s / min / h). Percentiles use the nearest-rank method.

The per-day min / avg / max and percentile columns are not additive: you cannot re-derive a minimum, an average or a percentile by summing the daily ones. So when you narrow the date-range filter, each day row still shows its own value but the total row blanks those columns (shown as “–”). The Files count is additive and re-totals normally. The distribution re-counts its buckets over the chosen date range; the slowest-subscriptions Median and p95 stay at their full-period value (Files and Max re-aggregate), the same convention the Performance report uses.

About this report

Duration of the 32105 Files over 68 day(s). Overall min 1.53 s, median (p50) 8.01 s, p95 37.95 s, p99 4.1 min, max 27.23 h. Only Processed Files count; Error transfers (mostly instant 0-byte attempts) are excluded so they do not flatten the statistics — switch to All transfers to include them. The two per-day tables sit side by side — the percentiles, then min / avg / median / max; the stats are shown in whole seconds, minutes or hours, and a narrowed date range keeps each day but blanks the non-additive totals.

One "File" = one logical transfer (all records sharing a CoreId); duration = its wall-clock span — from the first record start to the last record end, in milliseconds (so it includes the store-and-forward gap between the inbound and outbound legs, and the idle time between retries), NOT the sum of the record durations. Only Processed (OK) Files are counted here (use the All transfers button to include failures). Per-day min/median/max and percentiles are not additive: a narrowed date range keeps each day row but blanks the total. Percentiles use the nearest-rank method; p100 is the day's longest File — the Max of the other view — so the gap between p99 and p100 says how far the worst case sits from the rest.
