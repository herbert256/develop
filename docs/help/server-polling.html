UC2 pickup visits

Polling

What this shows

Every subscription that polls a partner in one row — the UC3 flows (and the pull side of UC5), where we are the client: SecureTransport connects to the partner’s server on a timer and collects whatever is waiting. The row joins three sides of that activity: the flow’s OK and Error transfers (the transfer log, as on the UC status / UC3 tab), the configuration (the Quartz cron expression from the FlowManager export and its plain-English Schedule) and the server log (what the schedule actually did). Every configured UC3 flow is listed, the never-seen ones included (their poll columns empty); a flow the log shows polling without a configured schedule still gets a row, its cron and transfer columns empty. The page is the bare table — no intro, no boxes.

This page replaces the former Remote polls server report and the Cronjobs analyses page; the same information sits on the UC status / UC3 tab as separate tables beside the status of every UC3 flow.

Reading the columns

OK and Error are the logical transfers of the flow in the transfer log — the figures of the UC3 tab. Its status, Files, Last file, Problems and Last log columns are not repeated here; the UC3 tab has them.

Cron expression is the Quartz form: sec min hour day-of-month month day-of-week (? = no specific value, 5/30 = every 30 from minute 5, MON-FRI = weekdays). Schedule spells it out.

Observed is when the schedule really fires, from the log: the median of the first poll of each day ± one standard deviation for a schedule firing up to 3× a day (the first and the last active day are left out: the export window cuts into both, so their first poll is the first poll after the cut, not the schedule firing), the poll rate (~23 polls/day) above that, and · files when no poll line exists and only the file arrivals of the flow give a slot. - means nothing was ever observed. A dark red Observed cell contradicts the schedule: the observed slot does not match the configured one (a daily schedule firing at another hour, an hourly one that polls once a day) — the export and the running server disagree, or the flow runs on another schedule than the one configured.

Polls counts every scheduled poll the log shows (the Applying the search pattern … N file(s) were found of which M matched lines); Empty polls those with nothing matching; Files matched the sum of M; Empty % the share. An empty poll consumes a slot, a connection and a directory listing but leaves no trace in the transfer log — chronic empty polling is visible only here. Listing errors counts the polls that could not even list the remote folder (Error occurred while listing files from partner …) — a wrong remote directory, a permission problem or a partner that dropped the connection mid-listing.

Poll starts, Failure lines and What goes wrong are filled for a schedule that fires but never completes a poll: the setup lines that opened the poll (Remote files pattern … evaluated), the connection and authentication failures naming the flow or its host, and the dominant reason (the host and port, the account, the error).

Filtering and drilling

The From/To bar re-totals the poll figures for a date range (Polls, Empty polls, Files matched, Empty %, Listing errors); the configuration columns and the Observed slot are for the whole period. Click a row for the 10 most recent poll lines of that subscription (on a flow without poll lines, the server-log lines that decided its status). Rows are tinted by the result of the subscription, as everywhere on this site. The Subscription cell links to the detail page of the flow.

How it's computed

The OK and Error columns are copied from the UC3 status table (uc3-status.rpt), so they can never disagree with the UC3 tab. The poll and listing figures come from the same per-subscription aggregation that feeds the UC3 tab (the unpublished remote-poll intermediate and its poll-times and poll-failures sidecars); the cron side reads subscriptions.json and the file-arrival fallback reads the Punctuality report. Subscription names are the configured ones — the logged _SCP_ / _SFTP_SERVER_ tails are dropped — and where the server truncated a long site name the two sides match by name prefix, either way, as long as the match is unique. All schedules are enabled; none skip holidays.
