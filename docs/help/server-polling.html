Polling

What it shows

One row per polling subscription (UC3 and the pull side of UC5: SecureTransport is the client and collects from the partner’s server on a timer) — its Files, its configured cron schedule and what the server log observed.

A bare table, no intro or boxes; the same tables sit on the UC status / UC3 tab.

Columns

  • Subscription — configured name, links to its detail page; row tinted by its result.
  • OK / Error — the flow’s Files in the transfer log, copied from uc3-status.rpt so they never disagree with the UC3 tab (which keeps Status, Files, Last file, Problems, Last log).
  • Cron expression — Quartz sec min hour day-of-month month day-of-week (? no specific value, 5/30 every 30 from minute 5, MON-FRI weekdays); Schedule spells it out.
  • Observed — when the schedule really fires (rules below).
  • Polls / Empty polls / Files matched / Empty % — the “Applying the search pattern … N file(s) were found of which M matched” lines; empty = M is 0; matched = sum of M.
  • Listing errors — “Error occurred while listing files from partner …”: wrong remote directory, permissions, or a partner dropping the connection mid-listing.
  • Poll starts / Failure lines / What goes wrong — filled for a schedule that fires but never completes a poll: the “Remote files pattern … evaluated” setup lines, the connection and authentication failures naming the flow or its host, and the dominant reason (host and port, account, error).

Rules

  • Every configured UC3 flow is listed, never-seen ones with empty poll columns; a flow polling without a configured schedule gets a row with empty cron and transfer columns.
  • Observed = the median of each day’s first poll ± one standard deviation (first and last active day left out — the export window cuts into both); a poll rate (~23 polls/day) for a schedule firing more than 3× a day.
  • · files = no poll line, only the file arrivals (the Punctuality report) give a slot; - = nothing ever observed.
  • Dark red Observed contradicts the schedule (a daily one firing at another hour, an hourly one polling once a day): the export and the running server disagree, or the flow runs on another schedule.
  • An empty poll costs a slot, a connection and a listing but leaves no trace in the transfer log — chronic empty polling shows only here.
  • From/To re-totals the poll figures; the cron columns and Observed are whole-period.
  • Names are the configured ones (logged _SCP_ / _SFTP_SERVER_ tails dropped); a server-truncated name matches by unique prefix, either way.
  • Cron from subscriptions.json; polls from the per-subscription aggregation that feeds the UC3 tab. All schedules enabled, none skip holidays. UC1 is a client use case too but pushes on directory scanning — no cron.

Tips

  • Click a row: its 10 most recent poll lines (on a flow without poll lines, the server-log lines that decided its status).
