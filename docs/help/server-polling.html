Polling

What it shows

  • One row per UC3 polling subscription: its configured schedule and what the server log observed. The UC status › UC3 tab holds the same facts as separate tables.

Columns

  • Subscription — the configured name; the row carries its result colour.
  • Active — Yes, or why not (hover for the words): 1 Undeployed, 2 SAVED_NOT_DEPLOYED, 3 receive schedule No, 4 folder monitoring Inactive; CFT for a SWIFT name.
  • Cron expression (Quartz, raw) · Schedule (plain English) · Observed (Rules); Schedule no cron = nothing makes it poll (the Missing cron box of Subscriptions in boxes).
  • Polls / Empty polls / Files matched / Empty % — from “Applying the search pattern … N file(s) were found of which M matched”; empty = M is 0.
  • Listing errors — the remote folder could not be listed (path, permissions, a dropped connection).
  • Poll starts / Failure lines / What goes wrong — filled for a schedule that never completes a poll: its setup lines, its connection and authentication failures, and the dominant reason.

Rules

  • Rows: every configured UC3 flow plus any UC3-named flow the log shows polling. A server-truncated name matches by unique prefix.
  • Observed: the median of each day’s first poll ± one standard deviation, or the poll rate above 3 a day; · files = only file arrivals give a slot; - = never observed; dark red = contradicts the schedule.
  • From/To re-totals Polls through Listing errors; the other columns are full-period.

Tips

  • An empty poll costs a slot, a connection and a listing but leaves no transfer record — chronic empty polling shows only here.
