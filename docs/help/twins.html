Twins

What it shows

  • Every twin pair the detail pages’ Twin rows know, each pair once. Configuration only.
  • Boxes: Subscription twin pairs · Name-matched · Shared login/account · Twin account, then the pairs per use-case combination (e.g. UC1 + UC3, UC4 + UC2); a box filters the rows.

Columns

  • Subscription twins — Subscription · Twin · Direction of each side (connection/movement) · Login · Detected by.
  • Account twins (separator spellings) — Account · Twin · Login: one partner relation configured under both the - and the _ spelling.

Rules

  • A subscription twin is the same flow configured the opposite way. Detected by (unioned): Name — same name body, opposite side; shared login/account — a UC2 + UC4 pair on one FE login, or an account’s single UC1 + UC3; spelling-twin accounts.
  • Shared login/account only — naming slip: the flows belong together but their names disagree — the rename backlog, listed first.
  • Login — the FE login the pair connects with (both when they differ); - for outbound flows, whose credential sits in the communication profile.

Tips

  • Renaming one side of an account twin merges the pair; Config hygiene lists the same twins.
