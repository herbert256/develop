Accounts in boxes

What it shows

Every FlowManager account, one row each, boxed by its connected subscriptions: the twenty boxes of Subscriptions in boxes (an account is in a box when at least one subscription is) plus No subscriptions, which exists only here.

Rules

  • Memberships come straight from the Subscriptions in boxes code path, joined onto accounts; nothing is computed here.
  • The join is the configuration cache xref/_subscriptions-accounts.tsv, never the name: UC1_<account>_<account> is only a convention, and separator twins (FRE-SAPCD-X, FRE_SAPCD_X: two accounts) would merge on a loose match.
  • Boxes are neither exclusive nor a verdict, except OK: every connected subscription green; one failing flow beside a delivering one = Error.
  • Row tint (green / orange / red / blue) = that site-wide account result.
  • No subscriptions = no row in the cache: nothing references it, nothing can route through it — configured, inert. It keeps the Total meaning “every account is in a box”. Same condition: the account page’s amber banner and “Account without subscriptions” on Config hygiene.
  • Sources: eight boxes read a report’s data file (From green to red, Trouble after success, Only red, No Dir, No Files, Missing cron, Went quiet, Connection failures); Deploy the Deploy errors report; One-legged, Waiting, Expired the transfer cache; OK, Not seen, Server log only the Entities sources.
  • Connection failures and Deploy are unresolved-only: a later OK File = recovered, not boxed.

Tips

  • Opens on OK. Click a box to narrow; empty columns hide; the note under the boxes explains the pick. Orange boxes (attention, not working yet) precede red (failing).
  • A flagged cell opens the subscription report behind it, searched for just the subscriptions that boxed this account; deliberately no account version exists.
  • Only red + Connection failures/Deploy = never worked, the server log says why. OK + Went quiet = delivered, then nothing. No subscriptions alone = cleanup, not an incident.
