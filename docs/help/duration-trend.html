What this shows

The delivered Files are split at the midpoint of the observed window; every subscription with 15+ delivered Files in each half gets a median duration per half and the ratio between them. Flows at 1.3× or above are listed as slower, 0.7× or below as faster.

The average file size per half sits beside the medians: a slowdown whose size also grew is load growth, not degradation — the interesting row is a slowdown at unchanged size. Only delivered Files count; a failed transfer's run time is a timeout artefact, not a trend.

About this report

The 32014 delivered (OK) Files with a measured duration, window 2026-06-23 → 2026-08-29, split at 2026-07-26. Per subscription with 15+ delivered Files in each half: the median duration per half and the ratio between them. 0 of the 102 comparable flows moved: 0 got slower (ratio ≥ 1.3×) and 0 got faster (ratio ≤ 0.7×). The average file size per half sits beside the medians — when the size grew with the duration, the flow is not degrading, the files are just bigger.

Biggest slowdown first. Read the size columns before alarming: a ratio of 2× with the average size also doubling is load growth, not degradation — a slowdown at UNCHANGED size is the interesting row.

Biggest speed-up first — usually good news (a fixed route, smaller files, an off-peak reschedule), but a sudden drop can also mean the flow now ships stubs instead of real content: check the size columns and the Size profile report.

Only delivered (Processed) Files count — a failed transfer's run time is a timeout artefact, not a trend. Duration is the File's wall-clock span (first record start to last record end, store-and-forward gap included). Medians use the nearest-rank method over each half; flows without 15 Files in both halves are not compared.
