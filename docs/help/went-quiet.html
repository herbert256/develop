Went quiet

What it shows

The silence report, both units: subscriptions that carried Files and then stopped (nothing in the last 7 days of the window, whatever the outcome), and accounts idle long against their own cadence.

Subscriptions table

  • Subscription — configured name, links its detail page.
  • Days ago last traffic — days from last File to window end; 8 = stopped right after the threshold, large = silent most of the window.
  • Quiet = most recent File more than 7 days before the last day in the data. Newest-quiet first: 8 days is a live question, 31 days probably an unrecorded decommissioning.
  • Every outcome counts as traffic (Processed, Failed, Waiting, Expired): the question is “is anything happening”, not “is it working”. A daily failer is noisy, not quiet; a green subscription (last File delivered, however long ago) can be listed.
  • Health is judged on Only red, From green to red and the UCx status verdicts.
  • Never carried a File = cannot go quiet, not listed; the Entities Not seen view has those.
  • One pass over _files.tsv: per subscription the last day with a File, against the last day in the data. Flat threshold: “what stopped?” is one list, not a ranking.

Accounts table

  • Days idle — against the most recent File across every account; tinted at 7+.
  • Median gap — typical spacing between the account’s active days (its cadence).
  • Idle ÷ gap — a daily account idle 3 days = 3.0 (three missed cycles), more alarming than a weekly one idle 5 days = 0.7; tinted at 2 or more. Single-day accounts have no gap: “-”, sorts last.
  • Files without account attribution (platform-internal, blanked at parse) are excluded. Always the full period: narrowing From/To would hide exactly the stalest accounts.

Rules

  • Both units measure from the window end, never today, so figures do not drift with the export’s age.
  • Nothing fails when a flow stops: partner stopped sending, source stopped producing, or decommissioned without cleanup — only the third is harmless.
