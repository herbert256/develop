One-legged

What it shows

  • Files (CoreIds) with only one leg — a single row in the transfer log. A complete transfer is store-and-forward: an Inbound leg (partner → ST) and an Outbound leg (ST → partner), commonly 2–7 rows with retries.
  • A single leg is one-sided: the file arrived and was never forwarded, or a send had no matching arrival. It never made the full crossing.

Tabs

  • Details — one row per subscription (links its detail page): One-legged Files (opens its 10 newest), First date, Last date; most first. From/To re-counts One-legged Files for the range (a subscription with none in it hides; First / Last date and the drill stay full-period); the Unknown subscription is left out (see Unknown transfers).
  • Per day — per day: One-legged Files (red: a lone leg is always an Error File), Unknown included.

Rules

  • Details: rows tint by the subscription’s result colour.
  • The two tabs are the second button row, under the Errors group row.
  • Every count is one File (one CoreId).

Tips

  • A day page’s transfer-log problems link the Per day tab for that day.
  • The 1-leg bucket of File journey is this same population; Failed Subscriptions gives such a File the reason One-legged when its log names no other cause.
