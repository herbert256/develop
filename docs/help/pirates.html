One-Legged Transfers

What this shows

Logical transfers (CoreIds) that have only one leg — a single technical row in the transfer log. Two views, switched with the buttons at the top right: Details — one row per single-leg transfer, showing that one leg's Direction (Inbound or Outbound), the transfer's outcome, and its account, subscription, partner, size and file (Account, Subscription and Partner link to their detail pages; newest first); and Top view — the count of single-leg transfers per day, split Error / OK. The From/To date filter narrows both.

Why "one leg" matters

A completed transfer is normally store-and-forward: the partner sends the file in (an Inbound leg) and Secure­Transport forwards it back out (an Outbound leg), so one logical transfer is commonly 2–7 rows (the two legs plus any retries). A single-leg CoreId is one-sided — only the Inbound leg (the file arrived but was never forwarded) or only the Outbound leg (a send with no matching arrival) was ever logged. The counterpart leg never happened, so the file never made the full crossing; these do not complete and end up Error. The Direction column tells you which half exists — the missing half is the other direction.

How it's computed

Leg count comes from the logical-transfer cache (_files.tsv, one row per CoreId, its rows column = the number of technical legs); a value of exactly 1 selects the pirates. The single leg's Direction is read from the parse cache (_transfers.tsv), and the account / subscription / partner / size / file from the same per-CoreId row. Every count here is one logical transfer (one CoreId), full period. Days on which a single-leg transfer occurred are also surfaced in the combined day page's Problems this day list.

About this report

Pirates — logical transfers (CoreIds) that have only one leg (one technical row). A complete transfer is store-and-forward: an Inbound leg (partner → ST) and an Outbound leg (ST → partner). A single-leg CoreId is one-sided — the counterpart leg never happened — so the file never made the full crossing. Details counts them per subscription; Top view the count per day.

One row per subscription: how many of its transfers were single-leg, and the first and last date one occurred. Single-leg transfers do not complete the store-and-forward, so they end up Error. The Subscription links to its detail page.
