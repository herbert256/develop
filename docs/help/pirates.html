One-Legged Transfers

What it shows

Pirates: logical transfers (CoreIds) with only one leg — a single technical row in the transfer log. Details counts them per subscription, Top view per day split Error / OK; the buttons at the top right switch, the From/To filter narrows both.

Columns

  • Details — one row per subscription (linking its detail page): how many of its transfers were single-leg, and the first and last date one occurred.
  • Top view — the count of single-leg transfers per day, Error / OK.

Rules

  • A complete transfer is store-and-forward: an Inbound leg (partner → ST) and an Outbound leg (ST → partner), so one logical transfer is commonly 2–7 rows (the two legs plus retries).
  • A single-leg CoreId is one-sided: only the Inbound leg (the file arrived, was never forwarded) or only the Outbound leg (a send with no matching arrival). The counterpart never happened, the file never made the full crossing, so these end up Error.
  • The leg count comes from the logical-transfer cache _files.tsv (one row per CoreId; its rows column = the technical legs); exactly 1 selects the pirates. The leg’s direction is read from the parse cache _transfers.tsv; account, subscription, partner, size and file from the same per-CoreId row.
  • Every count is one logical transfer (one CoreId), full period.

Tips

  • Days with a single-leg transfer also appear in the combined day page’s Problems this day list.
  • The 1-leg bucket of File journey is this same population.
