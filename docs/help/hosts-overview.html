Partners - Outgoing

What it shows

The opposite of Partners - Incoming: one row per remote host (the partner’s server we connect to) for UC1 (we deliver) and UC3 (we collect), with its use cases, contact stamps and Files. Full-period; no date filter.

Columns

  • Host — links its detail page.
  • Use cases — of its subscriptions: UC1 (we push), UC3 (we pull), UC1/UC3 (both).
  • Cloud — the newest successful transfer leg with the host here; empty when none.
  • Gateway — the host’s stamp on the old gateway, from input/hosts_old.txt.
  • Files (group) — In / Out: Files collected from / delivered to the host, by movement direction; Error: the Files that failed.
  • Auto retries — OK Files with a failed leg and no resubmit: the platform’s own retry delivered them.
  • Resubmit OK / Resubmit Error — the Files an operator resubmitted, by final outcome.

Rules

  • Tints: green delivering, red failing, orange configured, never seen; an old-gateway-only host (not configured here) is untinted. A 0 renders empty.
  • Roster = the FlowManager export’s host list; a subscription’s use case = its UC<n> name prefix, else the derived one.
  • Files: the transfer caches, the Entities host rule — a File counts for every host its legs name when we made the connection. Polls and connection failures: the Polling and Connection failures pages.
  • input/hosts_old.txt: hand-maintained like logons_old.txt, one host per line: the host, then its stamp as written (sftp.partner.example  2026-09-02 14:35); blank and # lines ignored; no file = empty column.
