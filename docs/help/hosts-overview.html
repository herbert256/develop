Partners - Outgoing

What it shows

The opposite of Partners - Incoming: one row per remote host (the partner’s server we connect to) for UC1 (we deliver) and UC3 (we collect): every configured host with its use cases, contact stamps, Files and polls. Full-period; no date filter.

Columns

  • Host — links its detail page.
  • Use cases — of its subscriptions: UC1 (we push to the partner), UC3 (we pull from the partner), UC1/UC3 (both).
  • Cloud — the newest successful transfer leg with the host on this platform: the last time we reached the partner; empty when the log window holds none.
  • Gateway — the host’s stamp on the old gateway, from input/hosts_old.txt.
  • Files in / Files out — Files collected from / delivered to the host, by movement direction, whole transfer window.
  • Error — Files that failed, delivered or collected.
  • Delivered — the out-side Files that completed. Delivered + the failed deliveries = Files out.
  • Auto retries — OK Files with a failed leg and no resubmit: the platform’s own retry delivered them.
  • Resubmit OK / Resubmit Error — the Files an operator resubmitted, by final outcome.
  • Last error — when the newest failed File started.
  • Polls / Poll pattern — the server-log polls of the host’s UC3 subscriptions summed (the Polling page), the pattern = the observed cadence of the busiest one; empty for a host we only deliver to.
  • Connection problems — the server-log connection failures of the host’s subscriptions summed (Connection failures); empty when none. Click it for that page with the busiest subscription’s row marked.

Rules

  • Tints: green delivering, red failing, orange configured, never seen; a host only the old-gateway file names (not configured here) is untinted — a partner not yet moved over. A 0 renders empty.
  • Roster = the FlowManager export’s host list; a subscription’s use case = its UC<n> name prefix, else the use case derived from its configuration.
  • Files: the transfer caches, the Entities host rule — a File counts for every host its legs name when we made the connection (the connection side is out).
  • Cloud and Last error: the transfer legs and Files caches (one File per CoreId). Polls and Connection problems: the server-log reports, joined through the host’s subscriptions.
  • input/hosts_old.txt: hand-maintained like logons_old.txt, one host per line — the host, then its stamp (sftp.partner.example  2026-09-02 14:35). First token (up to spaces, TAB, comma or semicolon) = the host, case-insensitive; the rest shown as written; blank and # lines ignored; a missing file leaves the column empty.
