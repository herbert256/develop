UC2 pickup visits

What this shows

For every UC2 flow (the partner connects in and collects files from us) whose pickup account ever logged on: what the partner’s SSH visits actually did. A visit is a group of logons — an SFTP client typically opens several connections per sitting; a gap of more than 30 minutes starts a new visit. Each visit is classified by what its window shows in the transfer log:

Collected — took at least one staged file (and delivered none). Collected + delivered — a two-way exchange: the partner dropped its own files (its UC4 twin flow) and took ours in one visit. Delivered only — the visit only handed files over; that is a UC4 delivery, not a pickup, and such visits are excluded from every pickup figure on this site.

Same connection is the hard evidence beside those time windows: the number of distinct technical SSH connections (the transfer log’s Session ID — one connection, one id) in which the account both delivered and collected a file. The visit classes group logons by time, and an SFTP client typically opens a fresh connection per operation — so a two-way exchange visit can still show 0 here when its uploads and downloads travelled in separate connections. Only this session-proven figure raises the Connection shared with UC4 drop row on the detail pages and the UC4 drop flag on the Pickups report.

Reading the table

Pickups counts the account’s pickup logons — the same figure the detail page’s Pickup information table shows as Total pickups — so it runs higher than the visit columns (a visit typically holds several logons). The pickup and visit columns are the account’s — the SSH logon lines carry only the account, so an account serving several UC2 subscriptions repeats its figures on each of them. Files picked up is per subscription and matches the OK figure of its detail page, which carries the flow’s own Pickup information table (first/last pickup, pattern, delivering logons).

A partner collecting over CFT/PESIT logs no SSH visit at all — such flows are absent here even while their files are collected fine. Flows whose account never logged on at all are not listed.

How it's computed

The figures come from the same per-visit classification that feeds the UC2 status report and the detail pages’ Pickup information tables (the uc2-pickups sidecar), so the three can never disagree. Logon evidence is the server log’s successful-SSH-logon lines; deliveries are the account’s inbound SSH transfer records; collections are each staged File’s final successful outbound (download) record. The Same connection column pairs those two transfer-log sides by their Session ID: a session counts once when it carries at least one delivery and at least one successful collection of the account’s files.
