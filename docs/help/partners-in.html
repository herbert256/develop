Partners in

What it shows

  • One row per login a partner connects in with: its use cases, its Files in and out, the pickup state, its logons and the SSH screening funnel. Full period; no date filter. Laid out like Partners Out.
  • Views — Endpoint (a row per login), Accounts and Partners: the same table per account / partner, over the logins the configuration pairs it with. A login serving two accounts counts for both, so the rows can add up to more than the Total, which counts every login once; a login no account / partner is configured for is left out. Per entity: counts summed, Cloud / Gateway the newest, Pattern the busiest login’s.

Columns

  • Login — links its detail page. Use cases — UC2 (the partner picks up), UC4 (the partner delivers) or both.
  • Files In / Files Out — Count: the login’s Files by movement; Errors: those that failed (Expired has its own column).
  • Pickup — the out-side Files: Retrieved (collected), Waiting, Expired.
  • Logons — successful logons, any protocol; Cloud the newest one here, Gateway the last one on the old gateway (input/logons_old.txt), Pattern their rhythm.
  • Screening, in log lines: Allowed / Disallowed (whitelist), Authenticated, Bad key, Locked, Auth failed (the anonymous “Authentication failed using local.”, booked to the login whose Allowed precedes it).

Rules

  • Rows: every configured login, every login only the old-gateway file names, then logins only the funnel knows (untinted).
  • Row tint = the login’s result colour; red cells keep their red. A 0 renders empty. Sorted by Waiting.

Tips

  • Click a Screening count for its 5 newest log lines. Outbound logons: Partners Out.
