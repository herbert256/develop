Partners - Incoming

What it shows

One row per FE login (the credential a partner connects with), combining the FE overview (use cases, logons, Files, pickups) with the Incoming logon funnel (the SSH screening counts). Every figure is the source page’s own. Full-period; no date filter.

Columns

  • Login — links its detail page.
  • Use cases — UC2 (the partner picks up from us), UC4 (the partner delivers to us), UC2/UC4 (the mailbox pair).
  • Cloud / Gateway — the newest successful authentication on this platform / the last logon on the old gateway (input/logons_old.txt).
  • Files in / Files out / Error / Retrieved / Waiting / Expired / Oldest waiting — the FE overview’s File figures: delivered to us / staged for pickup / failed / collected / staged, not collected yet / deleted unclaimed / the age of the oldest staged file.
  • Pickups — the pickup logons (an SFTP client opens several connections per visit).
  • Allowed / Disallowed / Authenticated / Locked — the SSH screening funnel per login, as on the Incoming logons page; click a count for its 5 newest log lines.
  • Auth Failed — the funnel’s Bad key + Key failures + Auth failed in one count; its drill holds the 5 newest lines of the three.
  • Pattern — the logon cadence (successful authentications over any protocol).

Rules

  • Rows = every FE overview login (configured, or named only by the old-gateway file), then the logins the funnel alone knows — empty transfer cells, no tint.
  • Tint = the login’s result: green delivering, red failing, orange configured, never seen. The funnel’s own screening colour is not carried; its red cells are. A 0 renders empty.
  • Not carried: the FE overview’s Pickup pattern and Logon problems, the funnel’s No account, Session errors, Re-screens, First logon, Logons and Last logon (= Cloud).
  • Definitions and sources: FE overview and Logon.
