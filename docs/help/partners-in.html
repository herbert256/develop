Partners in

What it shows

  • One row per login a partner connects in with: use cases, Files in and out, logons and the SSH screening funnel. Full period; no date filter. Laid out like Partners Out.
  • Views — Endpoint (per login), Accounts, Partners: the same table per entity the configuration pairs the logins with. A login of two accounts counts for both, so rows can exceed the Total, which counts each login once; an unpaired login is left out.

Columns

  • Login links its detail page. Use cases: UC2 (the partner picks up), UC4 (it delivers) or both.
  • Files In / Files Out — Count by movement, Errors the failed ones; Files Out adds Retrieved, Waiting and Expired.
  • Logons — successful logons; Cloud the newest here, Gateway the last on the old gateway (input/logons_old.txt), Pattern their rhythm.
  • Screening, in log lines: Allowed / Disallowed (whitelist), Authenticated, Bad key, Locked, Auth failed (the anonymous “Authentication failed using local.”, booked to the login screened just before).

Rules

  • Rows: every configured login, then logins only the old-gateway file or the funnel knows (untinted).
  • Row tint = the login’s result colour; red cells keep their red. A 0 is empty. Sorted by Waiting.

Tips

  • Click a Screening count for its 5 newest log lines.
