Sizes & types

What it shows

  • The files themselves: sizes, types, repeated names, the largest Files, and flows whose typical size changed or that ship stubs.

Tabs

  • By size — Size range / Files / Error / OK / Volume / % of Files / Distribution: nine buckets from 0 B to >= 1 GB; the bar is relative to the fullest bucket.
  • Empty files — Subscription / Empty OK Files / First / Last: zero-byte Files delivered OK.
  • By type — File type / Transfers / Error / OK / Volume / % of transfers, per extension; counts legs, so a file appears on its Inbound and Outbound leg.
  • Duplicates — Filename / Files / Error / Accounts / First / Last: names transferred more than once, whatever the outcome (Error counts the failed ones); Accounts = distinct senders (full period).
  • Largest files — the 50 largest Files: Size / Throughput (size ÷ the File’s wall-clock span) / Start Time / Account / Destination Subscription / Outcome / File. Rows in the File colour.
  • Size regime — flows with 20+ Files whose median size changed 3×+ between the first and second half of their own Files (split by count); ∞ = a first-half median of 0 bytes.
  • Stub shippers — flows with 10%+ stubs, files smaller than the Stub limit = max(1 KB, 1% of the flow’s median).

Rules

  • All tabs but By type count Files; Error = Failed or Expired.
  • The 0 B bucket holds every empty File, failed or not; only the OK ones reach Empty files.

Tips

  • Duplicates with Error below Files usually mean a failed transfer was re-sent successfully.
  • A data file plus a 0-byte semaphore gives a steady ~50% stub share by design; a sudden surge is the interesting row.
