Sizes & types

What it shows

  • The files themselves: sizes, types, repeated names, the largest Files, and flows whose typical size changed or that ship stubs.

Tabs

  • By size — Files / Error / OK / Volume / % of Files / Distribution in nine buckets, 0 B to >= 1 GB.
  • Empty files — per subscription, the zero-byte Files delivered OK, First / Last.
  • By type — per extension: Transfers / Error / OK / Volume / % of transfers; counts legs.
  • Duplicates — names transferred more than once, any outcome: Files / Error / Accounts (distinct senders) / First / Last; full period.
  • Largest files — the 50 largest Files: Size / Throughput (size ÷ wall-clock span) / Start Time / Account / Destination Subscription / Outcome / File, in the File colour.
  • Size regime — flows with 20+ Files whose median size changed 3×+ between the first and second half of their Files; ∞ = a first-half median of 0 B.
  • Stub shippers — flows with 10%+ stubs, files smaller than the Stub limit = max(1 KB, 1% of the flow’s median).

Rules

  • All tabs but By type count Files; Error = Failed or Expired.
  • The 0 B bucket holds every empty File, failed or not; only the OK ones reach Empty files.

Tips

  • Duplicates with Error below Files usually mean a failed transfer was re-sent successfully.
  • A data file plus a 0-byte semaphore gives a steady ~50% stub share by design; a sudden surge is the interesting row.
