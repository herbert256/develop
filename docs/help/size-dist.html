Transfer Size Distribution

What this shows

Files bucketed by file size, from 0 B up to >= 1 GB, with each bucket's Error/OK split, volume, share of all Files, and a relative-count distribution bar. This report counts logical transfers (Files, from _files.tsv) — one row per bucket, not per physical log row.

How it's computed

Each File's file size places it in exactly one of nine buckets (0 B; 1 B–1 KB; 1 KB–10 KB; 10 KB–100 KB; 100 KB–1 MB; 1 MB–10 MB; 10 MB–100 MB; 100 MB–1 GB; >= 1 GB). The distribution bar's width is relative to the bucket with the most Files, so it highlights where the bulk of activity sits rather than plotting to an absolute scale.

The 0 B bucket is dominated by failed Files: a transfer that never actually delivered a file often has no size recorded, so a large 0 B bucket usually reflects failed attempts rather than genuine empty-file transfers.

Empty files delivered OK

The second table isolates the interesting minority of that 0 B bucket: zero-byte Files whose delivery ended OK, per subscription. The transfer worked but the file was empty — which usually means the upstream export produced nothing. A flow that legitimately ships empty marker files recurs here steadily; a subscription that suddenly appears (or whose count jumps) deserves a look at what its source stopped producing.
