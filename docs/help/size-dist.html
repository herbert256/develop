Transfer Size Distribution

What it shows

The files themselves: Files bucketed by size (one row per bucket, from 0 B to >= 1 GB), the empty files delivered OK, the split per file type, and the filenames delivered more than once.

Sections

  • Size distribution — nine buckets: 0 B; 1 B–1 KB; 1 KB–10 KB; 10 KB–100 KB; 100 KB–1 MB; 1 MB–10 MB; 10 MB–100 MB; 100 MB–1 GB; >= 1 GB. Counts Files (_files.tsv), not log rows.
  • Per bucket: the Error/OK split, volume, share of all Files, and a distribution bar whose width is relative to the fullest bucket.
  • Empty files delivered OK — zero-byte Files whose delivery ended OK, per subscription: the transfer worked, the upstream export produced nothing. A flow that legitimately ships empty markers recurs steadily; a subscription that suddenly appears (or whose count jumps) deserves a look.
  • Per file type — the split per extension. Counts transfers (legs), not Files — a file appears on both its Inbound and Outbound leg.
  • Duplicate deliveries — one row per business filename delivered more than once, worst first (replay loops, re-sends): Files = logical transfers carrying that exact name, Error = how many failed, Accounts = distinct senders (full-period, not date-adjusted). Error below Files usually means a failed transfer was re-sent successfully.

Rules

  • The 0 B bucket is dominated by failed Files: a transfer that never delivered often has no size recorded. The failed 0-byte attempts stay in that bucket; only the OK ones move to the empty-files table.
  • Files and Error of the duplicates table re-aggregate over the selected dates.

Tips

  • Click an Error or OK count for that outcome’s 10 most recent Files (per file type: transfers), newest first; click an empty-files or duplicates row for its 10 most recent Files.
