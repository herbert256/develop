Anomalies

What it shows

Hours and days unlike their usual selves: Daily (one row per flagged calendar day), then Hourly (one row per episode of consecutive flagged hours, paged).

Columns

  • Date — opens the day page in the matching hero-chart view.
  • Value (Daily) / Peak (Hourly: the episode’s worst hour) — the flagged figure.
  • Typical — the baseline: the median, lifted to the rule’s floor when below it (shown “1 m (floor; typical 25.3 s)”); Value ÷ Typical = × typical.
  • × typical — the figure vs its baseline; an episode shows its worst hour’s three figures.

Rules

  • Typical = the median over the window’s days for that hour of day (or day); weekdays and weekends baselined separately; hours bucket by File start time.
  • Hourly, each ≥4× typical plus a floor: Error rate ≥25%, ≥5 Files; Duration avg per OK File ≥5 min, ≥5 OK Files (failures excluded, as on Performance); Files spike ≥30; Silence 0 Files where ≥20 are typical; Volume ≥100 MB.
  • Daily: Error rate ≥10%, ≥20 Files, ≥4×; Duration ≥5 min avg per OK File, ≥20 OK Files, ≥4×; Files spike ≥100, ≥2×; Files drop ≤¼ of a ≥100-Files typical; Silence no transfers where ≥20 are typical (missing days walked via the calendar); Volume ≥200 MB, ≥2×.
  • Consecutive flagged hours merge into one episode, bridging a single calm hour.
  • Red = ≥10× typical or a silence; orange the rest.
  • A day page lists Anomaly scan among its transfer problems only when it has findings (with the count); it opens this page narrowed to the day; Reset widens.
  • Newest day: outbound legs may not be exported yet, flagging late hours or the whole day as Error rate — recheck after the next export.
  • A Duration episode often pairs with a later Files/Volume spike (queue, then flush): one event. An empty report = nothing beat 4× its routine.
