Failed Subscriptions

What it shows

  • One row per failing subscription: its newest File in error (Failed or Expired), or a server row when only the server log reddens it — together every red subscription.
  • Views: Still failing (default) hides the subscriptions green again; All keeps them.
  • Also the help of the File pages (File: <name>, any outcome) and the subscription error pages (Failed subscription: <subscription> - <reason>). Only the newest OK File and the three newest Error Files of a subscription have a page.

Columns

  • Subscription; Date/time — the File’s start, or the reddening error’s time.
  • Reason — the first classifying server-log error (Connection failures, Route stopped…), One-legged, Expired (not collected), else the last leg’s raw status.
  • CoreId / SessionId — the File’s CoreId, or the session of the reddening error.
  • Last green day (never = never delivered), Days red, Failures in a row — blank on server rows.

Rules

  • Row tint = the subscription’s colour; a row opens its error page (an Expired File has none).
  • A server row: a server error after the last delivery, a deploy mistake, or an attributed authentication failure.
  • A File page: the facts (File name, CoreId, Date/time, Reason for an Error File, Subscription, Partner, Account, Login, Remote host), the legs in order, then the server log of their sessions and every line naming the CoreId or a transfer ID.
  • A subscription error page: facts, Last server error, the reddening connection’s log.

Tips

  • Every File in error: Failed files; back to green: Recovered flows.
