Failed Subscriptions

What it shows

  • One row per failing subscription: its newest File in error (Failed or Expired), or a server row when only the server log reddens it — together every red subscription.
  • Views: Still failing (default, first) hides the subscriptions green again; All keeps them.
  • Also the help of the File pages (File: <name>, any outcome) and the error pages (Failed subscription: <subscription> - <reason>). Only the published Files (per subscription the newest OK File and the three newest Error Files) have a page.

Columns

  • Subscription; Date/time — the File’s start; a server row: the reddening error’s time.
  • Reason — the File’s first classifying server-log error (Connection failures, Route stopped…), One-legged, Expired (not collected), else the last leg’s raw status.
  • CoreId / SessionId — the File’s CoreId; a server row: the session of the reddening error.
  • Last green day (never = never delivered), Days red (the current run’s first failure to the window end), Failures in a row — blank on server rows.

Rules

  • Row tint = the subscription’s colour (see Generic help); a row opens its error page — a row whose newest Error File is Expired opens nothing (an Expired File has no page).
  • A server row: a server error after the last delivery, a deploy mistake, or an attributed authentication failure.
  • File and error pages: the facts (File name, CoreId, Date/time, Subscription, Partner, Account, Login, Remote host, each when known) and the legs in chronological order.
  • Then the server log, oldest first: the legs’ sessions and every line naming the CoreId or a transfer ID.
  • A subscription’s error page: facts, Last server error, the reddening connection’s log.

Tips

  • Every File in error: Failed files; back to green: Recovered flows.
