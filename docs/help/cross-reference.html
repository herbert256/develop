Cross References

What this shows

An analysis of the cross references — which pairs of the nine entities (Account, Login, Subscription, Remote Host, Logical, Partner, Application, Domain and BL) belong together — not a traffic report: there are no counts, no volumes and no date filter here. Pick the first entity on the top tab row and the second entity on the row below it — both rows list all nine entities, and each grays out the entity the other row has selected, so a pair is never crossed against itself. The underlying pair data is symmetric — Account×Login and Login×Account are the same pairs, just read from either page.

Green and red rows

Each row is one (first entity, second entity) pair. A green row is a pair that actually appears together in the transfer logs; a red row is a pair CONFIGURED in the FlowManager exports (the cross-reference caches under data/<env>/flow-manager/xref/) that never appears in the logs — a configured flow with no observed traffic, or a spelling that never matches. Seen means seen anywhere in the loaded logs; these pages carry no From/To date filter. The intro line above each table gives the pair totals (all / seen / not seen).

How it's computed

A pair counts as seen when both values appear on one physical log row (a leg inherits the partner / application / domain attribution of its account). If either side is blank on a row — including a value blanked by the parse-time blacklist — that row doesn't establish the pair. A repeated first-column value is blanked, so consecutive rows of one entity read as a block; entity names link to their detail pages where those exist.
