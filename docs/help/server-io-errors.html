IO errors

What it shows

The platform failing to read (or write) a file on its own storage, per folder, per line and per day, each line joined to the File it concerns: IO Error reading file /data/FlowManager/VDN@FE000436/25U_….xml.

Sections

  • Per folder — one row per FlowManager folder (account + login). IO errors = lines; Files = distinct file names; Error/OK = distinct Files by outcome (Waiting = OK, Expired = Error); Not logged = lines naming a file the transfer log never saw; Subscriptions = the joined Files’ flows. Click a row for its 10 most recent lines.
  • Lines — every line, newest first. Operation = the wording between “IO Error” and the path (“reading file”); State = the joined File’s outcome: Failed (the route never read the file: a one-legged File), Processed (a retry read it), not logged (no File carries the name); Transfer = that File’s timestamp. The File cell opens its error page (or File page) when one exists; the row expands to the verbatim message.
  • Per day — lines, folders and files per day: a one-day burst across folders is a storage incident; a daily trickle from one folder is that folder’s disk, mount or permissions.

Rules

  • The path is the account’s FlowManager folder (the landing directory a partner pushes into), named account@login: one line names account, login and file. The upload landed; the platform then could not read it back — deleted or moved while a route ran, a stale NFS handle, a slow or full volume, a folder permission.
  • Source: every server-log line carrying IO Error (as a word, any case) or Input/output error (the Java/POSIX wording); the path is the first /… token after it, the folder its directory. A path outside FlowManager keeps an empty account (unless the joined File names one), so nothing is dropped.
  • Joined by file name to the File in flight at the time — the newest starting before the error, else the first after — which supplies subscription and outcome; with no match, the line’s session is looked up in the transfer legs for the subscription alone.
  • The transfer log alone cannot show this: the upload leg looks fine and the failed read writes no row, so the File ends one-legged (Failed) or, after a retry, goes through as if nothing happened.
  • Account and login show in configured spelling and link to their detail pages. Line and File counts are additive and re-total under the date filter.
  • Error is the real damage — files a partner delivered that went nowhere and were never reported failed by the transfer; OK is how often a retry papered over it. Every flow whose folder shares the volume is exposed.
  • The same lines classify as IO error on the Failed transfers list and the home Reason column, and as their own bucket on Errors / Reasons and Per flow.
