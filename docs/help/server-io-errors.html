IO errors

What it shows

  • The platform failing to read or write a file on its own storage (IO Error reading file /data/FlowManager/<account>@<login>/…).
  • The upload landed, then could not be read back: moved or deleted mid-route, a stale NFS handle, a full volume, a permission.
  • The summary line totals lines, folders, Files in error and days.

Columns

  • Per folder — Last / First line, Account, Login, Subscriptions (each links its page), Folder.
  • Per folder counts — IO errors (lines), Files (distinct names), Error / OK (distinct Files by outcome), Not logged (lines naming no File), Days with a line.
  • IO error lines — Date, Time, Account, Login, Subscription, File (opens its File page, if any), Operation, State, Transfer (the joined File’s start).
  • Per day — Date, IO errors, Folders, Files.

Rules

  • Source: every server-log line with IO Error or Input/output error; the folder account@login gives Account and Login.
  • Each line joins by file name to the File in flight (the newest starting before it, else the first after).
  • State: Error = the route never read it (a one-legged File), OK = a retry read it, not logged = no File has that name. A line joined to a File takes that File’s row colour.
  • Error / OK follow the site outcome (Waiting = OK, Expired = Error). Counts re-total under the date filter.

Tips

  • Click a folder row for its 10 most recent lines, a line row for the verbatim message.
  • A one-day burst across folders is a storage incident; a daily trickle from one folder is that folder’s disk, mount or permissions.
