Expired

What this shows

A UC2 file is staged for the partner to collect. If nobody collects it, the nightly File Maintenance retention sweep (around 03:00, ~11 days after staging) deletes the staged copy — the file's outcome becomes Expired: never delivered, no longer collectable. This page turns those expiries into insight:

  • How long until expiry — the staged→deleted age distribution. One global retention window (~11 days); a per-account deviation here would mean per-partner retention settings, and there is none.
  • Accounts — who the expired files were staged for, with each account's pickup rate (collected vs expired). Red rows never collected anything — a dead pickup flow where everything staged expires; orange rows collect some files and let the rest lapse.
  • Expiries per sweep night — each 03:00 maintenance run and how much it removed unclaimed; a missing night means that sweep found nothing uncollected.
  • Staged weekday — whether files staged on particular weekdays are likelier to expire (mind the note: one dominant account can masquerade as a weekday pattern).

How it's computed

The deletion leaves no trace in the transfer log — the evidence is the server log's "File Maintenance … finished. Deleted files […]" lines. The bin/expire-files.sh build step joins those onto the Waiting files (same account and file basename, deletion dated after staging) and records the deletion timestamp in the cache's Expired field. "Collected" counts the staged files that were picked up; the sweep also removes already-collected staged copies, which is routine cleanup and not counted here. Expired files count as Error on every report (never delivered), while Waiting files count as OK — this page and the Waiting Files page show the two states individually.

How it relates to the other pages

The Waiting Files report (same Subscriptions group) shows the same states per subscription and the individual files; this analyses page aggregates the expired population — timing, account behavior, sweep batches. The Partner league gives each partner's overall health verdict.

About this report

A UC2 file waits staged until the partner collects it — and the nightly File Maintenance retention sweep (03:00, ~11 days) deletes whatever nobody picked up: outcome Expired, never delivered. 385 File(s) went that way, 6.9% of every staged file whose fate is already decided, worth 267.3 MB that never reached a partner. The per-subscription view is on Waiting.

Calendar days between the staging start and the deletion: ONE global retention (~11 days) — the sweep runs at 03:00, so a file staged before 03:00 expires on calendar day 11, a later one on day 10-11. No account deviates (see the per-account average below), so retention is not configured per partner.

Pickup rate = Collected / (Collected + Expired) for the same account — how often this partner actually fetches what is staged for it. Red rows never collected a single file (a dead pickup flow: everything staged for them expires); orange rows collect some and let the rest expire. Waiting = staged within the last ~11 days, still collectable.

Each row is one 03:00 File Maintenance run and what it removed unclaimed. A missing night means that sweep deleted nothing — nothing staged ~11 days earlier went uncollected. The Accounts column is per night and not additive (one account expires files on many nights), so the Total leaves it blank.
