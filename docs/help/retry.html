Repeat Failures

What it shows

Transfers that did not succeed at the first attempt: failing flows, retry anatomy, retry spacing, which side fails, manual resubmissions.

Sections

  • Failing flows — one row per (Account, Subscription) pair; top 60, never-succeeded first, then by failure count. Fail days = distinct days with a failure; Failures/Successes = legs; Resubmitted = legs flagged as resubmissions; last failure time.
  • Retry anatomy, delivered — failed legs before delivery, delivered Files only (incl. Waiting). A big “first try” row is healthy; weight further down = the platform delivers by insisting.
  • Retry anatomy, abandoned — Files ended Error or Expired; “first try (0 failed legs)” is mostly Expired: every leg processed, the partner never collected.
  • Retry spacing — a failed leg’s start to the next leg of the same File. Under 10 seconds = automatic hammering; minutes/hours = scheduled re-runs.
  • Which side fails — Inbound = arrival (partner/CFT delivering to ST); Outbound = delivery (ST pushing onward, or the partner collecting).
  • Manual resubmissions — Resubmitted=true legs per day and per subscription. Error/OK is the leg’s own status: an OK resubmitted leg is the retry that worked.
  • Resubmission outcomes (server log) — “Error while resubmitting transfer” vs “Resubmission successfully executed” per day; also catches attempts that produced no transfer-log leg.

Rules

  • Flow key = Account+Subscription: file names carry timestamps, so a retry never repeats as a name; the pair does.
  • Failing flows count parse-cache rows, not Files: a failed leg later re-sent OK appears on both sides; the File-level reports fold such intra-File recoveries into one OK File (the delivered rule). Only flows with a failure are listed.
  • Resubmitted = the log’s own marker, set only by an operator’s manual resubmission, never by automatic retries (the Top view splits Recovered into Automatic and Manual by it).
  • Under a narrowed date range the Files columns of spacing, side and resubmissions, and the resubmissions’ First/Last, stay full-period.

Tips

  • Click a Failures/Successes count for that outcome’s 10 most recent transfers, an anatomy row for its 10 most recent Files, a resubmission row for the subscription’s 10 most recent resubmitted Files (newest first).
