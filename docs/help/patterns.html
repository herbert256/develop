File journey

What it shows

  • How each File (all legs sharing one CoreId) moves through the platform: its status pattern, leg count and protocol chain.

Tabs

  • Patterns — one row per ordered Direction / Status sequence of a File’s legs: Legs, Files, Transfers (Files × Legs), Last 5 files (each opens its File page). Protocol on adds each leg’s protocol, splitting a pattern by route.
  • Leg count — Legs (1–10, 11 - 100, > 100), Files, Volume (the bytes of those OK Files), % of Files, Distribution. A bucket with no OK File is not listed — the 1-leg Files (never OK) are on One-legged.
  • Most legs — the 25 Files with the most legs: Legs, Date & time, Subscription, Account, File, CoreId. Rows in the File colour.
  • Protocol journey — the ordered protocol chain (ssh → pesit): Files, Volume (their bytes), % of Files, Distribution.

Rules

  • Files counts the delivered (OK) Files, except on Patterns and Most legs, which count every File.
  • Leg count and Protocol journey drop a row without an OK File; their Total row shows the Volume too.
  • Statuses appear as logged; Patterns lists at most the 200 most frequent.
  • A clean store-and-forward is 2 legs, retries add legs, a UC2 pickup is 4+ (one leg per partner collect).
  • ? = a leg with no protocol logged.
