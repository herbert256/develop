Transfer Patterns

What it shows

How a File moves through the platform: its row/status pattern (the transfers sharing a CoreId), leg counts, the ordered protocol journey, and how files arrive vs leave.

Patterns table

  • A File is an Inbound row, an Outbound row and, when the Outbound fails, up to 5 Outbound retries (the Inbound can retry too).
  • One row per distinct pattern: the ordered “Direction / Status” lines of a File’s rows, Inbound first, then by start time (retries as they happened). Status as logged (“Failed Subtransmission” verbatim, not folded into Error).
  • Legs — lines in the pattern (physical rows). Files — logical transfers matching it. Transfers — Files × Legs (a two-leg pattern: twice as many Transfers as Files).
  • Last 5 files — the pattern’s most recent Files, newest first (start date, CoreId); each opens the File’s own page under files/ — the failed-file layout (facts table, every leg, the server log behind it) for any outcome.
  • Pattern and file cells load collapsed (first and last line, ⋯ for the hidden middle); click to expand, again to collapse.
  • Protocol off (default) / Protocol on adds each leg’s protocol (“Outbound / ssh / Processed”), splitting a shape by the way it travelled — the same Files, more rows. Remembered per report for the session.
  • Capped at the top 200 patterns by frequency (typically a few dozen exist); a note appears if any were cut.

Other tabs

  • Leg count — Files = the delivered (OK) Files of the bucket; the 1 leg bucket is the One-legged (Pirates) population.
  • Most legs — the extreme repeat-collectors: a UC2 file the partner keeps re-collecting adds one ssh leg per pickup while it stays staged.
  • Protocol journey — Files = the delivered Files of that journey; ? = a leg with no protocol logged.
  • Last leg — the protocol of each File’s final leg; delivered Files beside the Waiting / Expired population. routing = never left staging; a healthy delivery ends on ssh/ftp (partner side) or pesit (CFT side). The state columns keep full-period values under a narrowed range.
  • In and out — Arrived = protocol of the earliest Inbound row, Left = of the latest Outbound row, “(none)” = no such row. Files = the delivered (OK) Files of the pair, reconciling to the delivered total.
