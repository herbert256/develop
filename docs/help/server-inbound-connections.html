Inbound Connections

What it shows

Inbound: who connects in to SecureTransport, over which protocol, from where. Outbound: why and where our own connections fail.

Sections

  • Connections per day — one count per “… had initiated a connection over SSH|PESIT|FTP …” line, per day and protocol; the column totals are the per-protocol volume. A protocol falling silent or a spike shows here first.
  • By account — connections per account (as logged), protocol mix, distinct source addresses; a known account links to its detail page.
  • By source address — the partners’ SOURCE addresses (what connects in, what a whitelist allows — not the configured outbound endpoints), top 50, the total over shown rows; Accounts = distinct accounts from that address.
  • Outbound failure reasons — classified from the failure tail. “SSH exception (generic)” = a com.maverick.ssh.SshException with no more specific cause (often a reset/aborted connection); Timeout, Bad certificate, Incompatible security protocols and Algorithm negotiation each point at a different fix.
  • Per remote host — the physical endpoint (a host serves several subscriptions) with its dominant reason; as logged, linked to a detail page when one exists (matched case-insensitively).
  • Test connections — explicit “Performs test connection for <protocol> protocol” checks (an admin/API testing a configuration).
  • Host-key mismatches — presented-vs-expected pairs from the “Wrong server fingerprint: got X, expected Y” warnings; one presented key against many stored keys = a server-side key rotation (or worth a closer look); a short “got” is the log truncating.

Rules

  • A connection line counts before any authentication or transfer — connection volume. Connection and failure counts re-total under the date filter; distinct counts (Addresses per account, Accounts per address) are full-period.
  • Click a row for its 10 most recent lines.
  • Logon is the screening funnel (allowed / disallowed / no-account / lockouts per login) and the successful SSH authentications; this report is raw connections, every protocol, regardless of authentication. Many connections, few authentications = clients failing (or probing); an address the whitelist does not know is worth a look.
