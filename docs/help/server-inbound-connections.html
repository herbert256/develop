Connections

What it shows

  • Raw server-log connection lines, before any authentication: who connects in, where SecureTransport connects out, over which protocol, and why our outbound connections fail.

Tabs

  • Per day — Date, In, Out, SSH, PESIT, FTP, Other (any other protocol), Total.
  • By account — Account (a known one links its detail page), In, Out, Connections, Protocols, Addresses (distinct), First, Last.
  • By address — the top 50 addresses: Address, In, Out, Connections, Accounts (distinct), Protocols, First, Last.
  • Failure reasons — outbound failures by Reason (Timeout, Connection refused, Unknown host, …, Other): Failures, Share.
  • By remote host — the endpoint we connect to: Remote host, Failures, Top reason, First seen, Last seen.
  • Test connections — admin/API “Performs test connection” checks: Protocol, Attempts.
  • Host keys — “Wrong server fingerprint” lines: Presented fingerprint, Expected fingerprint, Mismatches (red), First, Last.

Rules

  • In = the line names a login: a partner connected in. Out = login name “”: SecureTransport connected out, the address being the target.
  • Counts are log lines and re-total under the date filter; the distinct Addresses and Accounts stay full period.
  • One presented key against many expected ones is a server-side key rotation; a short fingerprint is the log truncating.

Tips

  • Click a row (not on Per day or Test connections) for its 10 most recent lines.
  • Screening and successful logons per login: Logons.
