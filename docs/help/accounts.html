Accounts (analyses)

What it shows

A configuration audit of the configured accounts against their communication profiles (one profile per endpoint, defining how that connection is made). Every table lists the offending objects by name, so each row is directly actionable in FlowManager.

Checks

  • Type prefix — the name’s connection type against what the profile declares in type; a name promising one thing while the profile does another is a mismatch.
  • Auth suffix — the name’s authentication against clientAuthentication.
  • More than one profile — accounts carrying several communication profiles; normally an account has exactly one endpoint.
  • Login disagreement — profiles whose login and loginName differ; on client profiles the two should be identical.

Rules

  • A profile name is coded <TYPE>_<partner>_<AUTH>.
  • Prefix = connection type: SCP/SSCP = server (SecureTransport connects out to the partner), CCP = client (the partner connects in to us).
  • Suffix = authentication: PWD = password, KEY = public key.
  • Source: input/flow-manager/partners.json via jq, no log data — a finding is a config slip whether or not any file ever moved.
