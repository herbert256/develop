Configured accounts

What it shows

  • A configuration audit of the accounts, logins and communication profiles (one per endpoint) in the FlowManager export. Each check heading carries its count and its table a Total row; 0 = nothing to fix (the empty table says so).
  • Connection type / Protocol — profiles per type and per protocol.
  • Type — the name prefix / Authentication — the name suffix — profiles per prefix and suffix with their Meaning, against the configured type and clientAuthentication (Match auth / Mismatch).
  • Naming inconsistencies — a suffix contradicting the real authentication.
  • Not clear domain-application-partner — accounts whose logical flow lacks a part (Missing, Why); they drop out of that entity’s figures.
  • FTP endpoints — insecure — clear-text profiles.
  • Incoming partners without IP whitelisting — accounts with a CLIENT profile and no AllowIP list; Status = seen (last OK / Error) or never seen.
  • Remote hosts with conflicting setup / Whitelisted IPs with conflicting incoming setup — one table per attribute (each Value) that differs across one host’s profiles, or one IP’s accounts.
  • Account & login checks — non-FE<digits> logins, a login on several accounts, a profile with several hosts, password profiles without a stored password, accounts with several profiles, login ≠ loginName.

Rules

  • Profile names read <TYPE>_<partner>_<AUTH>: SCP/SSCP = server (ST connects out), CCP = client (the partner connects in); PWD = password, KEY = public key.
  • Incoming account names separate parts with -, outgoing with _. Account, login and host names and the whitelisted IPs link their detail pages.

Tips

  • A differing port usually means one is stale; a differing host key leaves one connection unprotected.
