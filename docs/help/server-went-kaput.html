Trouble after Success

What it shows

One row per still-green subscription whose last transfer was OK but which then logged a server-log Error after it — the subscription itself or a connected login, account or remote host. The fleet-wide view of the signal the detail pages flag with a red banner.

Columns

  • Subscription — linked to its detail page.
  • Last OK transfer — when the newest OK File ended.
  • Errors — E-level lines logged after it; Latest error its date and time; Latest message its text.
  • Source — which entity logged them: Subscription, Account, Login and/or Host. A connected account or host serves other flows too, so its Error need not concern this subscription.

Rules

  • Errors only: a Warning never puts a flow here — the warnings-only shape is the benign “Transfer site ID is not present in environment” of Transfer site missing. The poll-backlog warning … Skipping the next scheduled occurrence of this task. is excluded too.
  • The cut is the newest OK File’s end, not its start: a File started before the error but delivered by a retry after it ended OK after the error, so that error does not count and the flow stays green.
  • Sources: the server per-name Error/Warn caches of the subscription and its configured login(s), account(s) and remote host — the host only where the flow has exactly one configured, with the addresses it resolves to, the same restriction the result colours use. Lines are deduplicated across caches.
  • Still green only. This same evidence turns a flow red site-wide (onto the home page’s Failing subscriptions in Server log table, with its reason), so a red flow is simply failing, not an early warning; the intro says how many were left out.
  • What stays green and lands here: a flow whose newest error is a deploy defect (the Deploy errors report keeps it), or a UC3 that has polled cleanly since (cleared) — small by design.
  • A row needs all three: last transfer OK, at least one Error after it, result colour still green. A flow whose last transfer failed belongs to the ordinary failure reports.
  • Full-period; no date filter.

Tips

  • Click a row for its 10 most recent Error lines.
  • The home page lists every red flow with its reason.
