Cleanup backlog

What it shows

Every cleanup signal the site computes, merged into one ranked decommission-candidate list, safest first. One row per object, under its safest applicable class, with its evidence named.

Classes (rank order)

  • config-orphan — no subscription references the account: nothing can route through it.
  • never-any-traffic — a configured subscription with zero Files ever.
  • unused-whitelist — allowed addresses that never connected, grouped per allowing account.
  • no-cron — a cron-triggered subscription with no cron expression can never poll: the quietest failure mode there is.
  • long-quiet — no activity for 45+ days, measured against the newest log day.

Rules

  • Green row = never showed any traffic; removing it cannot break a working flow. Orange row = had traffic once, or is a config gap; check before acting.
  • Reads source data only — the flow-manager config caches, the coverage TSVs, the transfer cache and the SKIP-filtered subscriptions export (the same population as every other report) — never another report, so the ranking is stable.
  • “Never seen” for a whitelist address is the established rollup: no transfer from that address AND no server-log mention; a server-contact-only address is not listed.
  • no-cron is the Missing cronjobs condition (the use-case definitions decide which UCs are cron-triggered); such subscriptions leave no trace in any log, only the configuration reveals them.
  • Whitelist entries paired with no account at all are on Config hygiene.
  • A partner’s recency uses the site-wide union attribution, so it matches the lifecycle and Entities views.
