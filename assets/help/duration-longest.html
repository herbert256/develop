Longest Files

What this shows

The 50 longest Files by wall-clock duration — from the first record start to the last record end, so the store-and-forward wait inside SecureTransport and any retry idle are included. Split off the Duration report 2026-09-03. Only delivered Files are listed (outcome Processed): a Failed, Expired or still-Waiting File is not a completed transfer, and a failure’s run time is a timeout, not a duration (the former “All transfers” view went 2026-09-13).

Reading the table

Per File: the Duration (the column sorts by the exact milliseconds), the Start Time, the CoreId, the destination Subscription (linked to its detail page), the Size and the File name. The Duration and Start Time cells open the transfer’s record page: every record of that CoreId in chronological order, with direction, status, protocol, login, remote host and transfer id. Every listed File also has its own File page under files/ — the error-page layout: the facts table, every record and the server log of its connections — and the CoreId cell opens that page.

How it’s computed

From the logical-transfer cache (one row per CoreId): the 50 largest durations among the Files whose outcome is Processed. Error transfers are mostly instant 0-byte attempts, and a hanging one is a timeout — neither is a delivery, so neither is listed.
