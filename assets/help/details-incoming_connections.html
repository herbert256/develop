Incoming Connection Details

What this shows

One page per sighted whitelisted IP address — every address from the partners' AllowIP whitelists (patterns expanded) that has actually been seen: as the source of real transfers, or in the server log. The ~3,000 whitelisted addresses that have never been seen anywhere (whole ranges whitelisted "just in case") get no page.

The page opens with a Summary — the raw incoming address, the configured endpoint name when that same address appears in input/<env>/ip/ip-hosts.tsv (otherwise blank), its result, how many accounts whitelist it, and its traffic totals (Files, Volume, first/last seen). No reverse-DNS lookup is used. Then, for addresses with real traffic, Activity per day and the Latest 10 Files (account and subscription cells link to their own detail pages). Whitelisted by lists every account whose whitelist allows this address, each linked to its account page. For addresses sighted only in the server log, the page ends with the last 10 server log lines that mention the address.

Page colors

The page background is the address's result: light green = its last transfer was OK, light red = its last transfer failed, light blue = sighted in the server log only, never a transfer. A whitelisted IP is colored by its own transfers exclusively — never by the health of its partner's flows (a partner's healthy flow says nothing about which of its whitelisted addresses actually connect).

How it's computed

Traffic is every logical transfer (File) whose remote host equals this address — since the side-aware parse, an incoming connection keeps its raw source IP, so the address a partner connects from stays visible. The whitelisting accounts come from the FlowManager configuration (the expanded AllowIP whitelist); the server-log lines are the ones the Missing whitelisted IPs server report collected. The index page lists every sighted address; the "Why blue" matrix on the Seen in server log page links its whitelisted-IP entries here.
