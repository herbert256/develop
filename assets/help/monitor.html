Monitor

What this shows

The end-to-end monitor: a small file dropped on the CFT server every 15 minutes that travels through all four use cases with ourselves as the remote partner — out via the ST Edge across the internet and back in through the Edge, twice — and ends up back on the CFT. The graph offers three latency views that cut each cycle's trip into disjoint segments, so an incident shows up in exactly the segment that owns it. Each view draws on its own duration scale, fitted to its data — the loop view can never beat the ~5-minute poll floor, so a shared scale would flatten it:

  • Monitor CFT pickup — from the file's drop on the CFT (the timestamp encoded in its name, monitor_ccyymmdd_hhmmss.txt) to the start of its inbound UC1 leg into ST: CFT directory pickup plus PeSIT delivery, the segment before ST. A slow CFT scanner shows here and nowhere else. Healthy is roughly a minute.
  • Monitor duration — from entering ST (the UC1 inbound leg) to the final hand-off back to CFT (the UC3 outbound leg), joined on the file name (the four monitor subscriptions share no CoreId). This is the whole loop: the push to ourselves, UC4, the CFT relay, UC2 staging, the poll wait and the collect. Because the UC3 poll fires at :05, this view is floored at about 5 minutes — a file that misses the first poll reads ~20 minutes, and a file that never completed counts as 1 hour (or the slowest completed file, when that is longer), so losses stay visible in the percentiles instead of disappearing from a successes-only average.
  • Monitor staging — from entering ST to staged for pickup (the UC2 flow's inbound routing leg): the delivery path without the poll wait. This is the view that shows ST-internal drift first — the poll floor hides it in the loop view. Healthy is 1–2 minutes; it stays flat through a slow CFT scanner (that is pickup's segment) and through a dead poll (that is the loop view's).

All three are P50 / P90 / P98 percentile bands (dark green / orange / dark red) per slot on the fixed duration axis, with the usual Line / Bar / Solid styles and the 4-hour to 1-day interval switch. Clicking a slot opens that day's page (on its Files-processed view — the day pages carry no monitor graphs).

How it's computed

Everything comes from the transfer log's monitor rows: files named monitor_ccyymmdd_hhmmss.txt on the UC1/UC2/UC3-INFRA_ST-MONITOR_INFRA subscriptions, earliest leg per side so a retry never shifts a measurement. Each resolution is aggregated from the raw measurements (a median of medians is not a median). One honesty rule on the loss penalty: a file without its end leg that is younger than one hour against the newest monitor row is skipped rather than penalized — the log export was simply cut mid-flight.

When this page exists

Only in an environment whose transfer log actually carries monitor traffic — the top-bar Monitor link and this page appear and disappear with the data. The monitor itself (scripts, scheduling, its CFT-side logs under e:\admin\monitor\9-logs) is documented on the CFT server in 8-docs.
