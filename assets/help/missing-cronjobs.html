Missing cronjobs

What this shows

A subscription that can only ever run on a timer, with no timer configured. Where we are the client and pull from the partner — UC3, and UC5's pull side — a Quartz cron expression is what makes SecureTransport connect and collect. Nothing else triggers the flow. Without one the subscription is complete in every other respect and simply never runs.

  • Subscription — the configured name, linking to its detail page.
  • Use case — its UC<n> prefix, always one of the cron-triggered ones.

The schedules that are configured, each translated to plain English, are on Cronjobs. This page was that page's last table until 2026-07, when it became a report of its own — it answers a different question, and it belongs in the same worklist as the other subscription problems.

How it's computed

Straight from subscriptions.json: take every subscription whose use-case prefix is cron-triggered (the trigger comes from the shared use-case table, so this list follows the use-case definitions rather than being hardcoded here), then keep the ones with no parameter whose name contains cron holding a non-empty value. UC1 is a client use case too, but it pushes on directory scanning rather than on a timer, so it is never flagged.

It is pure configuration — no log is read — so the answer is the same whatever date range you are looking at, and the page carries no date filter.

Why it matters

This is the quietest failure mode on the site. Every other signal on Subscriptions in boxes needs the flow to have run at least once: something has to connect, or fail, or stage a file before there is anything to notice. A subscription with no cron expression never gets that far. It raises no error, writes no transfer record, and touches neither log — so it is invisible to every report that works from observed activity, and it can sit in the configuration indefinitely looking exactly like a flow that simply has nothing to fetch.

The fix is usually a one-line configuration change; the cost of not noticing is that a partner's files are never collected at all. That asymmetry is why it gets its own column on the problems worklist.

Notes

Every schedule listed is enabled, and none are configured to skip holidays. The number in the Schedule column is what the timer will actually do; the raw expression is kept alongside it so it can be cross-checked against the FlowManager configuration.
