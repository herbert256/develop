Auth Activity

What this shows

The complement to Logon: every successful inbound SSH authentication, from the server log's "successfully authenticated over SSH" lines. These are plain counts of matching log records, not Files — a baseline of who is actually logging in that the transfer log can't give you (a transfer record only starts after authentication has already succeeded). Accounts are shown as logged with the trailing @endpoint suffix stripped, unlinked (the server-log naming doesn't reliably match the transfer-side detail page slugs).

Three tables: successful logins by account, the same activity by source IP, and a Certificates table built from "Authentication attempt with certificate" lines.

How it's computed

One pass over the parse cache extracts the account and source IP from each successful-authentication line, tallying logins per account and per IP along with each side's count of distinct counterparts (source IPs seen per account, accounts seen per IP). Per-day buckets let the account and IP tables re-aggregate under the date filter.

Shared certificates

The Certificates table flags when one certificate serial number authorizes more than one account — the "Accounts on certificate" cell is tinted amber whenever that count exceeds 1. This is a security concern: a single private-key compromise would expose every account authorized on that certificate, not just one.
