Entity coverage

What it shows

  • Per configured entity, per direction: is the connection working? One tab per entity: Accounts, Logical, Partners, Domains, Applications, BL.
  • Boxes: Total, Covered (Current), Not covered, Covered once, OK transfers, Regressed.

Columns

  • Name, Direction, then per side (In, Out): Subs (configured subscriptions; a both-ways one counts on both), Files, and the proof — Logons (In) or Polls (Out).
  • Covered: Current, Once, OK transfers (yes / no) and Regressed.

Rules

  • A side is covered when a real File moved that way or the server log proves the link; 0 Subs = covered. A both-ways entity needs In and Out.
  • In proof: a successful SSH authentication by one of the entity’s logins (see Logons). Out proof: a successful UC3 remote poll, even one finding 0 files (see UC status › UC3).
  • Current: the newest File that way was OK, or a logon / poll proves the link. Once: any File, logon or poll ever. OK transfers: the newest File was OK; proofs do not count.
  • Regressed = covered Once, not Current; search regressed for that list. OK transfers ⊆ Current ⊆ Once.
  • Rows are green (Current covered) or red (not), overruling the usual result colours. Full period, no date filter.
