What it shows

Which pairs of the nine entities (Account, Login, Subscription, Remote Host, Logical, Partner, Application, Domain, BL) belong together: every pair seen on at least one log row, plus the configured pairs that never appear. Relationships only — no counts, no volumes, no date filter.

Rules

  • The top tab row picks the first entity, the row below the second; each grays out the other’s choice, so a pair is never crossed with itself. The data is symmetric: Account×Login and Login×Account are the same pairs.
  • One row = one pair; the intro line gives the totals: all / seen / not seen.
  • Seen = both values on one physical log row, anywhere in the loaded logs (a leg inherits its File’s partner / application / domain / logical / BL attribution).
  • Not seen = configured in the FlowManager exports (the xref caches under data/flow-manager/xref/) but never on a log row: a configured flow with no traffic, or a spelling that never matches.
  • A row with either side blank — including a value blanked by the parse-time blacklist — establishes no pair; pairs where either value is blacklisted or unattributed are not listed.
  • Each cell tints by its own entity’s result: light green last transfer OK, light orange configured but never seen, light red last transfer Error, light blue surfaced only by the Server → Transfer step (bin/build/seen-in-server-log.sh), no real transfer.
  • A repeated first-column value is blanked, so consecutive rows of one entity read as a block; names link their detail pages where those exist.
