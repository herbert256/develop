Connection efficiency

What it shows

  • How the technical connections are used. A session is one connection (an SFTP login, a PeSIT session), identified by the log’s Session ID.
  • All tables cover the full period; the summary line gives the platform-wide Sessions, Files/connection, Single-File share and All-Error sessions.

Columns

  • Files per connection (first table) — Account, Sessions, Files carried (a File counts once per session it used), Files per session, Single-File sessions (share carrying one File); least efficient first.
  • Connection storms — the top 20 accounts by Peak sessions/min (most sessions started in one minute), that Minute, and the account’s total Sessions.
  • Session failure anatomy — the top 20 accounts by All-Error sessions, with Mixed OK+Error and Retry marathons.

Rules

  • A session belongs to the account of its first record; records without a usable Session ID are left out.
  • Files per connection lists User-initiated sessions only (the partner controls reconnects), accounts with 200+ of them; its total row is the whole platform, any initiator. 1.00 = a fresh connection per File.
  • Storms count any initiator; a three-digit peak is a client script connecting per file — a load spike on shared listeners.
  • All-Error = 2+ records, all failed. Mixed OK+Error = some Files delivered, others failed. Retry marathons = 8+ records, one File, all Error. Per-record status (Processed = OK), not the File outcome.
