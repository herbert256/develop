Logons

What it shows

  • SSH authentication from the server log, counted in log lines.

Tabs

  • Incoming — every configured login through the screening funnel: Allowed (passed the whitelist), Disallowed (rejected by it), Authenticated, No account, Bad key, Key failures, Locked, Auth failed, Session errors.
  • Incoming continues with First logon / Last logon / Logons / Pattern (successful logons over any protocol, full period) and Re-screens.
  • Outgoing — this server failing to log on at a partner: Remote host, User, Failures = Password + Key + Certificate + Other, Reason (last seen), First, Last.
  • Near misses — unknown FE+digits names: Login, Attempts, Source IPs, Top source, Configured login (yes = defined in Flow Manager but mapped to no account), First, Last.
  • Scanners — the 25 most-tried other names: Username, Attempts, Source IPs, IPs (the addresses), First, Last.
  • By account / By source IP — successful SSH logins, with distinct Source IPs / Accounts.
  • Certificates — Auth attempts per serial; Accounts on certificate above one (amber) = a shared key.

Rules

  • Auth failed = the anonymous “Authentication failed using local.” line, counted for the login whose Allowed precedes it within a second.
  • Re-screens = an Allowed on an already-authenticated session (a held connection re-keys hourly); not in Allowed.
  • Incoming row colour = the latest funnel line: green an authentication, red anything else, orange never in the funnel.
  • Session errors = Error/Warning [Ssh Default] lines of no other column, booked to the session’s login — not the re-key warning “No session cycleId for file … will not get reported” (transfer bookkeeping, not a logon problem).
  • Click an Incoming count for its 5 newest lines, another row for its 10. Distinct counts stay full period under a date filter.
