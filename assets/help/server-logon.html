Logons

What it shows

  • SSH authentication from the server log, counted in log lines.

Tabs

  • Incoming — each configured login through the screening funnel: Allowed / Disallowed, Authenticated, No account, Bad key, Key failures, Locked, Auth failed, Session errors; then First logon / Last logon / Logons / Pattern (successful logons, any protocol) and Re-screens.
  • Outgoing — this server failing to log on at a partner: Remote host, User, Subscription (the flow that tried: the failed attempt’s connection joined to its transfer legs), Failures = Password + Key + Certificate + Other, Reason (last seen), First, Last.
  • Scanners — the 25 most-tried other names.
  • By account / By source IP — successful SSH logins, distinct Source IPs / Accounts, First seen / Last seen.

Rules

  • Auth failed = the anonymous “Authentication failed using local.” line, booked to the login whose Allowed precedes it within a second.
  • Re-screens = an Allowed on an already-authenticated session (a held connection re-keys); not in Allowed.
  • Incoming row colour = the latest funnel line: green an authentication, red anything else, orange never in the funnel.
  • Session errors = Error/Warning [Ssh Default] lines of no other column, booked to the session’s login (not the “No session cycleId” re-key warning).
  • A count opens its newest lines. Distinct counts stay full period under a date filter.
