AV Scan

What this shows

The anti-virus / ICAP scan outcome of every File, read from its first Inbound leg — the scan runs when a file enters the system, so that leg carries the File's verdict: Allowed, Blocked, Not performed, or Error/Unknown (grouped as "Other"). Five tabs: the overall Breakdown, outcomes Per day, outcomes Per protocol (how the file entered — pesit from CFT, ssh/ftp from a partner), the Blocked list — every blocked file individually, newest first, capped at 200 — Not performed (why arrivals skipped the scan: before scanning was active, failed/empty arrival, encrypted .pgp/.enc, oversized, Other) and Not first inbound.

The "Not first inbound" check

The last tab verifies the scan-on-entry model: it lists every real scan verdict (Allowed/Blocked/Error) found on a leg other than the File's first Inbound leg. What legitimately appears there: inbound retries (a re-entry is scanned again) and the UC2 staging re-entry (the Inbound routing leg). An Outbound row would break the model — outbound legs only ever carry the "Scanning was not performed" boilerplate, which this tab excludes.

How it's computed

One chronological walk over each File's physical rows; the first Inbound leg's ICAP verdict counts for the File (a File with no Inbound leg has no scan and is absent). Allowed is tinted green and Blocked red in the breakdown. If more than 200 files were blocked, a note states how many are hidden; if none were blocked, the Blocked table shows an explicit empty-state row.
