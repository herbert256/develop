Partners Out

What it shows

  • One row per host this server connects out to: every configured host, every host we failed to log on at, and every address we opened a connection to. Full period; no date filter. Laid out like Partners in.
  • Views — Endpoint (a row per host), Accounts and Partners: the same table per account / partner, over the hosts the configuration pairs it with. A host several accounts use counts for each of them (its failures too — User names the account that failed), so the rows can add up to more than the Total, which counts every host once; an address no host maps to is left out. Per entity: counts summed, Last connection / Last the newest, First the earliest, Reason the newest failure’s.

Columns

  • Remote host — links its detail page; an address no host maps to shows as the address.
  • Use cases — the use cases of the host’s subscriptions (UC1–UC4, a hybrid flow by its derived use case): the configured ones plus any whose failed attempt reached the host — the same cell as on Partners in.
  • Files In / Files Out — Count: the Files whose outgoing connection reached the host, by movement (the Entities Remote Hosts figures); Errors: those that failed or expired.
  • Connections — Connections / Last connection: the connections we opened (the “had initiated a connection” lines without a login name), over the host’s name and addresses — the host page’s figures.
  • Failed logons — User: the account(s) our failed logons used. Failures = Password + Key + Certificate + Other: our authentication failures at the host.
  • Reason (last seen) — the newest failure’s reason; First / Last — the first and last failure day.

Rules

  • Row tint = the host’s result colour; an address or an unconfigured host stays untinted. A 0 renders empty.
  • Sorted by Failures, then Connections.

Tips

  • Click a row with failures for its 10 newest failure lines. Inbound logons: Partners in.
