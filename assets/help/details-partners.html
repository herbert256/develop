Partner Details

What it shows

The detail page of one partner organisation — the LAST part of the three-part logical flow name domain_application_partner, merged into one organisation by shared endpoints, shared whitelist IPs, whitelisted host addresses and curated aliases.

Sections

  • KPI line — rank and share of traffic among all partners, failure rate, total volume, cadence, processed-transfer performance and a session count where durations are recorded.
  • Last error(s) — directly above Features, only when a subscription it moves files with has an error: one row per such subscription, its most recent error, newest first, with date and time, subscription and file. Red = failed file, orange = expired before the partner collected it.
  • Features — a Partner, Application, Domain or Logical breakdown holding exactly one row is folded away into a Features row, keeping its link and colour.
  • Activity per day / week / hour / weekday — the day table leads with the Files count.
  • Breakdowns — every dimension its transfers touch: account, subscription, login, remote host, protocol, AV scan, security parameters, direction, action-by, mode. Subscription comes first below Activity; Account sits right under the Incoming/Outgoing connections tables.
  • 10 largest transfers.
  • Whitelisted IPs — the allowed source addresses, when the partner’s configuration carries an AllowIP whitelist.

Rules

  • A file belongs to a partner through its attribution in the files cache: the organisation resolved from the file’s endpoint or its account’s whitelist cluster.
  • Every count is in Files: one per logical transfer, split by its delivered (final-row) outcome, volume counted once per file.
  • The account / subscription / login / remote host tables are cross-referenced with the FlowManager configuration: every name configured for this partner is listed, seen or not — green rows have logged data, red rows are configured but never seen; each links its own detail page.
  • Every configured partner has a page, seen or not. Background: light brown = seen & in, light blue = seen & out, light gray = seen & both/unknown, light yellow = never seen & in, light orange = never seen & out, light purple = never seen & both/unknown.
  • Configured both ways (common: the linked In + Out organisations): every outcome splits into In - Error / In - OK / Out - Error / Out - OK by each file’s own direction; a file without a direction counts in Files and Volume only.

Tips

  • Click anywhere on a Last error(s) row (the subscription name included) for that file’s error page: every transfer leg and the server log of the failure.
  • Those are the files of the Failed Subscriptions list, which guarantees every subscription’s last error has a page.
