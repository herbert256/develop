Sources and Targets

The From/To folder paths configured on every subscription, and where they overlap.

What this shows

Every subscription reads files from a source folder and writes them to a target folder (the "From" and "To" rows in its detail-page Features table). This report collects those paths across all subscriptions and highlights where the same path is used by more than one subscription, or serves as both an input and an output.

A path on a remote partner (an endpoint SecureTransport dials) shows the partner host after an @ — for example /some/dir @ sftp-test.lifetime.nl — exactly as on the Search page. A local SecureTransport path (for example F:\Data\Cloud\in\…) has no host. Each row links to the subscription and is tinted by that subscription's status (green / red / orange / blue).

The three tables

Values used as both a Source and a Target. A path that one subscription writes to and another reads from — an internal hand-off (a relay through a shared folder). The Role column tells you, per subscription, whether it uses the value as its source or its target.

Sources used by multiple subscriptions. One block per source folder that appears on two or more subscriptions, listing each subscription that reads from it.

Targets used by multiple subscriptions. The same for target folders — one block per target shared by two or more subscriptions.

How it's computed

The source/target values and the @ host come from the same inputs as the Search page: each subscription's detail-page From/To rows, plus the configured remote host and file-movement direction (the host is appended to whichever side is remote — the source on a pull flow, the target otherwise). Per-subscription Error and OK counts are the subscription's own transfer outcome. This is a configuration analysis over subscriptions.json, so it carries no From/To date filter.
