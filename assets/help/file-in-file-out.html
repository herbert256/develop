File in - File out

What it shows

  • Files carried by two subscriptions: the same filename arrives from one partner and leaves to another (or the reverse), copied across in between. Nothing but the filename links the two halves.

Tabs

  • Handovers — the routes, one row per First flow, Second flow and Direction: Files, Filenames (distinct), First partner, Second partner, gap Fastest / Median / Slowest, Same size, Size changed (full period).
  • Below it Latest handovers: the 100 newest — File, First time, First, Second time, Second, Direction, Gap, Size first, Size second.
  • UC4 to UC2 — deliveries the partner collected back; see its help.

Rules

  • In --> Out = arrived from a partner, then left to another; Out --> In = left to a partner, then arrived from another.
  • Filename match only, a different subscription, within 48 hours. Two passes per filename: first In → Out (each outbound File takes the most recent unmatched inbound one), then Out → In over the leftovers. A File joins at most one handover.
  • Size is not matched (re-encryption changes it): all Same size = a byte-for-byte copy, all Size changed = re-encrypted or re-wrapped.
  • Files = Filenames: every name unique, not coincidence. Far fewer filenames = a repeated fixed name that can pair by accident.
  • The same partner on both sides is usually a pull-then-stage flow, not a handover.
