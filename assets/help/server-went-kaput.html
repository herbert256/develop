Trouble after success

What it shows

  • Still-green subscriptions whose last File was OK but which then logged a server-log Error — the flow itself or a connected login, account or remote host. An early warning, full period.

Columns

  • Subscription — links its detail page.
  • Last OK transfer — when the newest OK File ended.
  • Errors after — Error lines logged after it; Latest error the newest one’s date and time; Latest message its text.
  • Source — who logged them: Subscription, Account, Login and/or Host.

Rules

  • Errors only: a Warning never lists a flow; the poll-backlog “Skipping the next scheduled occurrence” line is ignored too.
  • The cut is the newest OK File’s end: an error before a retry delivered the file does not count.
  • A host counts only when the flow has exactly one configured.
  • An account, login or host serving several flows counts only connection-level lines (connection failure, wrong server fingerprint, outbound login error); a line naming one flow concerns that flow alone.
  • The same evidence normally turns a flow red, and it leaves this page for the home page’s Failing subscriptions in Server log.
  • What stays is mainly deploy-classified errors. A UC3 that polled successfully after its newest error is left out.

Tips

  • Click a row for its 10 most recent Error lines.
  • Deploy defects: Routing errors.
