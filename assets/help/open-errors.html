Open Errors

What it shows

  • One row per open error: each red subscription — its newest File in error (Failed or Expired), or a server row when only the server log reddens it — plus each red host or login no UC1 / UC3 (host) or UC2 / UC4 (login) subscription row covers.
  • The same rows as the home page’s Errors table.
  • Views: Open (default); All also keeps the subscriptions green again.
  • Also the help of the File pages (File: <name>, any outcome) and the subscription error pages. Only the newest OK File and the three newest Error Files of a subscription have a page.

Columns

  • Entity; Date/time — the File’s start, the reddening error’s time, or a host / login’s newest evidence.
  • Reason — the first classifying server-log error (Connection failures, Route stopped…), One-legged, Expired (not collected), else the last leg’s raw status.
  • CoreId / SessionId — the File’s CoreId, or the session of the reddening error.
  • Last green day (never = never delivered), Days red, Failures in a row — blank on server, host and login rows.

Rules

  • Row tint = the entity’s colour; a subscription row opens its error page (an Expired File has none), a host or login row its detail page.
  • A server row: a server error after the last delivery, a deploy mistake, or an attributed authentication failure.
  • A File page: the facts, the legs in order (each with the remote host it logged), then the server log of their sessions and every line naming the CoreId or a transfer ID.

Tips

  • Every File in error: Failed files; back to green: Recovered flows.
