UC status › UC1

What it shows

  • Every configured UC1 subscription — we are the client and push a file to the partner as soon as one appears — one row each, worst status first; the boxes count the four statuses.
  • The other tabs: UC2 (the partner collects from us), UC3 (we poll and pull), UC4 (the partner delivers to us).

Columns

  • Status — ok, error, ok -> error or not seen (Rules).
  • Subscription — the configured name; ↗ opens its detail page.
  • Files / OK / Error / Last file — its Files by outcome and the newest one’s date.
  • Problems — a send that failed (“Could not send file”, “An error occurred while sending”, a step “finished with error”) or an unreachable partner (a Connection failure, a failing directory listing).
  • Last log — the date of the flow’s newest counted server-log line.
  • Total row: OK green, Error and Problems red.

Rules

  • Roster: every configured UC1 subscription (by name prefix, else by its derived use case), run or not. Rows carry the subscription’s result colour (Generic help).
  • ok (green) — its last File is OK; Waiting counts as OK.
  • error (red, never an OK File) — its last File Failed, or the server log reported errors after it: nothing ever worked, the configuration or the partner side was never finished.
  • ok -> error (red after OK Files; a red box, like its rows) — the same red, on a flow that has delivered before: a regression, a change to find.
  • not seen (orange) — never in the transfer log; a flow whose last File Expired is orange and lands here too. Problems still show whether it ever tried.
  • No “no files” status: a push starts only when a file appears — no file, no route run, no log line.
  • The whole table is the current state; a date range does not narrow it.

Tips

  • We are the active party: red rows, and not-seen rows with Problems, are ours to fix — our route, our send, our connection.
  • A row’s drill lists its newest problem lines from the server log (a failed send, an unreachable partner) — the ones the detail page’s “Next move” line reads.
