One-legged

What it shows

  • Files (CoreIds) with only one leg — a single row in the transfer log. A complete transfer is store-and-forward: an Inbound leg (partner → ST) and an Outbound leg (ST → partner), commonly 2–7 rows with retries.
  • A single leg is one-sided: the file arrived and was never forwarded, or a send had no matching arrival. It never made the full crossing.

Tabs

  • Details — one row per subscription (links its detail page): One-legged Files, First date, Last date; most first. A click on the row opens the subscription’s One-legged Files page. From/To re-counts One-legged Files for the range (a subscription with none in it hides; First / Last date stay full-period); the Unknown subscription is left out (see Unknown transfers).
  • Under it, Empty ssh probes — lone outbound ssh records of size 0 (Application none), dropped before they became Files: not counted anywhere, no File page.
  • Per day — per day: One-legged Files (red: a lone leg is always an Error File), Unknown included.

Rules

  • Details: rows tint by the subscription’s result colour.
  • A subscription’s One-legged Files page: Date/time, File name, CoreId, State (OK / Error / Waiting / Expired), newest first, tinted by the File colour, with a Total row and a button back to One-legged. Every row has its own File page and opens it from anywhere on the row; From/To narrows it like the Details count.
  • The two tabs are the second button row, under the Errors group row.
  • Every count is one File (one CoreId).

Tips

  • A day page’s transfer-log problems link the Per day tab for that day.
  • Failed Subscriptions gives such a File the reason One-legged when its log names no other cause.
