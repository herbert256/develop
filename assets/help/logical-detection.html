Logical detection

What it shows

  • How every configured FlowID (customAttribute_FlowIdentifier) became its Logical flow group, one row per FlowID.

Columns

  • FlowID — the configured value. Logical — the group it detected to; links its detail page, the row tints by its result.
  • Rules — the trail the derivation applied, in firing order, ;-separated.

Rules

  • separators normalized — - folds to _, doubled separators collapse, edge ones trim.
  • numeric-only parts removed — a name of four or more parts drops its purely numeric parts.
  • 4 parts: … 4th part dropped — the bare 3-part name exists, the first three parts are shared by 2+ FlowIDs, or the 3rd part is a known 3rd part.
  • digit tail stripped — a numbered variant folds onto the stripped form.
  • 5+ parts: folded onto the longest existing prefix.
  • pinned in … logical.txt — a fixed mapping in input/logical.txt set the Logical.
  • 2 parts: UNKNOWN inserted as the application (WA_VDN → WA_UNKNOWN_VDN).
  • … combined — the 3-part reshape joins parts with -, guided by the known 2nd/3rd parts; forced when nothing else fits.
  • parts replaced (logical_*.txt) — the domain / application / partner replacement lists renamed a part.
  • 3 parts - kept as-is — no work needed.
