No remote files

What this shows

UC3 subscriptions that poll the partner faultlessly and never find a thing. Every poll logs its result, and for these flows it always reads zero:

Applying the search pattern '*' for transfer site 'UC3_ZG_SCOPE_IMPRESS_…_KEY': 0 file(s) were found of which 0 matched the pattern.

Nothing is broken here — the connection, the credentials and the remote directory are all fine and the listing succeeds. There is simply never a file on the other side. Each row is a schedule spending connections and directory listings around the clock for no data at all: the top rows in this report poll thousands of times a month and have never once had anything to fetch.

Who gets listed

The scope is deliberately narrow, so the report answers one question — which flows have never had anything to fetch?

  • UC3 only — the pull use case, where polling is the whole point.
  • No transfer data — the subscription appears in the server log but has no transfer rows at all. Its result shows green when its latest poll succeeded (the clean-poll rule: the flow verifiably works, there is simply nothing to fetch) or blue otherwise. A subscription that has moved files is left out — a quiet stretch there is a lull, not this problem.
  • Every poll empty — zero files found on every single poll. A flow that saw files it could not match (found > 0, matched = 0) has a search-pattern problem, not an empty directory, and is left out; the note under the table says how many were excluded that way.

How it's computed

One pass over the poll lines in the server log. Both message shapes count — N file(s) were found of which M matched the pattern. and N file(s), matching the pattern, were found and will be downloaded. — since only the leading count is common to them. Last and First bound the polling, Polls is the number of empty listings and Days how many separate days it ran. Poll counts are additive, so a date-filtered range re-totals them, and clicking a row expands its 10 most recent poll lines.

Why it matters

An empty poll leaves no trace whatsoever in the transfer logs — no transfer is started, so the flow is invisible in every file-based report. A subscription can therefore run for years, cost a connection every few minutes, and never be noticed. Each row is a candidate for retirement, a slower schedule, or a question to the partner about whether they ever intend to deliver. Compare with Remote Polls, which ranks the empty-poll rate of every subscription including the working ones, and No remote dir, where the listing fails outright because the directory is not there.
