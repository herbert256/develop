Partners in

What it shows

  • One row per login a partner connects in with: its use cases, last logons, Files and pickups, and the whole SSH screening funnel. Full period; no date filter.
  • Views — Endpoint (a row per login), Accounts and Partners: the same table per account / partner, over the logins the configuration pairs it with. A login serving two accounts counts for both, so the rows can add up to more than the Total, which counts every login once; a login no account / partner is configured for is left out. Per entity: counts summed, Cloud / Gateway the newest, Oldest waiting the oldest, First logon the earliest, Pattern the busiest login’s.

Columns

  • Login — links its detail page. Use cases — UC2 (the partner picks up), UC4 (the partner delivers) or both.
  • Cloud — the newest successful logon here, any protocol. Gateway — the last logon on the old gateway (input/logons_old.txt).
  • Files in / Files out — by movement; Error, Retrieved, Waiting, Expired; Oldest waiting — the oldest uncollected File’s age. Pickups — pickup logons.
  • The funnel, in log lines: Allowed / Disallowed (whitelist), Authenticated, No account, Bad key, Key failures, Locked, Auth failed (the anonymous “Authentication failed using local.”, booked to the login whose Allowed precedes it), Session errors (Error/Warning [Ssh Default] lines of no other column, booked to the session’s login), Re-screens (an Allowed on an already authenticated connection — a re-key; not in Allowed).
  • First logon, Logons, Pattern — successful logons, any protocol.

Rules

  • Rows: every configured login, every login only the old-gateway file names, then logins only the funnel knows (untinted).
  • Row tint = the login’s result colour; the funnel’s red cells keep their red. A 0 renders empty.

Tips
