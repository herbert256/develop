Day pages

A day page answers "what happened on this calendar day?" for one of the two logs. There are two variants per day — a transfer page (the file movements) and a server page (the platform's own log) — reached by clicking a date on either Top view report. The links at the top of each page step to the previous/next day, switch to the other log's page for the same day, and return to the Top view.

What's on a transfer day page

Below the header line, Remarkable facts (shown just under the Files-per-hour chart) lists only what stands out — the busiest or quietest day of the window, the heaviest day by volume, an error rate well above the period average, a fully clean day, a flow whose every File failed, a spike in zero-byte Files, a heavily-retried transfer, a single account or a single hour that dominated the day's Files, traffic that was overwhelmingly inbound or outbound, one protocol carrying most transfer legs, an unusually long-running transfer, the largest file, accounts seen for the first time that day, accounts that went quiet after it, heavy resubmission activity, or weekend activity. The KPI cards add the activity window, average File size, active-subscription count, resubmissions and busiest-hour share. A day page carries exactly one graph — the hero, described below; the smaller grid charts (delivered outcome, configured direction, top accounts, protocol mix) were dropped, and the page closes with Remarkable facts and, below it, Busiest this day.

Busiest this day, at the foot of the page, is six small tables giving the day’s five biggest partners (left column) and subscriptions (right column) by Files, by Volume and by Errors — one metric per row. Each is just the name and the figure, largest first; an entity with none of that thing is not listed, so a clean day simply has no Errors tables. Each table’s See more → opens the matching Entities view narrowed to this day and sorted descending on the same column — so the five rows you were looking at are the top of that page, with the rest of the list beneath them. A File counts for every partner of its subscription as well as its own, the same rule the entity reports use, so the figures agree exactly.

Above the facts sit two boxed link lists, one per log: Server log problems this day (errors, warnings, and any non-zero operational signal — logon screening failures both ways: partners failing our incoming screening and us being refused at theirs; connection failures; route-abandon deploy errors; PeSIT ceiling hits; subscriptions whose configured remote directory does not exist; UC3 flows polling a directory that is always empty; UC3 flows whose scheduled poll itself errors — failing polls) and Transfer log problems this day (that day's failures, its one-legged transfers, the subscriptions that went from green to red or failed for the first time and have never delivered — only red —, the files staged that day still waiting for pickup or expired before it, plus the Anomaly scan, which is always offered so a clean day still gets one thing to check). Between them the two lists carry every signal of the Subscriptions in boxes page that leaves dated evidence in a log, each on the day it happened — only the three silent states (Missing cron, Went quiet, Not seen) have no day to appear on. Every entry links the report that details it — pre-narrowed to the day, except for the full-period reports (from green to red, only red, waiting, trouble after success, deploy errors, failing polls), which have no date filter and open at the full range. A log with nothing to report shows no list at all.

The hero chart has a row of view buttons above it — the SAME six activity views as the main dashboard, here with their own interval switch — 15 min, 30 min (the default, 48 slots) or 1 hour, by start time: Duration (the default — the P50/P90/P98 duration of each slot's OK Files as stacked dark-green/orange/dark-red bands on a fixed 1 s–>1 h scale), Files processed (OK Files per slot), Volume (bytes moved), Error % Files (the Error % of the slot's Files — mind small slots: 1 failure out of 2 Files is 50%; an empty slot shows a gap), Transfer errors (the failed transfer records — raw Status Failed or Failed Subtransmission — per slot; this counts log records (legs), not Files, so one failing File can log several, and a slot with no errors is a real zero), and PeSIT (problem lines on the CFT link, ST → CFT red vs CFT → ST purple; shown when the day has server-log coverage). Each view has a Line / Bar / Solid style switch bottom-right and a hover tooltip with the slot's exact values; the collapsible Data table under the chart carries the same numbers. The chosen view and style are remembered while you browse — stepping to the previous/next day keeps them, and they carry to and from the main dashboard (whose slot columns link straight into these pages).

What's on a server day page

The same idea over the server log. Remarkable facts flags the busiest or quietest server day, the day with the most errors, an hour when errors spiked, a surge in warnings, hits against the PeSIT 100-connection ceiling, a single error message dominating the day, a surge in authentication failures, and any component that was unusually busy. Its KPI cards (records and error rate) join the transfer ones in the row at the top, its facts join the same Remarkable facts list, and its problems fill the Server log problems this day box; the full-period message clusters live on the Top messages report.

Reading the figures

The five KPIs are Transfer files, Transfer error rate, Volume, Server lines and Server error rate. Transfer figures count Files (the logical transfer — see Shared Concepts); server figures count raw log records. The day pages carry no From/To date filter — the page itself is the date filter. Every KPI and chart title links to its full report opened pre-narrowed to that day (the ?axway_date= link parameter sets the target's From/To); widen the range there for cross-day views. Facts about "first seen" and "went quiet" are relative to the loaded log window, not all history: an account "first seen" on the window's first day is not called new, and one "quiet" on the last day is not called gone.

Where the numbers come from

Everything is derived from the same caches the other reports use — the day page's Files, Error and Volume figures reconcile exactly with that day's row on the transfer Top view, and the records/level figures with the server Top view row. The pages are regenerated on every build.
