Account sharing

What it shows

  • Accounts serving more than one subscription, one row each, with the shape of the sharing. The boxes count all accounts with subscriptions, the single-subscription ones (not listed), the shared ones and each kind.

Columns

  • Account — links its detail page. Kind — the shape (below).
  • UC1 … UC4 — its subscriptions per use case; Other — those of any other use case.
  • Subs — the number of subscriptions; Subscriptions — the list (three or more fold behind …).

Rules

  • Mailbox pair — exactly UC2 + UC4: one partner connection to drop and pick up.
  • Outbound pair — exactly UC1 + UC3: we push to and poll the same partner.
  • Outbound fan-out — several UC1/UC3 flows over one account.
  • Both directions — inbound and outbound on one account; real partners rarely, the ST monitor account by design.
  • Inbound (irregular) — inbound beyond the pair (two UC2s, two UC4s). Ungrouped flows — no UC1–UC4 flow at all.
  • The use case is the name’s UC<n> prefix, else the one derived from the configuration. Configuration only; ordered by kind, then size.

Tips

  • A login usually rides its account 1-to-1, so a shared account is a shared FE login too; some hybrid accounts carry one FE login per flow.
