Acceptance vs production

What this shows

The two environments’ entities compared by name, one page per entity type (Subscriptions, FlowID, Logical, Accounts, Logins, Hosts, Partners, Domains, Applications, Whitelist). An entity counts here when the environment knows it at all — configured in FlowManager or seen in the logs. The pages are name-only lists: no activity figures and no result colors — every name links its own environment’s detail page (FlowID, Logical and Whitelist have none), so each side is one click away. FlowID compares the customAttribute_FlowIdentifier values of the configured subscriptions — a flow’s UC subscriptions share one FlowID, so it compares the environments by flow rather than by subscription. Logical condenses the FlowIDs one step further: numbered variants and per-label branches of one flow fold into a single logical name, normalized to three _-separated parts (a - inside a part marks parts the normalization combined).

The views

The view button row cuts the union of the two name sets differently per button:

All — every name once, in one alphabet; the Acceptance and Production columns are filled where the name exists (a name in both fills both).
Acceptance / Production — one environment’s full set.
Only Acceptance / Only Production — names known to one environment but not the other.
Both — names known to both environments, one column per environment.
Difference — the two only-sets interleaved in one alphabet, each name filling only its own side.

Names are matched case-insensitively; each column shows its environment’s own spelling. The button labels carry the counts.

The Summary view

Summary is the verdict layer: both environments’ home status tables, then per type the set sizes plus the Both set’s activity split (busy in both, or dormant in exactly one environment — drawn from each environment’s entity reports, the one place activity still appears in this family).

Subscriptions vs partners

The last button of the type row opens a cross-view: the subscriptions present in both environments whose partners differ between Acceptance and Production, with each environment’s own partner(s) and account(s) beside them, every name linking its own environment’s detail page. Read a difference with care: it can be a real configuration gap, but it can also be the per-environment partner grouping — the same organisations merged into one group on one side and kept as separate partners on the other.

Freshness

Each environment’s copy of these pages is generated during that environment’s build pass and reads the other environment’s data as it is on disk at that moment — after a full build the Production copy is fully fresh and the Acceptance copy may lag the other side by one build.
