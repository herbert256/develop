Stale Accounts

What this shows

Every account, ranked by how overdue it is for activity: first activity, last activity, active days, its own median gap between active days, days idle, an idle÷gap ratio, and its File count. This report counts Files — logical transfers from _files.tsv — so an account's count here is "how many files it moved," with one File meaning all the transfers (rows) sharing that File, both directions and any retries collapsed into one.

How it's computed

"Days idle" is not measured against today's date — it's measured against the most recent File seen across every account in the data. So this table reflects staleness as of the end of the collected log window, not as of when you're viewing the page; an account idle "10 days" means 10 days before the last record in the export, however long ago that export was taken.

"Median gap" is the account's own typical spacing between its active days — its normal cadence. The idle÷gap ratio compares its current idle time against that cadence: an account that normally transfers daily and has been idle 3 days (ratio 3.0) has missed three of its own cycles and is more alarming than a weekly account idle 5 days (ratio 0.7), which a flat day-count threshold alone would rank the wrong way round. An account seen on only a single day has no gap to measure, shows "-", and sorts last. Idle 7+ days is tinted, as is a ratio of 2 or more (two missed cycles).
