Logical

What this shows

One row per logical flow — the FlowID families of the configured subscriptions condensed to one three-part name. Every name links its detail page.

The row is the entity’s traffic in seven column groups, the Top view way: Files (one per CoreId, split In / Out by the movement direction, with the Error count and rate), Retry / Resubmit (Auto = an OK File that carried a failed leg and was delivered by the platform’s own retry; Ok / Error = every File an operator resubmitted, by its final outcome — the Top view’s rule), Duration (the p90 / p95 / p99 / p100 wall-clock duration of its OK Files — p100 the longest — as whole seconds / minutes / hours / days: seconds green, minutes amber, hours and days red), Volume (the total and the average per File, whole units), Transfers (the physical log rows — every leg of its Files — Ok / Error with the error rate), State (the UC2 Waiting Files, staged but not collected yet, and the Expired ones, deleted unclaimed) and Dates (first and last day, days with traffic). Every figure follows the From/To range — the Duration percentiles are re-picked from per-day histograms — except First and Last, which stay full-period.

Reading the cells: an empty cell is a zero (In / Out and the tinted counts never show a 0), an empty Error keeps an empty rate beside it, a red cell is an Error / Expired count with a value, an amber one a Retry / Resubmit / Waiting count. The Retry / Resubmit and State groups are shown only while at least one visible row carries such a value — a view without any drops them for good, and a date range or search that leaves them empty hides them until a value comes back. The total row is the last row; its cols hotspot opens the column picker.

Every count opens its 10 most recent Files on click (newest first, by start time); the Transfers cells list the Files that carried a leg of that outcome, and a Duration cell the 10 most recent OK Files whose span is at or above that percentile, each with its span. A blank cell is not clickable.

How it's computed

Every configured subscription carries a FlowID (the customAttribute_FlowIdentifier value). The derivation condenses those FlowIDs into logical flow groups: numbered variants and per-label branches of one flow fold into a single name, normalized to three _-separated parts — a - inside a part marks parts the normalization combined, which is why these names are never separator-folded. A fixed mapping in input/logical.txt wins verbatim over the derivation. A File counts for a logical flow through its FlowID attribution, unioned with its subscription’s configured logical(s) — the same union rule the partner and application figures use.

The tab row: views and scope

The tab row carries three groups: the entity type (Subscriptions, Logical, Partners, Accounts, Logins, Hosts, Domains, Applications, BL), then the view, then the scope. Switching one keeps the other two, so you can walk from entity to entity without losing the view you were reading.

The six views are All (every configured name plus every logged one), Seen (the names with activity), Not seen (configured in FlowManager, never seen — name column only), and OK / Warning / Error, the names whose result is green / orange / red.

The scope decides whether a sighting in the server log counts as being seen. +Server is the default and counts it: an entity that only ever turned up in server-log messages — never in a transfer — is listed under Seen and shown light blue. Transfer ignores the server log, so that same entity counts as never seen: it drops out of Seen and turns up under Not seen and Warning instead, in the ordinary never-seen light orange. The scope only changes three of the views — Seen, Not seen and Warning. All lists the same names either way, and only a real transfer ever makes a name green or red, so OK and Error are the same list too: on those three views the scope tabs are greyed out. Under +Server the view row also offers a seventh view, Server — the names seen in the server log and nowhere else, i.e. exactly what that scope adds to Seen. It is not offered in the Transfer scope, where those names are simply never seen. This is the same choice as the including server log switch on the front page, and the front-page figures link straight into the matching view and scope.
