FE status information

What this shows

One row per FE login — the credential a partner connects with — with everything a status or migration check wants on one line. Use cases are those of the login’s subscriptions: UC2 (the partner picks up files from us), UC4 (the partner delivers files to us) or UC2/UC4 (both — the mailbox pair, one connection used to drop and pick up). Last logon is the newest successful authentication on this platform over any protocol (the same figure as the detail pages’ Logons table; empty when the log window holds none). Gateway logon is the login’s last logon on the old gateway, as recorded in the hand-maintained file input/<env>/logons_old.txt. Files in counts the login’s Files delivered to us and Files out those picked up from us, over the whole transfer window; Waiting are the staged Files not yet collected.

Reading the table

Every configured login is listed, tinted by its result colour: green delivering, red failing, orange configured but never seen. A login that the old-gateway file names but that is not configured on this platform gets an untinted row of its own — a partner not yet moved over stands out that way, and the “Old gateway only” box counts them. The login links to its detail page. The boxes above the table count the logins per use-case mix, those that have and have not logged on here, and those with a known gateway logon. Every figure is full-period; there is no date filter on this page.

How it's computed

The roster is the FlowManager export’s login list; the use cases come from the login → subscription pairs, each subscription classified by its UC<n> name prefix or, for a flow without one (the hybrid production flows), by the use case derived from its configuration. Last logon comes from the server log’s logon summary, Files in / out and Waiting from the transfer files cache (one File per CoreId, attributed to the login, split by the file’s movement direction — the home page’s In/Out rule).

The input file. input/<env>/logons_old.txt holds one login per line: the login, then its stamp — for example FE000123  2026-09-02 14:35. The first token (up to the first spaces, TAB, comma or semicolon) is the login, matched case-insensitively; the rest of the line is shown as written. Blank lines and lines starting with # are ignored. The file is per environment; when it is missing the Gateway logon column simply stays empty.
