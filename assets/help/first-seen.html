First seen

What this shows

For six entity types — Logical, Partners, Subscriptions, Accounts, Logins and Hosts — the calendar day each configured name was first seen in the transfer logs. One row per day in the loaded logs; a blank cell means nothing of that type appeared for the first time that day. On the first day of the logs everything active is “new”, so that row is naturally the largest.

The summary rows on top use the same Seen / Not seen split as the home page’s status tables (the coverage universe), so the figures here and there always agree. Per column: Seen + Not seen = Total (every configured name of that type), and the day rows + the “Seen, no date” row = Seen. The “Seen, no date” row holds the names that count as seen without a dated transfer of their own — a UC3 subscription whose polling works but never had a file to fetch, a name whose transfers are credited to a sibling (a shared endpoint’s co-tenant, one organisation of a two-partner account), or a blue name without a dated cross-reference.

The two views

The buttons above the table switch between two definitions of "seen". Transfer log only (the default) matches the status tables’ Transfer scope: a name that only ever appears in the server log (blue) counts as Not seen. Both Transfer & Server logs matches the +Server scope and additionally dates the blue names — the entities the site's server-log analysis flagged as server-log-only (the same set as the Status tables' Server column and the "Server log → Transfer log" page). A blue name never transferred, so it takes the oldest first transfer of its cross-referenced entities — its account, subscription, login, host or partner from the FlowManager configuration — as the day its surrounding flow first became active; the cell pages tag those rows Server in the Log column. This deliberately does not scan the raw server log for name mentions: the nightly housekeeping (File Maintenance) mentions virtually every configured account, which would move everything to the window's first day and drown the signal. A blue name whose cross-references also never transferred keeps no date and sits in the “Seen, no date” row of that view.

The cell pages

Every count links a page listing exactly the items behind it, each name linked to its detail page. The list shows the name, its configured direction (blank when the name is not configured) and its first transfer timestamp. Rows are tinted by the entity’s result: light green = last transfer OK · light orange = configured but never seen · light red = last transfer Error (or server-log errors after it) · light blue = seen in the server log only.

How it's computed

The Seen / Not seen split is read from the coverage tables (the exact files behind the home status tables and the Entities views), so the two pages cannot disagree. First-seen dates come from the transfer parse caches: accounts and partners per logical transfer (File), subscriptions, logins and hosts per log record; date matching is exact, case aside — subscriptions match by prefix (a configured subscription matches the logged site values it prefixes).

Those server-only (blue) names are recognizable on the cell pages by their light-blue tint.
