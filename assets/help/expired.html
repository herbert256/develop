Expired

What it shows

  • Staged UC2 Files the nightly File Maintenance sweep (03:00, ~11 days after staging) deleted before any pickup: outcome Expired, never delivered. Boxes: Expired Files, their share of resolved staged Files, Never-delivered volume, Average staged to deleted, Still waiting.

Columns

  • Staged to deleted (the first table) — calendar days from staging to deletion: Files, Share.
  • Subscriptions — Partner; Expired (opens its list of expired Files); Collected (picked up and delivered — as on Waiting); Waiting (still collectable); Pickup rate = Collected ÷ (Collected + Expired); Avg age at deletion; Volume; First / Last staged; Last deletion (the default sort).
  • Expiries per sweep night — Files expired, Volume, Subscriptions (per night, not additive).
  • Staged on which weekday — Expired, Collected, Expired share by staging weekday.

Rules

  • Subscription rows: red = never collected a File (everything staged expires), orange = collects some, lets the rest expire.
  • The deletion leaves no transfer-log record: it is taken from the server log’s File Maintenance “Deleted files” lines, matched on account and file name.
  • One global retention: staged before 03:00 expires on day 11, later on day 10–11. Always the full period.

Tips

  • On a subscription’s list the first 5 CoreIds open the File page. The Files still staged are on Waiting; each partner’s overall verdict on Partner scorecard.
  • One subscription can dominate the weekday split: check the Subscriptions table first.
