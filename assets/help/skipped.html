Skipped

What this shows

Some accounts and subscriptions are deliberately ignored across the whole site — they never appear in any report, coverage table, detail page or search result. This page is the audit of exactly what was removed and why: the skipped accounts and subscriptions, and how many transfer-log and server-log records were set aside along with them.

The skip list

The rules live in a per-environment file, input/<env>/skip.txt — one token per line (for example CRG and SWIFT). Each environment has its own list (per environment since 2026-08-31). An account or subscription is skipped when its name contains a token as a case-insensitive substring: CRG matches IPO_CRG-OK01_RABOBANK, SWIFT matches AB_SAPTRM_EWL_SWIFT, and so on. To change what is skipped, edit input/skip.txt and rebuild — a changed list re-derives the FlowManager config and re-parses both logs.

Where the filtering happens

Skipping is applied at parse time, at the source, so nothing downstream ever sees the removed items:

FlowManager config (bin/flow-manager.sh) — a filtered copy of the config exports is written to data/<env>/flow-manager/filtered/, so every base list, cross-reference pair, derived Partner/Domain/Application group and every config-derived analyses page (Accounts, Cronjobs, Certificate expiry, …) excludes the skipped names.

Transfer logs (bin/transfer/parse.sh) — a record whose attributed account or subscription name matches is dropped from the transfer cache and set aside in data/<env>/transfer/_skipped.tsv.

Server logs (bin/server/parse.sh) — a record whose message text contains a token is dropped from the server cache and set aside in data/<env>/server/_skipped.tsv.

The unattributable records

A last table lists the raw transfer-log records the parser dropped for a different reason than the skip list: a transfer whose legs carry neither a subscription nor an account after every attribution pass (platform-internal traffic whose names the blacklist blanked), or a transfer with an http leg (web-UI hand traffic, never flow traffic). These are the only transfers the site does not count.

A transfer that has an account but no findable subscription is not dropped: it is counted under the synthetic subscription name UCx_account — the usual UC naming shape, with UCx standing in for the use-case number nothing could determine. Before settling on that name the parser also asks the server log which flow the transfer's own connection executed (the session id joins the two logs, and the route lines name the subscription), and lets a partner-delivered Inbound leg pick the account's single receiving flow when only a response leg contradicts it; the synthetic name is used only when even those find nothing. That name is not configured anywhere: it appears in the transfer counts, the Entities views and on Not in Flow Manager like any other logged-but-unconfigured subscription, but never in First seen — a UCx_ row is a routing gap worth investigating, not a configured flow.

Reading the page

The info boxes at the top give the counts: skipped accounts, skipped subscriptions, skipped transfer log lines, skipped server log lines and dropped raw records. The tables below list every skipped account and subscription by name, and the dropped raw records with their reason. An environment where nothing matched the skip list (for example a Production config without these names) shows zeros and empty lists — that is expected, not an error. This is a static audit, so the page carries no From/To date filter.
