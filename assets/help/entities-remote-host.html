Remote Hosts

What this shows

One row per remote host (the partner side of a transfer): Files, Error vs. OK, volume, and first/last seen, with a Summary tab (all hosts) and a Detail tab (per host per day) — see the shared concepts page.

How it's computed

A remote host is a per-row attribute — the Inbound source host and the Outbound destination host differ — so the report counts distinct (host, CoreId) pairs: a host appearing on any row of a transfer counts that File once. Per-host counts can therefore sum to more than the number of distinct Files, noted on the page.

Host identity is side-aware and comes from the transfer cache plus the configured endpoint map input/<env>/ip/ip-hosts.tsv (IP<TAB>configured host). There is no reverse-DNS or PTR lookup. FlowManager forward-resolves configured non-IP endpoints into this per-environment map; the transfer parse can also retain a newly observed outgoing address under the row's uniquely attributable configured endpoint. The map is a union so an older logged address remains nameable after an endpoint moves.

  • Incoming — the partner dials in to us, so the report keeps the raw source IP. That is the address tested by the account's AllowIP whitelist.
  • Outgoing — we dial a configured endpoint, so the report uses the endpoint hostname configured for the account or subscription when it can attribute that address unambiguously.

An address that cannot be associated with a configured endpoint remains an address rather than receiving a guessed DNS identity. A handful of internal cluster addresses (the platform talking to itself) are blanked at parse time and never appear here at all.

The tab row: views and scope

The tab row carries three groups: the entity type (Subscriptions, Logical, Partners, Accounts, Logins, Hosts, Domains, Applications), then the view, then the scope. Switching one keeps the other two, so you can walk from entity to entity without losing the view you were reading.

The six views are All (every configured name plus every logged one), Seen (the names with activity), Not seen (configured in FlowManager, never seen — name column only), and OK / Warning / Error, the names whose result is green / orange / red.

The scope decides whether a sighting in the server log counts as being seen. +Server is the default and counts it: an entity that only ever turned up in server-log messages — never in a transfer — is listed under Seen and shown light blue. Transfer ignores the server log, so that same entity counts as never seen: it drops out of Seen and turns up under Not seen and Warning instead, in the ordinary never-seen light orange. The scope only changes three of the views — Seen, Not seen and Warning. All lists the same names either way, and only a real transfer ever makes a name green or red, so OK and Error are the same list too: on those three views the scope tabs are greyed out. Under +Server the view row also offers a seventh view, Server — the names seen in the server log and nowhere else, i.e. exactly what that scope adds to Seen. It is not offered in the Transfer scope, where those names are simply never seen. This is the same choice as the including server log switch on the front page, and the front-page figures link straight into the matching view and scope.
