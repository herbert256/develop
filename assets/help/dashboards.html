Dashboards

What this shows

The dashboard (the Dashboard link in the top bar) is a graphical read of the same data the tabular reports carry: five big-number KPI cards — Files transferred, Transfer failure rate, Volume moved, Server records, Server error rate — and one graph with twelve switchable views over the whole log window — six of per-slot activity, two cumulative coverage curves, then four per-use-case status stacks:

  • Duration — the P50 / P90 / P98 wall-clock duration of each slot's OK Files as stacked bands (dark green / orange / dark red): the top edge of each colour is that percentile. The vertical axis is a fixed duration scale (1 s up to >1 h), so a good slot is a low green line and a bad one a tall red spike.
  • Files processed — the OK Files (Processed + Waiting) started in each slot.
  • Volume — the bytes moved per slot.
  • Error % Files — the % of the slot's Files that Failed or Expired; a slot with no Files shows a gap.
  • Transfer errors — the failed transfer records (raw Status Failed or Failed Subtransmission) per slot. This counts log records (legs), not Files — one failing File can log several — and a slot with no errors is a real zero, not a gap.
  • PeSIT — the problem lines on the CFT link, split ST → CFT (red, the outbound TM client leg) vs CFT → ST (purple, the inbound PESITD server leg). Counts are log lines, not failed transfers — one failure logs several lines.
  • Subscriptions seen and Partners seen — cumulative: how many the site had seen at or before each slot, four counts per slot:
    • blue — seen in the transfer + server logs. The union of both, so always the highest number.
    • orange — seen in the transfer log. Never more than blue; the gap between them is what only the server log knows about.
    • green — green at the end of that slot: its latest File so far was OK (delivered, or still waiting for pickup).
    • red — not green at the end of that slot: its latest File so far Failed or Expired.
    Blue and orange are first sightings, so they only ever rise. Green and red each move both ways as flows break and recover, and they always sum exactly to orange — every subscription the transfer log has seen is, at every later slot, in one or the other.

    The three styles show this differently, unlike the other views. Line draws all four as separate lines — blue, orange, green and red — so you can read each count directly; the green and red lines mirror each other, because together they always make up orange. Bar and Solid instead stack red, then green, then blue, and drop the orange: red and green stack up to exactly the orange figure, so their boundary is the orange line, and the blue segment on top is the server-only remainder. Whichever style is on screen, the Data table lists all four numbers.

    These two are the one place on the dashboard that answers “how much of the estate is actually live” rather than “what happened in this slot”.
  • UC1 status, UC2 status, UC3 status and UC4 status — one per use case, each a full stack of that use case's configured subscriptions at every slot. Unlike every other view these are not a measurement of the slot's traffic but a composition: the stack's total is the number of subscriptions configured, which never changes (the site holds no configuration history), so the top edge is flat and only the mix inside it moves. Green OK sits at the bottom, the never-seen bucket in light orange on top, and the problem states ramp up in between in order of severity — so a healthy month is green growing upward from the floor and the light orange band shrinking away. Each stack is exactly the same verdict its report gives, evaluated at the end of each slot instead of once over the whole window: UC1/UC3/UC4 share the seven states OK · No result · No files · Server error · OK + error · Error · Not seen (UC1 has no “No files” state, so that band is always empty there), and UC2 has its own five — OK · Both · No files · Never collected · Nothing. Hover any slot for the exact figures, and follow the title link for the report behind it: UC1, UC2, UC3, UC4. A use case with no configured subscriptions in an environment simply has no button there.

Each view offers a Line / Bar / Solid style switch (bottom right of the card; your choice is remembered for the browsing session), and next to it an interval switch — 1 hour, 2 hours, 4 hours, 6 hours, 12 hours or 1 day per slot — so you can combine any style with any level of detail: a daily Bar chart gives the shape of the month, 6-hour Solid the shape of a day. Changing the From/To range picks a fitting interval for you — one day shows hourly slots, a week 4-hour ones, the full period daily — and a manual interval click still overrides it until the next range change. Both picks are remembered for the browsing session (the style follows you to the day pages, which offer their own three intervals — 15 min, 30 min and 1 hour — remembered separately). Each resolution is computed from the raw Files, not by merging the finer one: a median of medians is not a median, and a mean of percentages is not an error rate. Every view also has a hover tooltip with the slot's exact values, a collapsible Data table (bottom left, always at the 6-hour resolution whichever style is on screen), and a linked title to the best-fitting full report. Clicking any slot opens that calendar day's page in the same view — the day pages carry the same five activity buttons at 30-minute resolution, and the picked view follows you between the two. The cumulative curves and the four status stacks are the exception: a single day is one point on a cumulative curve, and a status stack of one day says no more than the report itself, so there is nothing for a day page to draw — clicking a slot in any of those six opens that day’s Files processed graph instead, and the day pages deliberately do not offer their buttons. (Pick one of them and then open a day page from elsewhere and it falls back to Duration, since that day page has no such view.)

Below the graph, Busiest this period closes the page with the same six Top-5 tables the day pages end on: the five biggest partners and subscriptions by Files, by Volume and by Errors. They follow the From/To date fields: narrowing the range re-picks the five busiest within it — not just re-summed, re-selected, so an entity that only mattered that week can enter the list — and the full range shows the whole log window again. A metric with no activity in the range leaves a gap rather than shifting the other tables. Partner figures use the site-wide union attribution (a File counts for every partner of its subscription as well as its own), so at the full range each table's numbers match the Entities view its See more link opens — the full list, sorted descending on the same column.

How it's computed

The charts are drawn from the same caches as the reports — the four transfer views from the logical-transfer cache, the PeSIT split from the PeSIT report's own classification — so the figures reconcile with the tables. The two cumulative views use the site-wide partner attribution (a File counts for every partner of its subscription as well as its own), so their final orange figure matches the First seen analysis exactly, and the blue one matches its both-logs view. Green and red use the same rule as the subscription colours everywhere else on the site: red when the latest outcome is Failed or Expired, green otherwise — so a subscription whose newest File is merely waiting for pickup still counts green. Because the server log has its own start date, blue can lag orange in the very first slots and then overtake it. The four status stacks come from the use-case reports themselves: each writes an hourly sidecar of its own verdict, and the dashboard only re-buckets it — and because a status is a state rather than a rate, a coarser slot takes the last hour inside it, never a sum or an average, and a slot with no observation of its own carries the previous state forward. That is why the right-hand edge of each stack is exactly the figure its report shows. Every chart is inline SVG (no external libraries or web fonts), so the page is fully self-contained and loads instantly.

The one difference from the reports

The dashboard opens at the full log period and has no search box — but it does have the full From/To date controls, right at the top under the title: From/To pulldowns plus All, Week / 4 weeks / Month (the last 7 or 28 full days, or one calendar month back — a partial newest day never counts), First day / Last day and Previous/Next day (the day-stepping pair works on a single-day selection). Everything below follows the picked range: the five KPI cards re-sum, the graph clips, and the Top-5 tables re-select within it. The range you pick here stays on the dashboard (it is remembered for the dashboards only, never carried onto the reports). When you spot something worth digging into, open the matching report from the Transfer or Server menu: there you get the searchable table, the per-row drill-downs and the exact numbers behind each chart.
